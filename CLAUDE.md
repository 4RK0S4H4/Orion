# Orion: working notes for Claude

## If you are a session building another app with Orion

You have this repo attached as a secondary repo (or only the skill) and are building the owner's own app. Orion's own
rules in the rest of this file are for sessions working on Orion; yours is this: **do not patch Orion's components,
tokens or checks from the app, and do not work around a defect silently. Log it**, so it feeds a future round.

- **Where.** A GitHub issue on `4RK0S4H4/Orion` with the form `.github/ISSUE_TEMPLATE/from-app.yml` (label `from-app`) if
  the session can (`gh issue create`, or the GitHub tools). If it cannot, append an entry (format in
  [`docs/issues/inbox.md`](docs/issues/inbox.md)) to `docs/issues/inbox.md` on a branch `issues/<app>-<date>` and push
  that branch. **Never push `s4-orion` or `main` from an app session.** Save screenshots in `docs/issues/img/`
  (`<date>-<app>-<short-name>.png`) on the same branch, or attach them to the issue.
- **One issue per problem**, with: app name, component or page, what happened, what was expected, steps, screenshot,
  browser/device/shell, Orion version (top of `CHANGELOG.md`, or the commit of this repo).
- **Workarounds** live in the app's own stylesheet, with a comment linking the issue (`/* Orion issue #123: ... */`),
  never in a copy of Orion's files. Tell the owner in chat what you logged and where.
- A gap that Orion's rules already cover ("the app is the app", decision 0053: make the element from Orion's rules in the
  app's stylesheet) is not a defect; log only what is broken, missing from the system, or surprising.

Orion is the owner's personal design system for web apps and pages: Material 3 Expressive plus a very clear,
contrast-guaranteed glass layer on floating chrome. It replaces the older **S4 Material** skill. **S4 Glass is a separate,
unrelated system**; don't mix the two. The repo was renamed from `s4-material` to `s4-orion` (2026-11) and again to `Orion` (2026-11-22, decision 0071); the product is **Orion**, formerly S4 Orion. The `s4` prefix stays as a technical namespace (below).

**Start every session working on Orion by reading [`docs/NEXT.md`](docs/NEXT.md) and [`docs/PLAN.md`](docs/PLAN.md)** (the goal, current stage, how workstreams run) (and [`docs/ROADMAP.md`](docs/ROADMAP.md) for the long view and what Orion will not become): current phase, the plan for what's left, the backlog
and the open questions. Update it (and the README phase table and CHANGELOG) before ending any session that changed
something, so the next session can pick up cold.

## Git and publishing

- Work on branch `s4-orion`; publish with `git push origin s4-orion && git push origin s4-orion:main` (fast-forward).
  No PRs needed for this repo; the owner reviews on Pages.
- **A new session starts on its own branch** (e.g. `claude/<name>`). Ignore it: `git fetch origin s4-orion main &&
  git checkout -B s4-orion origin/s4-orion`, work there, publish as above. Only if pushing to `s4-orion`/`main` is
  refused, push the session branch and open a PR into `main` instead (Pages updates when it's merged).
- Don't ask the owner which branch to use or whether to start the next phase: `docs/NEXT.md` says what's next.
- Commit after each meaningful step with a clear message. Never put model names or IDs in commits, code or docs.
- CI (`.github/workflows/check.yml`) runs `npm run check` on every push. It must stay green.

## Build and check (Node 20+, no dependencies; Playwright only for the page checker)

```sh
npm run build    # tokens -> tokens.css/ts/json; icons -> icons.js; components -> orion.css/js; skill assets + generated references
npm run check    # token validation + WCAG pairs, icons, glass guarantee (97 schemes), any-accent check (216 schemes), FAB labels with any seed, motion patterns, banned phrases, stale-output check
node skill/orion/scripts/check.mjs page.html [--out dir]   # page checker: 390 dark + 1280 light, contrast, overflow, lint
```

Generated files are committed (Pages serves them) and never edited by hand: `tokens/tokens.*`, `components/orion.*`,
`components/base/gray.css`, `components/assets/icons.js`, `skill/orion/assets/*`, and `skill/orion/references/*` **except** `patterns.md`.

After changing the skill, re-package it with skill-creator's packager (path varies per environment; find it with
`find / -name package_skill.py -path '*skill-creator*' 2>/dev/null`), run from the skill-creator folder:
`python3 -m scripts.package_skill <repo>/skill/orion <repo>/skill/dist` → `skill/dist/orion.skill`.
Validate with `scripts/quick_validate.py <repo>/skill/orion`. Keep `SKILL.md` under ~500 lines.

## Rules that are easy to break

- CSS: tokens only (no hex/rgb, raw ms, cubic-bezier), everything in `@layer s4.*`, mode blocks wrapped in `:where()`.
- Glass only on floating chrome and overlays, max two layers, solid in high contrast / reduced transparency / no
  backdrop-filter. Text on glass is `on-surface`. Content (cards, lists, panes, fields) is always solid.
- Motion (decision 0022): only transform and opacity animate (never clip-path, size, color or blur; nothing cloned).
  Dialogs and floating panels pop (rise 16px + fade), snackbars rise,
  shared axis between views. One transition per element at a time. No origin scaling. Decision 0042 amends this: menus
  fade in place with their items following (not out of the button); snackbars and tooltips are glass and rise; liquid
  motion (the `ink` spring, edges that lead and trail) only for ink (state fills), never for glass.
- Glass (decisions 0021, 0027-0029): tint 75%, blur 8px, saturate 150%, top-light edge via `--s4-glass-edge-*` inset shadows (its color is the surface's own color lifted toward white, never pure white; top and bottom are lit equally so surfaces never look raised; calibrated to the iOS tab bar, decision 0034: thin rim top and bottom, none on the sides, a soft glow inside it that inverts into an edge shade on light surfaces, decision 0036; flips at a lightness threshold, same top/bottom geometry in both modes, decision 0037); the edge width scales with screen density (1.5x standard, 2x large standard screens). The edge is for floating glass only; docked bars draw one hairline (0064).
- Decision 0025: no sharp corners anywhere a hover/press layer shows (lists 16, segments 12); FABs are glass tinted with their own color (tint 75%, default monochrome FAB icon proven at 3:1+ by `check-glass`); 41 components (added avatar, accordion, banner, skeleton, breadcrumbs, pagination, stepper, empty state); 0041 adds layout, stat, description list, prose, messages (46).
- Decision 0024: things you click are round; things you type into are medium-rounded (12), never pills or squared; selects open the glass menu; connected button groups are the Ink Track (0059).
- Decision 0023: nothing is outlined (everything filled); small things are pills, never squared or sharp. The demo is a generic mobile app (Orion Showcase) that shows every element; quizzes show only the one element being changed, not the app.
- Decision 0043 (the overhaul): a seed colors only accents (primary, selection, focus), surfaces stay neutral, status colors are fixed tokens (`--s4-color-success|warning|info|badge`); items on glass are tints (never solid patches; `check-glass` proves them); sheets are floating glass panels that pop (nothing slides from a screen edge, nothing docks); the rail is rows with a hamburger and a solid main action; no hover halos (controls answer in place); a chip never changes size; dialogs never focus a text field; errors keep the field's normal fill; lists are inset on every side, table rows are flat bands; press-to-square never inside a rounded container. Density: comfortable (touch) and compact (`data-density`); desktop apps use `data-window` + `.s4-titlebar` (`components/desktop/`). 48 components.
- Decision 0044: list rows hover with Edges Lean (own box per row, scale from `--_lean`, never a travelling highlight); an empty checkbox or radio uses `--s4-color-control` (3:1); placeholders at 85%. Compact density is opt-in, never the default.
- Decision 0045: Orion is any accent color on a neutral base; monochrome is one accent (the shipped one and the owner's favorite), never "the" look, so nothing may be designed to work only in black and white (`npm run check:accent` proves 216 accent schemes). Base grays are "Crisper" (white page, deep black), set by hand in `scripts/generate-color.mjs`. List dividers sit in the gap between rows, inset, and fade beside a hovered or selected row.
- Decision 0046 (one motion philosophy): every transition is one of ten named patterns (State, Ink, Morph, Bend, Reveal, Follow, Pop, Rise, Switch, Loop; `docs/foundations/motion.md`). CSS uses only pattern tokens (`--s4-motion-<pattern>`), script only `S4.transition.<pattern>()`; `npm run check:motion` rejects anything else. Never add a pattern without the owner.
- Decision 0047 (placement ladder): new content goes in place first (`.s4-expand`, inline `.s4-confirm`), then a menu, a pane, a floating panel; a dialog only when the app cannot go on without an answer. Do, then offer Undo, instead of "Are you sure?". 49 components.
- Decision 0049: no script ever puts the cursor in a text field, textarea or select (no `autofocus`, no `.focus()` on a field when anything opens, not even after a validation error). Only the person's own tap does. One case is the person's own action too (0067): a palette or search that their own keyboard shortcut opens (mod+K; mod+comma when it ends in the palette) may put the cursor in its search field, because they are already typing; opened by tap or click it never does. The suite fails on every other case.
- Decision 0050 (pages): three kinds of place. A view (`.s4-view`) is a destination; a page (`.s4-subpage`, `data-page-open`, `S4.pages`) is going into one thing, with Back in the bar, a title, a URL `#view/page/id` and the Back gesture; the placement ladder is for acting without leaving. Never a dialog for reading.
- Decision 0051: app behaviours are part of the language: `.s4-states` (loading, empty, error, offline for every list and pane), `.s4-form` (errors on blur, autosave, Undo), `components/direct/` (reorder with a finger, swipe, select several: never the only way to do a thing), `S4.palette` (mod+K), `data-resizable` splits, `.s4-chart` (one series = accent, several = `--s4-chart-1…6`, a table view always), small rewards. 57 components, 15 templates.
- Decision 0052: (1) nested corners are concentric: inner radius = outer radius minus the gap, or a full pill (the suite fails on a mismatch); (2) two color modes, both first class: neutral (default) and tinted (`S4.theme({ seed, surfaces: 'tinted' })`, the M3E everything-is-colored look); never design for only one, and keep an already tinted app tinted; (3) glass is for what floats over content: a toolbar in the page flow is a solid joined button group; (4) never re-insert an element while it is being touched, never animate it under the finger.
- Decision 0053 (the app is the app): Orion is a language, not a kit of parts. Adapting an existing app keeps its screens and its own elements and redraws each in Orion's style; never drop one or swap it for the nearest stock component (a chart is not a calendar). When an app needs an element Orion lacks, make it from Orion's rules (tokens, filled, round, a named motion pattern or none, text beside the picture, both color modes), first in the app's stylesheet, then in `components/` once it is general. Added that way: `.s4-ring`, `.s4-milestones`, `.s4-month` (marks: today, dot, band, flag), `.s4-timeline`. 61 components.
- Decision 0054 (tool panels): a floating panel that is a tool for the page behind it (filters, an inspector) takes `data-modeless`: from 600 wide no scrim, the page stays live, its controls act at once (no Apply). Task panels (a form you save or cancel) and all dialogs stay modal; on a phone every panel is modal.
- Decision 0055 (brand dials): what an app may change is a short list of attributes on `<html>`, set by `S4.theme`: accent, color mode, `gray` (pure, warm, cool), `page` (plain, soft), `corners` (round, soft, firm: never sharp), `display` and `text` typefaces, density, icon set. Everything you click reads `--s4-shape-control` clamped to half its height; never write a pill as `corner-full` on a control. Fixed in every app: filled, no shadows, glass only on what floats, concentric corners, the motion patterns, the behaviours. Letter spacing is tuned for Inter; headings are weight 600. `components/base/gray.css` is generated (`scripts/build-gray.mjs`, `npm run check:gray`).
- Decision 0056: every dial works on any element and nests (`data-theme`, `data-gray`, `data-page`, `data-corners`, `data-type-*`, `data-accent`, `data-energy`; `S4.theme(opts, el)`); scoped themes are for regions (a dark sidebar, a band), never one component; contrast and reduced motion/transparency stay page-wide (`npm run check:scopes`). `data-energy` calm/standard/lively, never per component. App defaults on `<html>` only pick the unmarked variant (`data-buttons="tonal"`, `data-cards="filled"`, `data-lists="segmented"`, `data-rail`); the main action still names `data-variant="filled"`. `data-density="roomy"` is for content sites only.
- Decision 0057 (website kit): a site is a document (`body.s4-site`, no app shell), fluid site type only on sites, section rhythm tokens, toned bands are inset rounded blocks, one accent a page, start-aligned, header solid then glass with a floating glass phone panel, pictures are real components in frames (never gray boxes or gradients), bento spans add to 12. Site pages load `orion.min.css`, `orion.min.js`, `icons-site.js` (defer). 62 components, 19 templates.
- Decision 0058 (reach): `dir="rtl"` mirrors everything (logical properties only; directional icons flip); dark is screen-only, print is light (`data-s4-print="hide"`); controls that hold text use `min-block-size`, never a fixed height, and truncate only in the five listed places; forced colors and focus rings are covered. `npm test` runs `tests/reach.mjs` and a dial-preset pass; a new clickable component reads `--s4-shape-control` and joins `dialAudit`.
- Decision 0059 (button groups and tabs): if it swaps what is on the screen, it is tabs; if it changes a value or how the same thing is shown, it is a button group; if it narrows a collection and there can be many, it is chips. Connected button groups are the Ink Track (a filled track, the accent ink slides on Ink with a calm-Ink trailing copy; multi fills in place and fuses neighbours; on glass the glass is the track). Tabs are the navigation family (no tray, labels on the surface, the nav indicator in `secondary-container`, heavier selected label, every tab has a panel). The page checker and suite fail a group that swaps panels and tabs without panels. Supersedes 0026, amends 0009.
- Decision 0060 (lessons from the templates): a seed with no variant is `auto` (fidelity for a muted or deep seed, vibrant for a vivid one); name `vibrant` only for a brighter version. Glass FAB labels are proven for every seed (`core.js` picks the label and raises the tint only as far as needed; `check-glass`): never switch a FAB's color for contrast. A fixed brand is restored with `S4.theme.restore(key, brand, { only: ['mode'] })`, never hand-written. Kinds of things take `--s4-category-1…6` (named in words), drawings of real objects the fixed roles, seams `--s4-space-hairline`; faces add `geometric`, `humanist` and `displayWeight`. Proposals waiting for the owner are in `docs/history/round-0056/lessons.md`.
- Decision 0061 (data at scale): more than about 50 rows, or rows from data, is `S4.table(el, opts).setRows(rows)` (virtual rows, a real `<table>`, one Tab stop, the identifying column `data-pin`ned; `data-resizable`, `data-key`, `data-column-menu` for daily tools; `data-edit` only for short values, with Undo); phones stack rows (`data-layout="scroll"` only for numbers compared across a row); narrowing a collection is `.s4-filter` (views and filters as chips, a tool panel with counts, state in the address query, never an Apply button); code is `.s4-code` with fixed `--s4-syntax-*` colors, never colored by hand; nothing is drag-only. 79 components, 20 templates.
- Decision 0062 (desktop anatomy): a desktop app writes every action once in `S4.commands` (menus, menu bar, shortcuts, `data-cmd` buttons, the palette and a shell's native menu all read it); add `.s4-menubar`, `.s4-doc-tabs` (only for things opened and closed; labels may truncate), `.s4-tree`, `.s4-inspector` (solid, in the layout) and `.s4-statusbar` only for the jobs the app has; the rail is the source list; settings is a view with search and instant changes plus Undo, never a dialog; shells start from `examples/`.
- Decision 0063 (the eleven calls): a fixed brand links its brand file (`scripts/brand.mjs`, generated for templates by the build) right after `orion.css`, so it never paints monochrome first; `.s4-kicker` (real small caps, never faked) and `figure.s4-figure` for editorial pages; a labelled track is `.s4-meter`, lanes of cards are `.s4-board` (Alt+arrows, add in place, never drag-only); in tables an empty resting checkbox is a quiet dot (amends 0044 there); every FAB color and the vibrant toolbar follow one label rule (per-color tint tokens, no exemptions); `data-dense` only for maps of real things (18px drawn, 24px apart); the selection a seed writes is never more colorful than the tonal palette; Inter is the only bundled face. 78 components (81 folders with glass, motion and icons).
- Decision 0064 (calm dialogs, docked glass): a dialog only asks a question the app cannot go on without (delete for good, leave unsaved work, a permission), with two or three named answers: Cancel tonal, a destructive answer tonal error; never one answer, never a form (page checker and suite fail both). On a phone dialogs and modal panels are a card in the bottom of the screen (inset 16, bottom corners `--s4-shape-screen` minus the inset, answers filling the width), dismissed by a tap outside, a swipe down, Escape or Back; this is automatic, never position them by hand. Scrim 16% light / 32% dark; modal glass 90%. Docked glass bars (top bar scrolled, site header, nav bar, docked toolbar) have no rim, glow or shade: one device-pixel `--s4-glass-edge-line` hairline on the content-facing edge. Floating glass keeps the full edge. Amends 0043, replaces 0039/0040.
- Decision 0065: Back restores the view's scroll and focuses what opened the page; no flow (Back, Escape, close, add in place, `S4.app.go`) leaves focus on `<body>` (the suite fails it). Data tables are the grid pattern: one Tab stop for the header and one for the body. The checker and suite fail an unknown `s4-` class, a word split across lines, a part outside its component and a status more than 2:1 from its surface: a status is a tint (accent tones are washes; only the state that needs action now is warm). Figures are `.s4-num` (right-aligned in tables). One tonal tool per toolbar. `npm run check:words` bans phrases of the old look outside decisions and history.
- Decision 0066: sites load the site bundle (`orion.site.min.css`, `orion.site.min.js`, `inter-site.woff2`, `icons-site.js`), never the app bundle, unless they need a part it leaves out (`npm run check` holds the budget and fails a site template that uses one). Danger zones are neutral panes with a `tonal` + `error` button; the dialog carries the weight. Modal panels on a phone have a grabber and a scrim that follows the drag (dialogs do not); modal glass is 96% on a phone. `corners: firm|soft` reach containers. Two more dials: `scale` (compact, large) and `headings` (tight, editorial), on any element. One filled selection per screen (refined by 0068: per region and job). A site header never opens with a nav item selected. The hub's counts are written by the build.
- Decision 0067 (dial values, header keys, proofs): every dial has a list of values (`S4.theme.dials`); `S4.theme` with a value off the list warns in the console naming the allowed values and does not write the attribute, and the page checker fails a bad `data-*` dial value in markup (`S4.theme.audit()`), so never invent a value (`data-scale="roomy"`, `corners: 'square'`). A data table says its header keys (Up from the first row, then arrows) in an `aria-description` and a `p.s4-table-hint`; keep both. A rule in the page checker or suite is only a rule once a known-bad page in `tests/fixtures` fails it (`npm run test:checker`); Back restoring scroll and focus has its own test (`npm run test:back`). 0049's one exception is a palette or search the person's own keyboard shortcut opens.
- Decision 0068: one accent fill per job in a region (at rest a rail, pane, card or header shows at most one accent selection fill and one filled main action; other selections neutral, other buttons `elevated` or `text`; a tree's selection in a rail with a current item is neutral); a wide window gets more real content, not a capped shell; site pages load `icons-site.js` (the icons the site templates draw; any other name fetches `icons-solar.js` once), site budget 150 KB.
- Decision 0069 (lean app bundle, focus landing): an app links `orion.core.min.*` plus only the packs it uses (`data`, `commands`, `desktop`, `direct`, `inputs`, `sitekit`; core first, packs after; `node scripts/packs.mjs page.html` lists them, the page checker and `npm run check` fail a page that links too few or too many); `orion.css`/`orion.js` and `orion.min.*` still load everything (prototypes, the Showcase). Budgets live in `scripts/build.mjs`; `npm run test:lean` proves a lean page equals the full bundle. A pack never relies on another except through core (`desktop` on `commands`). Closing a dialog, sheet or palette with no opener returns focus to what had it, else to main (`S4.util.land()`), never `<body>`. The grid-keys hint shows on a touch screen after the first navigation key in the table.
