## Button

Starts an action. M3 Expressive buttons: five variants, five sizes, round or square, with a shape morph on press.

```html
<button class="s4-button" type="button"><span class="s4-icon" data-icon="add"></span>Add Bill</button>
<button class="s4-button" data-variant="tonal" type="button">Export</button>
<button class="s4-button" data-variant="outlined" data-size="xs" type="button">Filter</button>
<button class="s4-button" data-toggle aria-pressed="false" type="button">Autopay</button>
<button class="s4-button" data-color="error" type="button">Delete All Data</button>
```

| Attribute | Values | Default |
|---|---|---|
| `data-variant` | `filled`, `tonal`, `elevated`, `text` (`outlined` still works and draws filled) | `filled` |
| `data-size` | `xs` (32), `s` (40), `m` (56), `l` (96), `xl` (136) | `s` |
| `data-shape` | `round`, `square` | `round` |
| `data-color` | `error` (destructive) | — |
| `data-toggle` + `aria-pressed` | toggle button; `data-label-on/off`, `data-icon-on/off` swap label and icon | — |

**When to use what:** one **filled** button for the most important action in an area; **tonal** for a strong secondary
action; **outlined** and **text** for the rest; **elevated** when a button needs to read as raised: its fill is one step above whatever it sits on (the page, a card, a
pane, a menu), a tenth of the text color mixed into that surface, so it works in light and dark and on both a page and a card (Orion has no shadows).

**Do**
- Use Title Case labels that say what happens: "Save Changes", "Export to Excel".
- Put the icon before the label.
- Use `data-color="error"` only for the confirm button of a destructive dialog or a danger zone.

**Don't**
- Don't put two filled buttons side by side; make one tonal.
- Don't grey out the main action when there's nothing to do; hide it or explain why.
- Don't color every row's delete button red; a per-row delete is a plain icon button.

**Accessibility:** every size keeps a 48dp touch target; focus shows the M3 ring; disabled buttons use M3's 12% / 38%
opacities; forced-colors mode draws a real border. Icon-only actions use the [icon button](#icon-button), which needs
an `aria-label`.

**Tokens:** `--s4-shape-button`, `--s4-shape-button-pressed`, `--s4-size-button*`, `--md-sys-typescale-label-large-*`,
`--md-sys-motion-spring-fast-spatial` (shape morph), `--md-sys-state-*`.

## Icon Button

Runs one action with one icon. M3 Expressive icon buttons: four variants, five sizes, three widths, round or square,
toggleable, with the same press morph as the [button](#button).

```html
<button class="s4-icon-button" type="button" aria-label="Edit Bill"><span class="s4-icon" data-icon="edit"></span></button>
<button class="s4-icon-button" data-variant="filled" data-size="m" type="button" aria-label="Add Bill"><span class="s4-icon" data-icon="add"></span></button>
<button class="s4-icon-button" data-variant="tonal" data-toggle aria-pressed="false" type="button" aria-label="Remind Me"><span class="s4-icon" data-icon="notifications"></span></button>
<button class="s4-icon-button" data-toggle aria-pressed="false" aria-label="Show Amounts" data-label-on="Hide Amounts" data-icon-on="hidden" type="button"><span class="s4-icon" data-icon="visible"></span></button>
```

| Attribute | Values | Default |
|---|---|---|
| `aria-label` | what the button does, Title Case | required |
| `data-variant` | `standard`, `filled`, `tonal`, `outlined` | `standard` (no container, on-surface-variant icon) |
| `data-size` | `xs` (32), `s` (40), `m` (56), `l` (96), `xl` (136); icons 20 / 24 / 24 / 32 / 40 | `s` |
| `data-width` | `narrow`, `default`, `wide` (e.g. s: 32 / 40 / 52) | `default` |
| `data-shape` | `round`, `square` | `round` |
| `data-toggle` + `aria-pressed` | toggle; `data-icon-on/off` swap the icon, `data-label-on/off` swap the `aria-label` | — |

Toggle colors (M3 Expressive): standard selected = primary icon; filled unselected = surface-container with
on-surface-variant icon, selected = primary / on-primary; tonal unselected = secondary-container, selected = secondary /
on-secondary; outlined selected = inverse-surface. A selected toggle swaps shape (round → square, square → round).
`icon-button.js` flips `aria-pressed` and fires `s4-toggle { pressed }`; inside a selecting [button group](#button-group)
the group manages it instead.

**When to use what:** **standard** in toolbars, app bars and list rows; **filled** for the one key action in a compact
spot; **tonal** for a strong secondary action; **outlined** next to filled/tonal ones for a quieter alternative.

**Do**
- Always give an `aria-label` that names the action ("Delete Electric Co.", not "Trash").
- Use toggles for on/off states (favorite, bookmark, show amounts) and swap the label with `data-label-on`.

**Don't**
- Don't use an icon button when the icon alone isn't clear; use a [button](#button) with a label.
- Don't color a per-row delete red.

**Accessibility:** native `<button>`; 48dp touch target at every size; the M3 focus ring; toggles expose `aria-pressed`;
disabled uses M3's 12% / 38%; forced-colors mode draws a border on contained variants.

**Tokens:** `--s4-shape-icon-button`, `--md-sys-shape-corner-*` (square and pressed shapes), `--s4-size-icon-button`,
`--s4-size-button-*`, `--s4-size-icon*`, `--md-sys-motion-spring-fast-spatial` (shape morph), `--md-sys-state-*`.

## Button Group

Groups related buttons. A **standard** group reacts as one when pressed; a **connected** group is one control for
choosing a value: the **Ink Track** (decision 0059), one filled track with the options on it and an accent ink pill that
slides to the choice.

**Button group, tabs or chips?** If it swaps what is on the screen, it is [tabs](#tabs). If it changes a value or how
the same thing is shown, it is a button group. If it narrows a collection and there can be many, it is
[chips](#chip).

```html
<!-- standard: actions -->
<div class="s4-button-group">
  <button class="s4-button" data-variant="tonal" type="button">Edit</button>
  <button class="s4-button" type="button">Mark Paid</button>
</div>

<!-- connected, single select: a value -->
<div class="s4-button-group" data-connected data-select="single" aria-label="Period">
  <button class="s4-button" type="button" value="week">Week</button>
  <button class="s4-button" type="button" value="month" aria-pressed="true">Month</button>
  <button class="s4-button" type="button" value="year">Year</button>
</div>

<!-- connected, several at once, icons -->
<div class="s4-button-group" data-connected data-select="multi" data-fit="content" aria-label="Attach">
  <button class="s4-icon-button" type="button" value="photos" aria-label="Photos" aria-pressed="true"><span class="s4-icon" data-icon="image"></span></button>
  <button class="s4-icon-button" type="button" value="links" aria-label="Links"><span class="s4-icon" data-icon="link"></span></button>
</div>
```

| Attribute (on the group) | Values | Default |
|---|---|---|
| `data-connected` | the Ink Track: a filled track (`surface-container-highest`, 4dp padding, corner concentric with the options) holding the options as words; the selected option is the accent ink | standard: buttons 8dp apart |
| `data-select` | `single` (exactly one pressed, radio-like: the ink slides), `multi` (each toggles: each selected option fills in place, selected neighbours fuse into one pill) | none: plain buttons |
| `data-fit` | `content`: as wide as the labels (never stretched by its parent) | connected groups stretch to fill (equal weights) |
| `aria-label` | names the choice ("Period") | — |

Children are `.s4-button` or `.s4-icon-button`; the group follows their `data-size` (xs 32, s 40, m 56, l 96, xl 136).
In a connected group their `data-variant` does not matter: every option is words on the track. Standard groups have
the M3 Expressive press interaction: the pressed button widens ~15% while its neighbours give way.

**Behaviour** (`button-group.js`): manages `aria-pressed` for `data-select`, fires `s4-change { value, values, button }`
on the group (`value` is the pressed button's `value` attribute, or the array of values for multi). Connected and
selecting groups are one tab stop (roving tabindex): Arrow keys move focus (RTL aware), Home / End jump, Space / Enter
press; disabled buttons are skipped. Groups get `role="group"`.

**From script:** `S4.buttonGroup.set(group, 'month')` (an array for `data-select="multi"`) presses that option, moves the
tab stop and slides the ink, and fires no `s4-change`, so a group can follow something the page knows (the line type
under the caret, a value restored from storage) without a loop. `S4.buttonGroup.value(group)` reads it. Setting
`aria-pressed` yourself also moves the ink, but `set` keeps exactly one option pressed in a single group.

**The ink** (connected groups while at most one option is pressed): one pill behind the options, placed by script over
the pressed option whoever changed `aria-pressed` (a click, the keyboard, a page script). It is drawn twice, the front
copy on Ink (`--s4-motion-ink`) and the back copy on calm Ink (`--s4-motion-ink-calm`), so the edge in the direction of
travel leads and the other trails, then they land together. Reduced motion: it jumps. Calm energy: both copies move
alike. A lively overshoot is clipped to the track. Without script the selected option paints its own pill. When a
group wraps (larger text, a narrow pane), options keep their full label width and the ink moves between rows; a fused
run of selected options never joins across a row break.

**When to use what:** connected + `single` for 2 to 5 short, fixed options that set a value or change how the same
content is shown (Week / Month / Year on a chart, list or grid, units, alignment); a pair (Monthly / Yearly) is the same
form with two options. Connected + `multi` for independent options shown together (formatting, attachments). Standard
for a set of related actions. A toolbar of actions can be connected (`role="toolbar"`).

**Do**
- Give each button a `value` and the group an `aria-label`; icon options need their own `aria-label`.
- Keep labels short and parallel; use the same size for every button in a group.

**Don't**
- Don't use a button group to swap panels of content (`aria-controls` pointing at a panel, a script that shows one
  region and hides another): that is tabs. The page checker and the suite fail on it.
- Don't put more than five options in a connected group; use a select or chips.
- Don't make it scroll; it wraps.

**On glass** (inside a glass bar, panel, menu or dialog): items on glass are tints (decision 0043). The glass is the
track (no fill of its own: a fill under the ink would stack two tints, which `check-glass` cannot prove for every
accent); the ink is the accent at `--s4-glass-fill-selected-opacity`; every label is `on-surface`. That selected tint
is what `scripts/check-glass.mjs` proves for 210 schemes.

**Accessibility:** buttons stay native `<button>`s with `aria-pressed`; one tab stop per group with arrow keys; the
focus ring stays above the neighbours; selection shows as fill and label color, never color alone. Forced colors: the
track and every option get a border; the selected option is `Highlight` with `HighlightText`.

**Tokens:** `--s4-space-1` (track padding), `--s4-space-2` (standard gap), `--s4-shape-control` (option corner, clamped to
half the height; the track adds its padding), `--md-sys-color-surface-container-highest` (track),
`--md-sys-color-on-surface-variant` (labels), `--md-sys-color-primary` / `on-primary` (ink), `--s4-motion-ink`,
`--s4-motion-ink-calm` (the ink), `--s4-motion-morph` (press and fusing corners), `--s4-motion-state` (colors),
`--s4-glass-fill-selected-opacity` (on glass), plus the button and icon-button tokens.

## FAB

The floating action button holds the most important action on a screen. M3 Expressive sizes: FAB 56, medium 80,
large 96, each also as an extended FAB with a label.

```html
<button class="s4-fab" type="button" aria-label="Add Bill"><span class="s4-icon" data-icon="add"></span></button>
<button class="s4-fab" data-size="m" data-color="secondary-container" type="button">
  <span class="s4-icon" data-icon="camera"></span><span class="s4-fab-label">Scan Receipt</span>
</button>
<button class="s4-fab" data-fixed type="button"><span class="s4-icon" data-icon="add"></span><span class="s4-fab-label">Add Bill</span></button>
```

| Attribute | Values | Default |
|---|---|---|
| `data-size` | (default) 56 · corner large · icon 24 · label title-medium; `m` 80 · large-increased · 28 · title-large; `l` 96 · extra-large · 36 · headline-small | 56 |
| `data-color` | `primary-container`, `secondary-container`, `tertiary-container`, `primary`, `secondary`, `tertiary` | `primary-container` |
| `.s4-fab-label` | makes it an extended FAB | — |
| `data-collapsed` | folds an extended FAB back to its icon (width animation), e.g. while a list scrolls | — |
| `data-fixed` | pins it 16dp from the bottom end corner, above the nav bar (inside `.s4-app`, put it in its view) and the safe area, at `--s4-z-fab` | — |
| `aria-label` | required when there's no label | — |

Elevation level 3, level 4 on hover; the shared state layer for hover / focus / press.

**Do**
- Use one FAB per screen, for a constructive action (Add Bill, Scan Receipt, Pay).
- Use the extended FAB when the icon alone isn't obvious.

**Don't**
- Don't use a FAB for minor or destructive actions (Delete, Settings).
- Don't put two FABs on one screen; use a FAB plus regular buttons.

**Accessibility:** native `<button>`, at least 56dp; icon-only FABs need `aria-label`; when collapsed, the label text stays
in the accessibility tree; forced-colors mode draws a border.

**Tokens:** `--s4-size-fab`, `--s4-size-fab-large`, `--s4-shape-fab`, `--s4-shape-fab-large`,
`--md-sys-shape-corner-large-increased`, `--md-sys-elevation-level3/4`, `--md-sys-typescale-title-medium/title-large/headline-small-*`,
`--md-sys-motion-spring-spatial` (collapse), `--s4-z-fab`.

## App Shell

The page frame: navigation, top app bar and content, adapting to the window size class (M3 canonical layout).

```html
<div class="s4-app">
  <nav class="s4-nav-rail" aria-label="Main">…</nav>
  <div class="s4-app-body">
    <header class="s4-top-app-bar">…</header>
    <main class="s4-content">
      <section class="s4-view" data-view="home" data-title="Home">…</section>
      <section class="s4-view" data-view="bills" data-title="Bills" hidden>…</section>
    </main>
  </div>
  <nav class="s4-nav-bar" aria-label="Main">…</nav>
</div>
```

| Part / attribute | Purpose |
|---|---|
| `.s4-app` | Size container named `s4-app`; a grid of rail + body, nav bar underneath. At least the full viewport height. |
| `.s4-nav-rail` | Optional. Shown from 840 (expanded), sticky at the left, full height. |
| `.s4-app-body` | Column holding the top app bar and the content. |
| `.s4-content` | Margins 16 (< 600) / 24 (≥ 600), width capped at `--s4-layout-content-max`, safe-area insets. |
| `.s4-nav-bar` | Optional. Shown under 840, sticky at the bottom. |
| `.s4-view[data-view][data-title]` | Optional sibling destinations. A nav item with the same `data-view` switches to it (shared axis) and sets the top app bar title to `data-title`. |
| `--s4-content-max` | Set on `.s4-app` to change the content cap (e.g. `none` for a full-width table). |
| `--s4-app-inset-bottom` | Read-only: how much of the bottom is covered (nav bar + home indicator). Use it to float a FAB or toolbar above the bar. |
| `.s4-page-header`, `.s4-section`, `.s4-section-title` | Page helpers: a title + actions row, a section with vertical rhythm, a section heading (title-medium, emphasized). |

| Window | Width | Navigation | Margins |
|---|---|---|---|
| Compact | < 600 | Nav bar at the bottom | 16 |
| Medium | 600–839 | Nav bar, items horizontal | 24 |
| Expanded+ | ≥ 840 | Nav rail at the left | 24 |

**Scrolling:** the window scrolls, not an inner box. On phones this keeps the browser's collapsing toolbars, pull to
refresh and scroll-to-top on status bar tap. The top app bar is sticky at the top, the rail sticky at the side, the nav
bar sticky at the bottom. Sticky keeps the nav bar in the page flow, so it never covers the last content and nothing
needs bottom padding. Size classes are container queries on `.s4-app`, so the shell also works inside a frame.

**Behaviour (`app.js`):** the nav bar and rail of one app stay in sync (same index). With views, a destination change
runs the shared axis transition (old view slides 30px toward where you came from and fades; new one slides in from the
side you're heading, spatial spring for movement, effects for fades), scrolls to the top and fires
`s4-change { view, previous }` on `.s4-app`. `S4.app.go(app, 'bills')` switches from code.

**Do**
- Use the same destinations, in the same order, in the nav bar and the rail.
- Put a FAB or floating toolbar at `bottom: calc(var(--s4-app-inset-bottom) + var(--s4-space-4))`.
- Use window scroll; if you need an inner scroller (a split pane), give that pane its own top app bar.

**Don't**
- Don't use `position: fixed` bars inside `.s4-app`; the shell already places them.
- Don't wrap `.s4-app` in another full-height scroll container: the bars are sticky to the window.

**Accessibility:** `main`, `nav` and `header` landmarks; give each `nav` an `aria-label`. Views that aren't shown are
`hidden`, so they leave the accessibility tree. Content and bars respect the notch and home indicator (`viewport-fit=cover`).

**Tokens:** `--s4-layout-margin-compact`, `--s4-layout-margin`, `--s4-layout-content-max`, `--s4-size-nav-bar`,
`--s4-z-navigation`, `--s4-motion-pattern-shared-axis-distance`, `--md-sys-motion-spring-spatial`, `--md-sys-motion-spring-effects`.

## Layout

S4 addition, from the M3 canonical layouts. Page widths for different kinds of screens, and the two-pane layouts most
apps need: **list-detail** (mail, contacts, bills, any CRUD app) and **supporting pane** (a document or form with
context beside it). Works inside an [app shell](#app); window classes are container queries on `.s4-app`.

```html
<!-- page width: on the content, or on one view -->
<main class="s4-content" data-width="reading">…</main>
<section class="s4-view" data-view="settings" data-width="reading">…</section>

<!-- list-detail -->
<div class="s4-split" id="inbox">
  <section class="s4-split-pane" aria-label="Messages">
    <ul class="s4-list" role="listbox" aria-label="Messages">…rows with data-split-open…</ul>
  </section>
  <section class="s4-split-pane" data-sticky aria-label="Message">
    <button class="s4-button" data-variant="text" type="button" data-split-back><span class="s4-icon" data-icon="back"></span>Inbox</button>
    …detail…
  </section>
</div>

<!-- supporting pane -->
<div class="s4-split" data-layout="supporting">
  <section class="s4-split-pane">…main…</section>
  <aside class="s4-split-pane" data-sticky>…context…</aside>
</div>
```

| Part / attribute | Values | Default |
|---|---|---|
| `data-width` on `.s4-content` or `.s4-view` | `reading` (720: articles, forms, settings, sign-in), `wide` (1600: tables, boards, editors), `full` (no cap, content only) | 1200 |
| `.s4-split` | grid of two `.s4-split-pane`s, 24 apart | — |
| `data-layout` | `list-detail`, `supporting` | `list-detail` |
| `data-open` (split) | list-detail under 840: the detail replaces the list | absent (list shown) |
| `[data-split-open]` / `[data-split-back]` | inside the split: set / clear `data-open`; back buttons hide from 840 | — |
| `data-sticky` (pane) | from 840 the pane stays in view under the top app bar and scrolls inside itself | — |
| `data-join="extra-large"` (pane) | a third list-detail pane (the open item's context) shown from 1600 only; what it holds must also be reachable from the detail | — |
| `--s4-split-list`, `--s4-split-support`, `--s4-split-join` | column widths | 360, 400, 360 |

| Window | list-detail | supporting |
|---|---|---|
| < 840 | one pane at a time; opening adds a history entry so the phone's Back returns to the list | supporting pane stacks under the main pane |
| ≥ 840 | list 360 + detail | main + 400 supporting pane |
| ≥ 1600 | list 360 + detail + joined context 360 | the same |

**Wide windows and alignment (issue 56):** capped content is centred beside the rail at every width, and the top app
bar's title and actions follow that column (the page width of the content or of the visible view). Nothing joins at
large (1200–1599): the rail expands there and takes the extra width; at extra-large a joined pane appears and `wide`
pages grow. Card grids (`.s4-grid`) fill their row. The full ladder is in `docs/foundations/spacing.md`.

**Resizable panes:** add `data-resizable` to a `.s4-split` (and `data-resize-key="name"` to remember the width). From
840 a grip sits between the panes: drag it, or focus it and use the arrow keys (Home and End for the limits);
double-click or Enter collapses the side pane and brings it back. `S4.split.resize(split, px)`,
`S4.split.collapse(split)`, event `s4-resize { size, collapsed }`.

**Behaviour (`layout.js`):** clicks on `[data-split-open]` / `[data-split-back]` toggle `data-open`, run the shared
axis (spatial movement, effects fade) when one pane replaces the other, and fire `s4-toggle { open }` on the split.
`S4.split.open(split, true|false)` does it from code, e.g. on a listbox's `s4-change`.

**When to use what:** list-detail when people pick one item from many and act on it; supporting pane when one main
thing needs context (a form with a summary, an article with related links); plain views when screens are siblings.
Pick the page width by content: reading for text and forms, default for dashboards, wide for tables.

**Do**
- On wide screens, select the first item so the detail pane is never empty (or show an [empty state](#empty-state)).
- Give each pane a name (`aria-label` or a heading).

**Don't**
- Don't nest splits.
- Don't add your own `position: fixed` panes; `data-sticky` already keeps a pane in view.

**Accessibility:** panes are landmarks or labelled sections; the hidden pane under 840 is `display: none`, so it leaves
the accessibility tree; Back (browser or button) returns focus to the list's page.

**Tokens:** `--s4-layout-content-reading`, `--s4-layout-content-wide`, `--s4-layout-list-width`,
`--s4-layout-inspector-width`, `--s4-layout-pane-gap`, `--s4-size-top-app-bar`, `--s4-motion-pattern-shared-axis-distance`.

<a id="page"></a>

## Pages

Going somewhere: a full screen you push into from a view or from another page, with Back in the top app bar, its own
title, its own URL and the phone's Back gesture. Use it whenever a thing deserves the whole screen: reading a message,
an order, a profile, a document, a step-by-step task.

```html
<main class="s4-content">
  <section class="s4-view" data-view="inbox" data-title="Inbox">
    <button class="s4-list-item" data-page-open="message" data-page-id="42" data-page-title="Maya Chen">…</button>
  </section>
  <section class="s4-subpage" data-page="message" data-title="Message" hidden>
    <header class="s4-subpage-header">
      <h2 class="s4-subpage-title">Invoice for October</h2>
      <div class="s4-subpage-meta"><span>Maya Chen</span><span>9:41</span></div>
    </header>
    …
  </section>
</main>
```

| Attribute | On | What |
|---|---|---|
| `data-page="name"` | `.s4-subpage` | the page's name (a sibling of the `.s4-view`s, starts `hidden`) |
| `data-title` | `.s4-subpage` | the top app bar title while it is open |
| `data-page-open="name"` | any control | opens that page; `data-page-id` and `data-page-title` say which item and what to call it |
| `data-page-back` | any control | goes back one level (the top app bar's Back button is added for you) |
| `data-detail-title` | `.s4-split` | the bar title when the split shows its detail on a phone (it goes one level in the same way) |

Script: `S4.pages.open(app, name, { id, title })`, `S4.pages.back(app)`, `S4.pages.home(app)` (all the way out),
`S4.pages.current(app)` gives `{ name, id }` or `null`. The page fires `s4-open { id, from }` just before it shows:
fill it from your data there. It fires `s4-close` when left.

**What it does for you**
- **Back, three ways:** the bar's Back button, the phone's Back gesture or the browser's Back button, and
  `data-page-back`. Forward works too.
- **A URL per page:** `#inbox/message/42`. Opening or reloading that link lands on the page; Back returns to its view.
- **The bar follows:** Back appears, the title becomes the page's, and both return when you leave.
- **On a phone the bottom navigation steps aside** while a page is open (a pushed page is not a destination). The
  side navigation stays on wide screens. Tapping the destination you are in takes you back to its start.
- **Your place is kept:** the view you left is scrolled back to where you were.
- **Pages can stack:** a page can open another page.

**When to use what (where things open)**
1. In place, an expand, a menu, a pane, a floating panel, a dialog: the placement ladder (see [expand](#expand)) is
   for acting on what you are looking at **without leaving**.
2. **A page** is for **going to** something: you want to read it, work on it or come back to it later by link.
3. **A view** (`.s4-view` + the navigation) is a top-level destination of the app.

On a wide screen a list with a detail pane (`.s4-split`) shows both; give the detail an "Open Full Page" button for
focused reading. On a phone the split already behaves like a page.

**Do**
- Give every page a clear title and, when it shows one item, an id, so its link can be shared.
- Fill the page in `s4-open`, from the id: a reload must show the same thing.
- Keep the page's main actions at its end or in the top app bar's actions.

**Don't**
- Don't open a page for a quick answer or a short form: that is the placement ladder.
- Don't put top-level destinations on a page; don't hide Back.
- Don't focus a field when a page opens (decision 0049).

**Accessibility:** the page takes focus when it opens (so a screen reader starts there) and focus is never moved into
a field. Back is a real button named "Back". The URL changes, so browser history, reload and sharing work.

**Motion:** Switch: forward going in, back coming out.

**Tokens:** type scale `headline-medium`, `body-medium`; `on-surface`, `on-surface-variant`; spacing `--s4-space-*`.

```html
<header class="s4-top-app-bar">
  <button class="s4-icon-button" type="button" aria-label="Back"><span class="s4-icon" data-icon="back"></span></button>
  <div class="s4-app-bar-title-group">
    <h1 class="s4-app-bar-title">Iron Mountain</h1>
    <p class="s4-app-bar-subtitle">12 Bills · $14,880.00 This Year</p>
  </div>
  <div class="s4-app-bar-actions">
    <button class="s4-icon-button" type="button" aria-label="Search"><span class="s4-icon" data-icon="search"></span></button>
  </div>
</header>
<header class="s4-top-app-bar" data-size="large">…</header>
```

| Attribute / part | Values | Default |
|---|---|---|
| `data-size` | `medium` (112, 136 with subtitle; headline-medium), `large` (120, 152; display-small) | small (64; title-large) |
| `data-align` | `center` (small only) | start |
| `data-scrolled` | set by `top-app-bar.js` while content is under the bar | — |
| `.s4-app-bar-title-group` | `.s4-app-bar-title` + optional `.s4-app-bar-subtitle` | — |
| `.s4-app-bar-actions` | trailing icon buttons (at most 3; put the rest in a "More Options" menu) | — |
| any other child | the leading slot (navigation icon button) | — |

**When to use what:** **small** for most screens and every detail screen; **medium** or **large** for a top-level
screen where the title deserves weight (Budget, Reports). They collapse into the small bar on scroll.

**Behaviour:** sticky at the top of its scroll container (the window, or the nearest scrolling ancestor). At rest the
bar is `surface`; once content scrolls under it, `data-scrolled` switches it to `surface-container` (and glass.css turns
that into glass). Medium and large stick with a negative `top`, so only the 64dp row stays; the JS slides that row down
as the headline scrolls away, clips and fades the headline, and fades a small copy of the title (`aria-hidden`) into the
row. Changing `.s4-app-bar-title` text updates the copy.

**Do**
- Use Title Case titles; keep them short enough for one line on a phone.
- Put the screen's search behind a Search action or a [search bar](#search) in the content, not in the title.

**Don't**
- Don't put text buttons and icon buttons together in the actions; use icon buttons with `aria-label`.
- Don't use medium or large on screens that also have tabs directly under the bar.

**Accessibility:** use a real heading (`h1`) for the title. Icon buttons need `aria-label`. The collapsed title copy
is hidden from assistive tech. Pads for the notch with `env(safe-area-inset-*)`.

**Tokens:** `--s4-size-top-app-bar`, `--s4-z-app-bar`, `--md-sys-color-surface` / `-surface-container`,
`--md-sys-typescale-title-large-*`, `-headline-medium-*`, `-display-small-*`, `--md-sys-motion-spring-effects`.

## Navigation Bar

Switches between 3 to 5 top-level destinations on compact and medium windows (under 840). M3 navigation bar, with M3
Expressive horizontal items from 600 wide.

```html
<nav class="s4-nav-bar" aria-label="Main">
  <a class="s4-nav-item" href="#home" data-view="home" aria-current="page">
    <span class="s4-nav-indicator"><span class="s4-icon" data-icon="home"></span></span>
    <span class="s4-nav-label">Home</span>
  </a>
  <a class="s4-nav-item" href="#bills" data-view="bills">
    <span class="s4-nav-indicator"><span class="s4-badge-host"><span class="s4-icon" data-icon="bills"></span><span class="s4-badge">3</span></span></span>
    <span class="s4-nav-label">Bills</span>
  </a>
  …
</nav>
```

| Part / attribute | Purpose |
|---|---|
| `.s4-nav-item` | `a` (navigates) or `button` (same page). 3 to 5 per bar. |
| `aria-current="page"` | The current destination: secondary-container pill, on-secondary-container icon (solid), on-surface emphasized label. |
| `.s4-nav-indicator` | The 56×32 pill around the icon; carries the state layer and focus ring. |
| `.s4-nav-label` | label-medium; on-surface-variant when not current. |
| `.s4-badge-host` + `.s4-badge` | Optional badge on the icon (see [badge](#badge)). |
| `data-view` | Ties the item to an `.s4-view` in an [app shell](#app). |

**Layout:** 80dp on surface-container. Under 600 the icon sits over the label; from 600 (the bar is its own container)
the icon and label sit side by side inside a 40dp pill. Inside `.s4-app` the bar is sticky at the bottom, pads for the
home indicator and hides from 840, where the [nav rail](#nav-rail) takes over.

**Behaviour (`nav-bar.js`):** clicking an item moves `aria-current` to it and fires `s4-change { item, index, value }`
on the bar (`value` = `data-view`, else `href`). `preventDefault()` in a click handler vetoes it. The new pill expands
from half width and fades in (spatial / effects springs, pure CSS, so changing `aria-current` from code animates too).

**Do**
- Use short, one-word Title Case labels; always show labels.
- Keep the same destinations and order as the rail.

**Don't**
- Don't use it for actions (use a FAB or toolbar) or for more than 5 destinations.
- Don't hide labels on unselected items.

**Accessibility:** a `nav` landmark with `aria-label`; `aria-current="page"` announces the current destination. Every
item is a full-height cell (≥ 48dp target). The focus ring wraps the pill. Forced colors: the current pill uses
Highlight and the bar gets a top border.

**Tokens:** `--s4-size-nav-bar`, `--s4-size-nav-indicator-width/height`, `--s4-shape-nav-indicator`,
`--md-sys-color-surface-container`, `--md-sys-color-secondary-container`, `--md-sys-typescale-label-medium-*`,
`--md-sys-state-*`, `--md-sys-motion-spring-spatial`, `--md-sys-motion-spring-effects`.

<a id="nav-rail"></a>

## Navigation Rail

> **Decision 0043:** the rail is side navigation. Items are rows (icon, label beside it). Collapsed it is one icon wide
> (72) and labels become hover titles; expanded (240) the labels show; it expands by itself from 1200
> (`data-expand="off"` to stop that). The menu button is a hamburger. The header's `.s4-fab` is a solid primary button
> in the same row shape, never glass. Optional `.s4-nav-rail-title` group titles and a `.s4-nav-rail-footer` that stays
> at the bottom. Where the text below still describes labels under icons or a 96dp rail, this note wins.

Top-level destinations at the side of expanded windows (840 and up). M3 Expressive rail: collapsed (96dp) or expanded,
with an optional menu button and FAB. Uses the same `.s4-nav-item` as the [navigation bar](#nav-bar) (styles in
`nav-bar.css`).

```html
<nav class="s4-nav-rail" aria-label="Main">
  <div class="s4-nav-rail-header">
    <button class="s4-icon-button" type="button" data-rail-toggle aria-expanded="false" aria-label="Expand Navigation"
            data-label-expand="Expand Navigation" data-label-collapse="Collapse Navigation"><span class="s4-icon" data-icon="menu"></span></button>
    <button class="s4-fab" type="button" aria-label="Add Bill"><span class="s4-icon" data-icon="add"></span><span class="s4-fab-label">Add Bill</span></button>
  </div>
  <div class="s4-nav-rail-items">
    <a class="s4-nav-item" href="#home" aria-current="page"><span class="s4-nav-indicator"><span class="s4-icon" data-icon="home"></span></span><span class="s4-nav-label">Home</span></a>
    …
  </div>
</nav>
```

| Attribute / part | Purpose |
|---|---|
| `data-expanded` | Expanded rail: wider (`--s4-nav-rail-expanded-width`, default 240), labels beside icons, label-large, a 56dp pill spanning icon and label, surface-container. |
| `[data-rail-toggle]` | Button that flips `data-expanded`; `aria-expanded` and the optional `data-label-expand/collapse` labels follow. |
| `.s4-nav-rail-header` | Menu button and FAB slot. In the collapsed rail the FAB's label is hidden (icon FAB); expanded it shows (extended FAB). |
| `.s4-nav-rail-items` | The destinations (`.s4-nav-item`, see nav bar). |

**As a desktop source list (issue 60):** the expanded rail is the sidebar of a desktop app. It takes sections with
titles (`.s4-nav-rail-title`), sections that fold away, a [tree](#tree), a footer for the account and Settings, a grip
to resize it, and it still collapses to icons. There is no second sidebar component.

```html
<nav class="s4-nav-rail" aria-label="Project" data-expanded data-resizable data-resize-key="app-sidebar">
  <div class="s4-nav-rail-items">
    <a class="s4-nav-item" href="#strings" aria-current="page">…</a>
    <div class="s4-nav-rail-group">
      <button class="s4-nav-rail-title" type="button" aria-expanded="true">Languages</button>
      <div class="s4-nav-rail-group-items"><a class="s4-nav-item" href="#fr">…</a>…</div>
    </div>
    <div class="s4-nav-rail-title">Files</div>
    <ul class="s4-tree" aria-label="Files" data-density="compact">…</ul>
  </div>
  <div class="s4-nav-rail-footer">…account, Settings…</div>
</nav>
```

| Part / attribute | What |
|---|---|
| `.s4-nav-rail-group` + `button.s4-nav-rail-title` + `.s4-nav-rail-group-items` | A section whose title folds it (Reveal); `aria-expanded` follows; remembered with `data-resize-key`. Collapsed to icons, a folded group still shows its icons |
| `.s4-tree` inside | A tree in a section; its icons line up with the items; hidden while the rail is collapsed |
| `data-resizable` (+ `data-resize-key`) | A grip on the end edge (`role="separator"`): drag, or Left / Right on it, Home / End for 200 and 400, Enter collapses or expands; dragged narrower than 150 it collapses. Fires `s4-resize { size, collapsed }` |

**Behaviour (`nav-rail.js`):** item clicks move `aria-current` and fire `s4-change { item, index, value }`; the toggle
fires `s4-toggle { expanded }`. The width animates on the spatial spring, labels fade in on effects; icons stay in place
because the expanded pill starts where the collapsed one did. In an [app shell](#app) the rail is sticky at full
height from 840 and mirrors the nav bar.

**Do**
- Put the screen's main action in the FAB slot; give the FAB an `aria-label` (the label is hidden when collapsed).
- Keep destinations identical to the nav bar.

**Don't**
- Don't put secondary actions or settings toggles in the rail.
- Don't use the rail on compact windows; use the nav bar.

**Accessibility:** `nav` landmark with `aria-label`; `aria-current="page"`; the toggle exposes `aria-expanded`. Items keep
≥ 48dp targets. Forced colors: the rail gets an end border.

**Tokens:** `--s4-size-nav-rail`, `--s4-size-nav-indicator-*`, `--s4-shape-nav-indicator`, `--s4-size-icon-button`,
`--md-sys-color-surface` / `-surface-container`, `--md-sys-typescale-label-large-*`, `--md-sys-motion-spring-spatial`.

<a id="tabs"></a>

## Tabs

Move between different panels of content within one screen: a bill's Details, Payments and Notes; a workspace's
Overview, Activity and Files. Tabs belong to the **navigation family** with the nav bar and the nav rail (decision
0059, amending the Segmented Tray of 0009): no tray, the labels sit on the surface, and the selected tab gets the same
neutral indicator the nav bar and rail use, sliding from tab to tab; its label steps up in weight.

**Tabs, button group or chips?** If it swaps what is on the screen, it is tabs. If it changes a value or how the same
thing is shown (Week / Month / Year on a chart, list or grid), it is a [button group](#button-group). If it narrows a
collection and there can be many, it is [chips](#chip).

**Tabs or document tabs?** These tabs are a fixed set of views of one thing, chosen by the app: they never close, never
move and their set does not change. The open files or records of a desktop window, which the person opens, closes and
reorders, are [document tabs](#doc-tabs) (`.s4-doc-tabs`): each a filled pill with a close button and an
unsaved-changes dot, no sliding indicator.

```html
<div class="s4-tabs" role="tablist" aria-label="Bill">
  <button class="s4-tab" type="button" role="tab" id="tab-details" aria-controls="panel-details" aria-selected="true">Details</button>
  <button class="s4-tab" type="button" role="tab" id="tab-payments" aria-controls="panel-payments" aria-selected="false">Payments</button>
</div>
<div class="s4-tab-panel" role="tabpanel" id="panel-details" aria-labelledby="tab-details">…</div>
<div class="s4-tab-panel" role="tabpanel" id="panel-payments" aria-labelledby="tab-payments" hidden>…</div>
```

| Attribute | Values | Default |
|---|---|---|
| `data-variant` | `secondary`: inside a pane or card. Smaller (32dp indicator, label-large) and quieter (the indicator is a 12% tint of the text color over whatever it sits on), icons inline | primary: 40dp indicator in `secondary-container`, title-small, icons stacked above the label |
| `data-scrollable` | adds scroll padding so the selected tab scrolls clear of the edge (any row scrolls sideways when the tabs do not fit; it never wraps) | — |
| `aria-selected` | `true` on the current tab | first tab |
| `aria-controls` | id of the tab's panel: **required**, every tab has a panel | — |
| icon | `<span class="s4-icon" data-icon="…">` before the label: stacked in primary (the indicator holds icon and label, as in the nav bar), inline in secondary | — |

Tabs sit at the start of the row and are as wide as their labels (16dp each side; 12 in secondary). The indicator's
corner is the nav indicator's (`--s4-shape-nav-indicator`, clamped to half its height), so it follows the corner dial.

**When to use what:** **primary** tabs right under the top app bar to organize the whole screen; **secondary** tabs
inside a pane or card to divide it further. Many tabs on a phone: the row scrolls (add `data-scrollable`).

**Behaviour (`tabs.js`):** one indicator slides between tabs on the Ink pattern, measured to the selected tab's box.
Each label's text is wrapped in `.s4-tab-label` (`data-text` holds it) so the heavier selected weight never changes the
tab's width or moves its neighbours. Panels switch with the shared axis pattern (Switch): the old panel slides 30px away
and fades out, the new one slides in from the side of the newly selected tab. Keys: Left / Right (wrapping, RTL aware),
Home / End, with automatic activation and a roving tabindex. Fires `s4-change { tab, index, panel }` on the tab list.
Missing ids, roles and `aria-labelledby` are filled in. Without JS each selected tab paints its own indicator.

**Do**
- Use short Title Case labels (one or two words) and keep the tab order stable.
- Put tabs at the top of the content they switch; give every tab a panel.

**Don't**
- Don't use tabs to set a value or change how the same content is shown (a period, a unit, list or grid): that is a
  button group. Tabs without panels fail the page checker and the suite.
- Don't use tabs for a sequence of steps (a stepper) or for actions.
- Don't nest primary tabs inside primary tabs; use secondary tabs.

**Accessibility:** WAI-ARIA tabs pattern; the tab list is one tab stop and panels are focusable. Selected shows as the
indicator, the label color and a heavier weight (and a solid icon), not color alone. Inner focus ring so a scrolling
row never clips it; the 48dp touch target sits inside the row's padding. Forced colors: the indicator is `Highlight`
and the selected label `HighlightText`.

**Tokens:** `--s4-size-button` / `--s4-size-button-small` (indicator height), `--s4-size-touch-target`,
`--s4-shape-nav-indicator`, `--md-sys-typescale-title-small-*` and `--md-sys-typescale-label-large-*` (labels; the
`emphasized` weights when selected), `--md-sys-color-secondary-container` / `on-secondary-container` (primary
indicator), `--md-sys-color-on-surface` (secondary indicator tint and label), `--md-sys-color-on-surface-variant`
(labels at rest), `--s4-motion-ink` (indicator), `--s4-motion-state` (label color), the Switch pattern
(`S4.transition.sharedAxis`) for panels.


| Attribute / part | Values | Default |
|---|---|---|
| `data-color` | `vibrant` (primary-container) | standard (surface-container) |

| `data-type` | `docked`: full width, 64dp, square corners, no shadow, home-indicator padding | floating: 64dp pill, elevation 3 |

| `.s4-toolbar-dock` | toolbar + FAB in a row; `data-position="bottom"` floats the pair centered above the bottom (and above the nav bar in an app shell) | — |

**Do**
- Use icon buttons with `aria-label`; one tonal or filled button is fine for the key action.
- Keep 3 to 6 actions; move the rest into a "More Options" menu.

**Don't**
- Don't put navigation destinations in a toolbar (use the nav bar or rail).
- Don't stack a docked toolbar and a nav bar.

**Accessibility:** WAI-ARIA toolbar pattern with `aria-label`; disabled controls are skipped. Forced colors: the toolbar
gets a border (its shape is otherwise only a background).

## Search

A search bar that filters the current page as you type. M3 search bar (no full-screen search view).

```html
<div class="s4-search" role="search" data-filter="#bill-list" data-filter-empty="#bill-empty">
  <span class="s4-icon" data-icon="search"></span>
  <input class="s4-search-input" type="search" placeholder="Search Bills" aria-label="Search bills">
  <button class="s4-icon-button s4-search-clear" type="button" aria-label="Clear Search" hidden><span class="s4-icon" data-icon="close"></span></button>
  <button class="s4-icon-button" type="button" aria-label="Account"><span class="s4-search-avatar">AS</span></button>
</div>
```

| Attribute / part | Purpose |
|---|---|
| `.s4-search` | 56dp, full radius, surface-container-high, up to 720 wide. `role="search"`. |
| leading `.s4-icon` or `.s4-icon-button` | the search icon, or a menu / back button |
| `.s4-search-input` | `type="search"`, body-large, placeholder in on-surface-variant |
| `.s4-search-clear` | shown while there's text; clears and refocuses |
| trailing `.s4-icon-button` / `.s4-search-avatar` | optional actions or the account avatar (32dp initials or `<img>`) |
| `data-filter="<selector>"` | hide the target's children that don't contain the text (case and accent insensitive); `data-filter-skip` on a child keeps it |
| `data-filter-empty="<selector>"` | element shown when nothing matches |

**Behaviour (`search.js`):** every edit fires `s4-change { value, matches }` on `.s4-search` (`matches` is the visible
count with `data-filter`, else `null`). Escape clears. Clicking the bar's empty space focuses the input.

**Do**
- Say what's searched in the placeholder: "Search Bills", "Search Vendors".
- Show a short empty message when nothing matches.

**Don't**
- Don't add a Search button; results update as you type.
- Don't use a search bar as a general text field.

**Accessibility:** a `search` landmark; the input needs `aria-label` (the placeholder isn't a label). The bar is the field and
carries the one focus mark: the focus ring inside its edge from the keyboard, a quiet accent hairline after a tap or click. The clear button is a real button with a label. Forced colors: the bar gets a border.

**Tokens:** `--s4-size-text-field` (56), `--s4-shape-search`, `--md-sys-color-surface-container-high`,
`--md-sys-typescale-body-large-*`, `--s4-layout-list-width` (×2 = 720 max).

## Desktop Windows

What an Orion app needs to live in a desktop window or ship as a desktop app (an installed web app, Electron, Tauri),
on the same shell and components (decision 0043), and the anatomy of a desktop window (issue 60).

```html
<html lang="en" data-density="auto">
<div class="s4-app" data-window>
  <header class="s4-titlebar">                                        <!-- drags the window -->
    <div class="s4-menubar" aria-label="Application" data-menus="app"></div>
    <span class="s4-titlebar-title">Ledger</span>
  </header>
  <nav class="s4-nav-rail" aria-label="Main" data-resizable>…</nav>   <!-- the sidebar / source list -->
  <div class="s4-app-body">
    <div class="s4-doc-tabs">…</div>                                  <!-- the open documents -->
    …
  </div>
  <aside class="s4-inspector" aria-label="Inspector">…</aside>        <!-- properties of the selection -->
  <footer class="s4-statusbar" aria-label="Status">…</footer>
</div>
```

### The anatomy

| Part | Where | What |
|---|---|---|
| Title bar | here, `.s4-titlebar` | Drags the window; holds the title, the menu bar, document tabs or a toolbar; room for the system's window buttons |
| Menu bar | [`menubar/`](#menubar) | File, Edit, View… inside the window (Windows, Linux, web); hidden where the system draws it (Mac) |
| Commands | [`commands/`](#commands) | One list of actions feeding the menu bar, menus, shortcuts, the palette and a shell's native menu |
| Sidebar | [`nav-rail/`](#nav-rail) | The rail, expanded: destinations, folding sections, a [tree](#tree), account and Settings at the foot; resizable, collapses to icons |
| Document tabs | [`doc-tabs/`](#doc-tabs) | The open files or records: close, reorder, reopen, unsaved dot |
| Content | [`layout/`](#layout) | List and detail (`.s4-split[data-resizable]`), each pane scrolling on its own |
| Inspector | here, `.s4-inspector` | A resizable pane at the window's end for the properties of the selection |
| Status bar | [`statusbar/`](#statusbar) | Sync, selection, position, zoom, connection |
| Palette | [`palette/`](#palette) | mod+K: every command and destination by name |

On a phone the same page is the normal touch app: the title bar, menu bar, document tabs, inspector and status bar
step out (under 600 or 840), the rail becomes the nav bar, and each list opens its detail as a page.

### Classes and attributes

| Class / attribute | What |
|---|---|
| `data-window` on `.s4-app` | The app fills the window and never scrolls as a page; the body and each pane scroll on their own. Thin scrollbars, arrow cursor on controls, chrome text can't be selected. |
| `data-density="auto"` (best on `<html>`, so menus and panels follow) | Pointer-sized controls where the pointer is a mouse (see `base/density.css`); `compact` forces it. |
| `.s4-titlebar` | A title bar that drags the window (`app-region: drag`). Buttons, links, fields, the menu bar, tabs and anything with `data-no-drag` stay clickable. Hidden under 600. |
| `data-variant="tabs"` on the title bar | The document tabs are the title bar (no title); the space around them drags. A browser-like document window. |
| `data-variant="unified"` on the title bar | A taller bar (52) that holds the window's toolbar: title at the start, then search and buttons. A tool window. |
| `.s4-titlebar-title`, `data-align="start"` | The title, centered (or at the start) |
| `.s4-titlebar-spacer` | Pushes what follows to the end |
| `data-controls="start"` on the title bar | Room for the Mac's traffic lights in a frameless window (also automatic with `<html data-platform="mac" data-shell="electron\|tauri">`) |
| `.s4-window-controls` > `.s4-window-control[data-window-action="minimize\|maximize\|close"]` | Window buttons for frameless shells that do not draw their own; each click fires `s4-window { action }` on the document. Wire it to the shell. |
| `.s4-inspector` (+ `.s4-inspector-header`, `-title`, `-body`, `details.s4-inspector-group`, `.s4-inspector-fields`, `.s4-inspector-row`) | The properties pane at the window's end: solid, resizable from its start edge (drag, arrows, Home/End, Enter hides it), `data-resize-key` remembers the width, groups fold with Reveal. From 840 wide. `S4.desktop.inspector(el, on)`; `--s4-inspector-width`. |
| `data-shortcut="mod+k"` | That key combination clicks the element. `mod` is ⌘ on Apple platforms, Ctrl elsewhere; also `shift`, `alt`. |
| `<kbd class="s4-kbd">` | Shows a shortcut. Empty inside a `data-shortcut` or `data-cmd` element (or with `data-for="id"`), it is filled in the platform's spelling. |
| `data-context-menu="menu-id"` | Right-click (long press on touch, Shift+F10 or the menu key) opens that menu at the pointer or under the element. The menu fires `s4-context { target }` and has `.contextTarget`. |
| `<html data-platform>` | `mac`, `windows`, `linux`, `ios`, `android`; set once by the script unless the page set it |
| `<html data-shell="electron\|tauri\|pwa">` | Set by your shell bridge (see `examples/`) |
| `<html data-native-menu>` | The shell draws the native menu bar: the in-window menu bar hides (a Mac shell sets it) |
| `<html data-window-blurred>` | Set while the window is not in front: title bar, menu bar and status bar step back to `on-surface-variant`, tree selections turn neutral |
| `<html data-window-state="fullscreen overlay maximized">` | `fullscreen` (no room kept for the traffic lights), `overlay` (an installed web app draws into the title bar area); set by the script where the browser knows, or by the shell |

Script: `S4.desktop.platform`, `S4.desktop.format('mod+k')` (⌘K or Ctrl+K), `S4.desktop.matches(event, 'mod+k')`,
`S4.desktop.inspector(el, on)`. Events: `s4-window { action }`, `s4-context { target }`.

### The window

**Drag regions.** The title bar is `app-region: drag` (Electron and installed web apps; Tauri reads a
`data-tauri-drag-region` attribute instead: see `examples/README.md`). Everything you click in it is `no-drag`. Never make content
draggable as a window.

**Window buttons.** On a Mac they are the traffic lights at the start: a frameless window keeps about 80 of room for
them (`data-controls="start"`), full screen gives it back. On Windows and Linux they are at the end: an installed web app
with window controls overlay draws its title bar into `env(titlebar-area-*)` (`.s4-titlebar` already reads it), and
Electron's `titleBarOverlay` does the same. Draw `.s4-window-controls` only in a frameless shell that draws none.

**In front or not.** A window that is not in front dims its chrome a step and its selections turn gray, as every
desktop does, so you can tell which window has the keyboard. Content never dims.

**Selection and cursor.** Chrome (title bar, menu bar, rail, tabs, status bar, buttons, labels) cannot be selected as
text and keeps the arrow cursor; content (messages, documents, fields, tables) stays selectable, and links in content
keep the pointing hand.

**Full screen.** Nothing is kept for window buttons; the title bar stays (it holds the menu bar and tabs).

### Platform conventions (express them in Orion, don't copy their look)

| | Mac | Windows | Linux (GNOME, KDE) |
|---|---|---|---|
| Menu bar | The system's, at the top of the screen (shell builds it from the commands) | In the window (`.s4-menubar`), or none with everything in the palette and toolbars | In the window |
| Window buttons | Traffic lights at the start | At the end | At the end (GNOME: close only, by default) |
| Settings | App menu, "Settings…", ⌘, | File or Tools menu, "Settings", Ctrl+, | Main menu, "Preferences" or "Settings", Ctrl+, |
| Quit | App menu, ⌘Q | File, Exit (Alt+F4 closes) | File, Quit, Ctrl+Q |
| Rename | Enter | F2 | F2 |
| Delete | ⌘⌫ | Delete | Delete |
| Redo | ⇧⌘Z | Ctrl+Y (and Ctrl+Shift+Z) | Ctrl+Shift+Z |
| Context menu key | none (Ctrl-click) | Shift+F10, menu key | Shift+F10, menu key |

### Settings: a window, not a dialog

On a desktop, settings are their own surface: a view (or, in a shell, a second window) with a sidebar of categories
and a pane, a search box that finds a setting across categories, and every change applied at once with Undo in a
snackbar: no Save button, no OK and Cancel. mod+comma opens it. On a phone the same settings are the
[settings template](../../templates/settings.html)'s list, then a page per category. The
[desktop template](../../templates/desktop-app.html) shows both from one markup: a `.s4-split` of categories and pane.

### Inspector or tool panel?

| | Inspector (`.s4-inspector`) | Tool panel (`.s4-side-sheet[data-modeless]`, decision 0054) |
|---|---|---|
| Shows | The properties of what is selected, and changes them | A tool that works on the whole page: filters, find and replace, a color picker |
| Lives | In the window's layout, at its end, solid; the content makes room | Floats over the content (glass) and can be moved away |
| Follows | The selection: it changes as you pick another item | Nothing: it stays as it is |
| On a phone | Steps out; the same properties belong in the item's own page | Becomes a modal panel |
| Use when | People edit properties of items all day (an editor, a design or data tool) | People reach for the tool now and then |

### When, Do, Don't

**When:** `data-window` for anything used like an application (mail, an editor, a dashboard that stays open). A page
people read (article, landing page) keeps normal page scrolling. Add the menu bar, document tabs, inspector and status
bar only when the app has those jobs: a small tool is a title bar, a sidebar and content.

**Do:** give every primary action a command with a shortcut and show it in its menu item and tooltip; keep right-click
menus short and make every item reachable another way; keep chrome quiet so content leads (one weight of type, no
fills at rest, solid surfaces).

**Don't:** draw `.s4-window-controls` when the system already draws its own; don't put the only way to do something in
a context menu, the menu bar or a shortcut; don't make the window scroll as a page; don't put glass on the title bar,
sidebar, status bar or inspector (they don't float).

**Accessibility:** shortcuts never fire while typing unless they use `mod`; context menus are normal menus (arrows,
Escape, typeahead) and return focus; the grips are separators with values and arrow keys; every landmark has a name.

**Tokens:** `--s4-size-titlebar`, `--s4-size-menubar-item`, `--s4-size-doc-tab`, `--s4-size-statusbar`,
`--s4-size-tree-row`, `--s4-size-tree-indent`, `--s4-size-inspector`, `--s4-density-compact-*`.

**A real shell:** [`examples/`](../../examples/) has an Electron skeleton (frameless window, drag regions, traffic
lights or the Windows overlay, the native menu built from `S4.commands.native`, focus and full-screen states) and an
installed web app with window controls overlay. Neither can be run in this repository's CI; they are kept small and
follow the documented APIs.

<a id="menubar"></a>

## Menu Bar

The application menu inside the window: File, Edit, View, Window, Help. For Windows and Linux shells and for web apps
in a window; on a Mac the system draws the menu bar, so a Mac shell builds the native menu from the same
[commands](#commands) and sets `<html data-native-menu>`, which hides this one. Not shown on a phone (under 600):
the same commands are in the palette and in each screen's own menus.

```html
<header class="s4-titlebar">
  <div class="s4-menubar" aria-label="Application" data-menus="app"></div>
  <span class="s4-titlebar-title">Field Notes</span>
</header>
<script>S4.commands.menu('app', [{ label: 'File', items: ['file.new', 'file.open', '-', 'file.save'] }, …]);</script>

<!-- or by hand -->
<div class="s4-menubar" role="menubar" aria-label="Editor">
  <button class="s4-menubar-item" type="button" data-menu="m-file">File</button>
</div>
<div class="s4-menu" id="m-file" aria-label="File">…</div>
```

| Part / attribute | What |
|---|---|
| `.s4-menubar` | The bar (`role="menubar"`). In the title bar it never drags the window; or put it in its own row at the top |
| `data-menus="name"` | Fill it from `S4.commands.menu(name, [{ label, items }])` |
| `.s4-menubar-item` + `data-menu` | One menu's button (by hand); `data-access="x"` picks its Alt letter (default: its first letter) |
| `<html data-native-menu>` | Hide it: the shell draws the native menu bar (a Mac shell sets this) |
| Script | `S4.menubar.render(bar, items)`, `S4.menubar.focus(bar)` |

The menus are the glass [menu](#menu), with submenus, check and radio items, disabled items and shortcut hints in the
platform's spelling (⌘S on a Mac, Ctrl+S elsewhere).

**Where things live (platform conventions):** File (New, Open, Open Recent, Save, Close; on Windows and Linux also
Settings and Exit), Edit (Undo, Redo, Cut, Copy, Paste, Find), View (panels, zoom, full screen), the app's own menus,
Window (on a Mac), Help (shortcuts, about). On a Mac, Settings and Quit live in the app menu the system draws; a shell
puts them there from the same commands (see `examples/`).

**Do:** keep menu names to one word; give every item a shortcut that the platform's apps use for the same thing; show
disabled items instead of removing them. **Don't:** put the only way to do something in the menu bar; don't build a
menu bar on a phone or a Mac shell.

**Accessibility:** WAI-ARIA menubar. Left and Right move along the bar (and switch the open menu), Down, Enter or Space
open a menu at its first item, Up at its last, Home and End, a letter jumps to a menu; inside a menu the arrow away from
it moves to the next menu, the arrow back closes a submenu. F10 or a lone Alt moves focus to the bar and back; Alt with
a letter opens that menu (not while typing on a Mac, where ⌥ types characters); Escape closes and returns focus. One tab
stop for the bar.

**Tokens:** `--s4-size-menubar-item`, `--s4-shape-control`, `--md-sys-color-secondary-container` (the open menu's item),
label-large type.

<a id="doc-tabs"></a>

## Document Tabs

The open documents of a desktop window: files, records, conversations. Each tab is a thing you opened: it closes,
carries a dot while it has unsaved changes, moves, and comes back after you close it by mistake.

**Not the [content tabs](#tabs).** Content tabs switch between a fixed set of views of one thing (Overview,
Activity, Settings) and belong to the navigation family (decision 0059): they never close, never move and their set
does not change. Document tabs are made and closed by the person, as many as they like, and can be reordered. If the
set of tabs is fixed by the app, use content tabs.

```html
<div class="s4-doc-tabs">
  <div class="s4-doc-tabs-list" aria-label="Open Files">
    <div class="s4-doc-tab" data-modified>
      <button class="s4-doc-tab-label" type="button" aria-selected="true" aria-controls="doc-1">
        <span class="s4-icon" data-icon="document"></span><span class="s4-doc-tab-text">dialogue.json</span></button>
    </div>
  </div>
  <button class="s4-icon-button s4-doc-tabs-new" type="button" aria-label="New File" data-cmd="file.new"><span class="s4-icon" data-icon="add"></span></button>
</div>
<section id="doc-1">…</section>
```

| Part / attribute | What |
|---|---|
| `.s4-doc-tabs` | The row (on chrome). In a title bar: `.s4-titlebar[data-variant="tabs"]` |
| `.s4-doc-tabs-list` | The tabs (`role="tablist"`); scrolls sideways when full |
| `.s4-doc-tab` + `.s4-doc-tab-label` | One tab: the label is the `role="tab"` button; `aria-controls` names its panel |
| `data-modified` on a tab | Unsaved changes: the close button is a dot until you point at the tab |
| `.s4-doc-tabs-new` | Your new-tab button (wire it to a command) |
| Added by the script | Each tab's close button, the All Tabs menu button (shown only when the tabs don't fit), the right-click menu (Close, Close Others, Close To The Right, Move Left, Move Right) |
| `data-keys="off"` | This row ignores the window-wide keys |
| Events on `.s4-doc-tabs` | `s4-change { tab, index, panel }`; `s4-close { tab, panel, modified }` before closing (`preventDefault()` keeps it); `s4-reorder { item, from, to }` |
| Script | `S4.docTabs.add(bar, { label, icon, panel, modified, select, next })`, `.select(tab)`, `.close(tab)`, `.reopen(bar)`, `.move(tab, index)`, `.modified(tab, on)`, `.tabs(bar)`, `.current(bar)` |

**Keys and pointer:** click selects, middle-click closes, drag reorders (a finger: hold, then drag). On a tab: Left and
Right (move and select), Home, End, Delete (close), mod+Shift+PageUp / PageDown (move). Anywhere: mod+W closes the
current tab, mod+Shift+T reopens the last closed one, mod+1 to mod+8 pick a tab and mod+9 the last, Ctrl+Tab and
Ctrl+Shift+Tab (or Ctrl+PageDown / PageUp) step through them. A browser keeps mod+W, Ctrl+Tab and mod+1…9 for its own
tabs; in an installed app or a desktop shell they all work, and each has a click or a menu item that does the same.

**Closing unsaved work:** do, then offer the way back (decision 0047): close it and show a snackbar with Reopen
(`S4.docTabs.reopen`), rather than asking first. Keep the unsaved changes with the closed tab.

**Look:** the current tab takes the content's surface (it is the document under it); the others are quiet labels with
the state layer on hover. Corners follow the dial. Labels end in an ellipsis when long (the one place besides the title
bar title where a desktop window cuts text); the full name is in the All Tabs menu. Under 600 wide the row hides: a phone
shows one document at a time. Switching shows the panel at once (no motion: a document is not a view to slide to).

**Do:** show the file's or record's name and an icon of its kind; put a new-tab button at the end. **Don't:** use
document tabs for a fixed set of views; don't nest them; don't close a tab with unsaved work without a way back.

**Accessibility:** tabs pattern with one tab stop; close buttons are out of the tab order (Delete closes); the close
button's name says "unsaved changes" when the dot shows; forced colors give every tab a border.

**Tokens:** `--s4-size-doc-tab`, `--s4-shape-control`, `--md-sys-color-surface` (current tab),
`--md-sys-color-surface-container-low` (the row), label-large type.

<a id="statusbar"></a>

## Status Bar

A slim solid bar along the bottom of a desktop window for the state of things: saved and synced, what is selected,
where the cursor is, the zoom, the connection. Quiet chrome: small type, no fills at rest, the content leads.

```html
<footer class="s4-statusbar" aria-label="Status">
  <span class="s4-statusbar-item"><span class="s4-statusbar-dot" data-tone="success"></span>Saved</span>
  <span class="s4-statusbar-item" role="status" aria-live="polite">3 Selected</span>
  <span class="s4-statusbar-spacer"></span>
  <button class="s4-statusbar-item" type="button" data-menu="zoom-menu">100%</button>
</footer>
```

| Part / attribute | What |
|---|---|
| `.s4-statusbar` | The bar. In a `data-window` app it spans the window's last row; shown from 840 wide |
| `.s4-statusbar-item` | A segment: text, optionally an icon or dot before it. A `button` (or `a`) segment opens a menu (`data-menu`), a panel (`data-sheet`) or runs a command (`data-cmd`) |
| `data-tone="error"` on an item | The words turn error colored |
| `.s4-statusbar-dot[data-tone="success\|warning\|info\|error"]` | A dot beside words that already say the state |
| `.s4-statusbar-spacer` | Pushes what follows to the end |

**When to use:** a desktop app whose state people glance at while they work (an editor, a mail client, a data tool).
Not for actions (use the toolbar or the menus), not on a phone (each screen shows its own state), not in a web page.

**Do:** put what changes as you work on the left (sync, selection, position) and settings of the view on the right
(language, zoom, connection); write states as words ("Saved", "Offline: 3 changes waiting"). **Don't:** make a
segment the only way to reach what it opens; don't use color alone; don't fill it with buttons.

**Accessibility:** a `footer` with a name. A segment that changes as people work gets `role="status"` and
`aria-live="polite"` so it is announced without moving focus. Clickable segments are real buttons in the tab order.

**Tokens:** `--s4-size-statusbar`, `--md-sys-color-surface-container-low`, label-medium type, `--s4-color-success`,
`--s4-color-warning`, `--s4-color-info`.

<a id="commands"></a>

## Commands

One list of what an app can do, written once, and every way of doing it drawn from that list: the
[menu bar](#menubar), menus and right-click menus, keyboard shortcuts, the [command palette](#palette), buttons,
and a desktop shell's native menu. A command knows its label, icon, shortcut, whether it can run now and whether it is
on, so every place shows the same words, the same shortcut and the same state.

```js
S4.commands.add([
  { id: 'file.save', label: 'Save', group: 'File', icon: 'save', shortcut: 'mod+s',
    enabled: function () { return doc.dirty; }, run: function (ctx) { save(); } },
  { id: 'view.wrap', label: 'Word Wrap', group: 'View', type: 'check', shortcut: 'alt+z',
    checked: function () { return wrap; }, run: function () { wrap = !wrap; } },
  { id: 'zoom.100', label: '100%', type: 'radio', radio: 'zoom', palette: false,
    checked: function () { return zoom === 100; }, run: function () { zoom = 100; } }
]);
S4.commands.menu('app', [                                   // the menu bar: a list of menus
  { label: 'File', items: ['file.new', 'file.open', { label: 'Open Recent', items: ['recent.1'] }, '-', 'file.save'] },
  { label: 'View', items: ['view.wrap', '-', { heading: 'Zoom' }, 'zoom.90', 'zoom.100'] }
]);
S4.commands.menu('row-menu', ['edit.copy', 'edit.rename', '-', 'edit.delete']);   // a right-click menu
```

```html
<div class="s4-menubar" aria-label="Application" data-menus="app"></div>
<li data-context-menu="row-menu">…</li>                     <!-- the menu is made for you -->
<button class="s4-button" type="button" data-cmd="file.save">Save<kbd class="s4-kbd"></kbd></button>
```

| Command field | What |
|---|---|
| `id` | A stable name (`file.save`). Made up if missing. |
| `label`, `icon`, `group`, `keywords` | Title Case label, icon name, palette group, extra words people type |
| `shortcut` | `mod+s`, `mod+shift+t`, `alt+z`, `f2`. Runs from anywhere (not while typing unless it uses mod); shown the platform's way in menus, buttons and the palette |
| `run(ctx)` | What it does. `ctx.source` is the element, `'keyboard'` or `'palette'`; `ctx.target` is what a right-click menu was opened on |
| `enabled()` | False greys it out everywhere and stops its shortcut |
| `type: 'check' \| 'radio'`, `checked()`, `radio` | A check item, or one of a radio group (`radio` names the group) |
| `palette: false` | Keep it out of the palette (radio items, recent files) |

| Menu item form | What |
|---|---|
| `'file.save'` | A command |
| `'-'` | A divider |
| `{ heading: 'Zoom' }` | A group label |
| `{ label, icon, items: [...] }` | A submenu |
| `{ id, label }` | The same command under another label in this menu |

| Script | |
|---|---|
| `S4.commands.add(list)`, `.remove(id)`, `.get(id)`, `.list()` | The list |
| `S4.commands.run(id, ctx)` | Run one (if enabled) |
| `S4.commands.enabled(id)`, `.checked(id)` | Ask its state |
| `S4.commands.menu(name, items)` / `.menu(name)` | Define or read a named menu: renders into `.s4-menubar[data-menus=name]`, else into `<div class="s4-menu" id=name>` |
| `S4.commands.refresh()` | Ask every `enabled()` and `checked()` again (after your app's state changes; menus also refresh as they open) |
| `S4.commands.native(name)` | The menu as plain data (`{ label, submenu }`, `{ id, label, accelerator, enabled, type, checked }`, `{ type: 'separator' }`) with Electron-style accelerators (`CmdOrCtrl+S`), for a shell's native menu (see `examples/`) |
| `S4.commands.accelerator('mod+s')` | `CmdOrCtrl+S` |
| `[data-cmd="id"]` | Clicking runs it; label, disabled, `aria-pressed` (check commands) and an empty `<kbd class="s4-kbd">` follow the command |
| Events on `document` | `s4-command { command, context }` after one runs; `s4-commands` when the list or a state changed |

**When to use:** every app with more than a handful of actions, and every desktop app. Write the app's actions once
here, then decide where each appears. `S4.palette.register` still works and adds to this list.

**Do**
- Name commands as verbs in Title Case ("Archive Message", "Close Others"); keep one shortcut per command.
- Use the standard shortcuts of the platform's apps: mod+N new, mod+O open, mod+S save, mod+W close, mod+Z undo,
  mod+shift+Z redo, mod+F find, mod+comma settings, F2 rename.
- Make every command reachable on screen too (a button, a menu): shortcuts and the palette are for people who know.

**Don't**
- Don't put the same action in two commands with two labels.
- Don't hide a command (remove it) because it can't run now: disable it, so people learn where it lives.

**Accessibility:** commands render as real menu items (`menuitem`, `menuitemcheckbox`, `menuitemradio`) and buttons;
disabled items keep their place and say so (`aria-disabled`).

**Tokens:** none of its own; menus, the menu bar and the palette draw it.

## Breadcrumbs

Where you are in a hierarchy. Links are pills; the current page is plain text.

```html
<nav class="s4-breadcrumbs" aria-label="Breadcrumb">
  <ol>
    <li><a class="s4-breadcrumb-link" href="/">Home</a></li>
    <li aria-current="page">Electric Co.</li>
  </ol>
</nav>
```

| Attribute | Values | Default |
|---|---|---|
| `aria-current="page"` | on the last `<li>` | — |

**When to use what:** Use on desktop and tablet for deep hierarchies. On phones prefer a back button in the top app bar.

**Do**
- Keep labels short; use the page title as the last item.

**Don't**
- Don't use as primary navigation.
- Don't include the current page as a link.

**Accessibility:** A `<nav>` with a label, an ordered list and `aria-current="page"` on the last item. The separators are decorative.

**Tokens:** surface-container roles, `on-surface`, `on-surface-variant`, shape `full` and `large`, spacing `--s4-space-*`, spring tokens. No outlines (decision 0023).

<a id="pagination"></a>

## Pagination

Move between pages of a long list or table. Circles, filled; the current page is filled inverse.

```html
<nav class="s4-pagination" aria-label="Pagination">
  <a class="s4-page" href="?page=1" aria-label="Previous Page"><span class="s4-icon" data-icon="chevron-left"></span></a>
  <a class="s4-page" href="?page=2" aria-current="page">2</a>
  <a class="s4-page" href="?page=3">3</a>
</nav>
```

| Attribute | Values | Default |
|---|---|---|
| `aria-current` | on the current page | — |
| `aria-disabled="true"` | previous or next at the ends | — |

**When to use what:** Use for long, ordered data that people jump around in. For feeds use load more or infinite scroll.

**Do**
- Show the first, last and the pages around the current one.

**Don't**
- Don't show every page number of a long set.

**Accessibility:** A `<nav>` with a label; icon items need `aria-label`; the current page has `aria-current="page"`.

**Tokens:** surface-container roles, `on-surface`, `on-surface-variant`, shape `full` and `large`, spacing `--s4-space-*`, spring tokens. No outlines (decision 0023).

## Stepper

Progress through a fixed sequence of steps, such as a checkout or setup. Dots joined by a filled track.

```html
<ol class="s4-stepper" aria-label="Setup Progress">
  <li data-state="done"><span class="s4-step-dot"><span class="s4-icon" data-icon="check"></span></span><span class="s4-step-label">Account</span></li>

```

| Attribute | Values | Default |
|---|---|---|
| `data-state` | `done`, `current` (upcoming has none) | upcoming |
| `aria-current="step"` | on the current step | — |

**When to use what:** Use for two to six steps that happen in order. For loose sections use tabs or an accordion.

**Do**
- Name every step; on phones only the current label shows.

**Don't**
- Don't use for more than six steps.
- Don't let the color be the only difference: done steps show a check.

**Accessibility:** An ordered list; the current step has `aria-current="step"`. The labels carry the meaning.

**Tokens:** surface-container roles, `on-surface`, `on-surface-variant`, shape `full` and `large`, spacing `--s4-space-*`, spring tokens. No outlines (decision 0023).

## Card

Holds content and actions about one subject. M3 cards: elevated, filled and outlined, with optional media, body and
actions. Cards are content surfaces: always solid, never glass.

```html

  <div class="s4-card-media"><img src="receipt.jpg" alt=""></div>

  </div>

    <button class="s4-button" data-variant="text" type="button">Details</button>
    <button class="s4-button" type="button">Pay Now</button>
  </div>
</article>

<a class="s4-card" data-variant="outlined" href="/bills/10451">…</a>   <!-- the whole card opens something -->
```

| Attribute / part | Values | Default |
|---|---|---|
| `data-variant` | `elevated` (surface-container-low, level 1), `filled` (surface-container-highest), `outlined` (surface + outline-variant) | `elevated` |
| `.s4-card-media` | image, video or SVG area; takes the card's top corners (bottom corners when last). `--s4-card-media-ratio` sets the aspect ratio | 16 / 9 |
| `.s4-card-body` | 16 padding; `.s4-card-title` (title-medium), `.s4-card-subhead` and `.s4-card-supporting` (body-medium, on-surface-variant) | — |
| `.s4-card-actions` | buttons, end-aligned, 8 apart; pushed to the bottom in a grid of cards | — |
| `a.s4-card`, `button.s4-card` | interactive card: state layer from base; hover raises elevated to level 2, filled and outlined to level 1 | — |
| `disabled` / `aria-disabled="true"` | container at 38%, content on-surface at 38%, outline at 12% | — |

**When to use what:** **elevated** to lift a card off a busy page; **filled** for quiet grouping; **outlined** when cards
sit on a surface of the same color or in dense grids. For a section of settings or a form, use a [pane](#pane) instead.

**Do**
- Make the whole card a link or button when it opens one thing, and keep other buttons out of it.
- Put the main figure (an amount, a count) in tabular figures.
- Keep a card's actions to two, the main one filled or tonal.

**Don't**
- Don't nest cards, or put a card inside a card-colored pane without changing one of the surfaces.
- Don't put buttons or links inside an interactive card (nested interactive content).
- Don't add glass or blur to cards.

**Accessibility:** a static card is an `<article>` labelled by its title. An interactive card is one native `<a>` or
`<button>`, so it is a single tab stop with the M3 focus ring; its text is its accessible name, so keep it short.
Forced-colors mode draws a real border.

**Tokens:** `--s4-shape-card`, `--md-sys-color-surface-container-low` / `-highest`, `--md-sys-color-surface`,
`--md-sys-color-outline-variant`, `--md-sys-elevation-level0`–`2`, `--md-sys-typescale-title-medium-*`,
`--md-sys-typescale-body-medium-*`, `--md-sys-state-*`, `--md-sys-motion-spring-fast-effects`.

## Pane

S4 addition. A solid section of a page: a group of settings, a form, or a block on a dashboard. Title, optional
supporting text, then content.

```html
<section class="s4-pane" aria-labelledby="autopay">
  <h2 class="s4-pane-title" id="autopay">Autopay</h2>
  <p class="s4-pane-supporting">Pay recurring bills from your operating account on the due date.</p>
  …
</section>

<section class="s4-pane" data-color="error" aria-labelledby="danger">
  <h2 class="s4-pane-title" id="danger">Delete Workspace</h2>
  <p class="s4-pane-supporting">This deletes every bill, receipt and vendor. You can't undo this.</p>
  <div class="s4-row"><button class="s4-button" data-color="error" type="button">Delete Workspace</button></div>
</section>
```

| Attribute / part | Values | Default |
|---|---|---|
| `data-color` | `lowest` (surface-container-lowest), `high` (surface-container-high), `error` (danger zone: error-container, on-error-container) | surface-container-low |
| `.s4-pane-title` | title-medium | — |
| `.s4-pane-supporting` | body-medium, on-surface-variant, 4 below the title | — |
| `--s4-pane-padding` | override the padding | 24, or 16 under 600 |

Children are stacked 16 apart. Padding follows the space the pane sits in: 24 from the medium window class up, 16 when
compact. That's a container measurement (`cqi` against the nearest container, such as the app's content area, or the
viewport when there is none), so a pane works with or without a container ancestor. The pane is itself an inline-size
container, so lists, tables and grids inside it can adapt to it.

**When to use what:** a **pane** groups related settings or fields under a heading; a [card](#card) is one item among
many. Use `lowest` or `high` only to separate a pane from a neighbour or a parent of the same color. Use `error` once per
page, last, for destructive settings.

**Do**
- Give every pane a title in Title Case, and use supporting text in sentence case to say what the section is for.
- Use the heading level that fits the page outline (the class sets the look, not the level).

**Don't**
- Don't nest panes of the same color.
- Don't make panes glass; they are content surfaces.
- Don't fill a whole page with `data-color="error"` panes.

**Accessibility:** use `<section aria-labelledby>` so each pane is a named region. The error pane's text uses
on-error-container, which the token build checks at AA. Forced-colors mode draws a real border.

**Tokens:** `--s4-shape-pane`, `--s4-space-4`, `--s4-space-6`, `--s4-breakpoint-medium`,
`--md-sys-color-surface-container-low` / `-lowest` / `-high`, `--md-sys-color-error-container`,
`--md-sys-color-on-error-container`, `--md-sys-typescale-title-medium-*`, `--md-sys-typescale-body-medium-*`.

Group by date or status with subheaders; put the group total in the subheader.

**Do**
- Keep the headline to one line; put detail in supporting text (sentence case).
- Right-align amounts in the trailing slot; they use tabular figures automatically.
- Use `aria-current="page"` for the current item in navigation lists, `aria-selected` only inside a listbox.

**Don't**
- Don't put two interactive controls in one interactive item (a link item with a switch in it).
- Don't mix one-, two- and three-line items in a list without reason; set `data-lines` on the list to even them out.
- Don't show status by color alone; use a [status](#status) pill with a label.

layer and an inner focus ring (so it isn't clipped by a scrolling parent). A `label` item makes the whole row the
checkbox's or switch's label. Listboxes follow the WAI-ARIA listbox pattern. Forced-colors mode outlines the selected item
and segmented items.

**Tokens:** `--s4-size-list-item-one-line` / `-two-line` / `-three-line`, `--s4-shape-list-segment`,
`--s4-shape-list-group`, `--md-sys-color-secondary-container`, `--md-sys-color-on-secondary-container`,

`--md-sys-state-*`.

## Table

S4 addition (M3 has no current data table spec). Compares rows across columns: bills, payments, invoices. Sorting,
row selection, clickable rows, a sticky header, and a stacked layout on phones so nothing scrolls sideways. Tables are
solid content surfaces, never glass.

```html
<div class="s4-table-wrap" data-sticky>
  <table class="s4-table">
    <caption>October Bills</caption>
    <thead><tr>
      <th scope="col" data-check><label class="s4-checkbox"><input type="checkbox" aria-label="Select All Bills"><span class="s4-checkbox-box"></span></label></th>
      <th scope="col" data-primary aria-sort="none"><button type="button" class="s4-table-sort">Vendor<span class="s4-icon" data-icon="chevron-down"></span></button></th>
      <th scope="col">Status</th>
      <th scope="col" class="num" aria-sort="none"><button type="button" class="s4-table-sort">Amount<span class="s4-icon" data-icon="chevron-down"></span></button></th>
    </tr></thead>
    <tbody>
      <tr tabindex="0">
        <td data-check><label class="s4-checkbox"><input type="checkbox" aria-label="Select Iron Mountain INV-10482"><span class="s4-checkbox-box"></span></label></td>
        <td><a href="/bills/10482">Iron Mountain</a></td>
        <td><span class="s4-status" data-tone="tertiary">Due</span></td>
        <td class="num" data-value="1240">$1,240.00</td>
      </tr>
    </tbody>
    <tfoot><tr><th scope="row" colspan="3">Total</th><td class="num">$1,240.00</td></tr></tfoot>
  </table>
</div>
```

| Attribute / part | Values | Default |
|---|---|---|
| `.s4-table-wrap` | surface-container-low, large corners, scrolls sideways if it must; the container the compact layout measures | — |
| `data-sticky` (wrap or table) | header stays at the top while rows scroll inside the wrap; height from `--s4-table-max-height` | header + 8 rows |
| `th`, `td` | header 56 (title-small, on-surface-variant), rows 52 (body-medium), 16 side padding, tabular figures | — |
| `.num` on `th` / `td` | right-aligned (table.js copies it from the header to the column's cells) | start |
| `data-wrap` on `th` / `td` | let a long column wrap (min 192) | no wrap |
| `th[aria-sort]` + `button.s4-table-sort` | click cycles `ascending` → `descending` → `none` (original order); sorts each tbody by `data-value` or text; `s4-change { type: 'sort', column, label, direction }` | — |
| `data-value` on `td` | the sort key: a number for amounts, an ISO date for dates | the text |
| `th[data-check]`, `td[data-check]` | checkbox column; header box selects all (indeterminate for some); checked rows get secondary-container; `s4-change { type: 'select', rows }` | — |
| `tr[tabindex="0"]` | clickable row: state layer, click or Enter fires `s4-select { row }` and follows the row's first link | — |
| `th[data-primary]` | in the stacked layout, that column's cell is the block's headline | — |
| `data-label` on `td` | column name shown in the stacked layout; table.js copies it from the header; `data-label=""` hides it | header text |
| `tfoot` | totals, title-small | — |

**Compact (the wrap under 600):** each row becomes a block: the primary cell as a headline, then one line per cell with
its column name on the left and the value on the right. The header row becomes a toolbar with select-all and the sort
buttons; plain column names are hidden (each cell carries its own). A selectable row's checkbox sits at the block's top
start.

### At scale (round 0056)

Everything below is opt-in; markup without these attributes behaves exactly as above.

### Columns (any table, markup or data)

| Attribute | What |
|---|---|
| `data-resizable` on the table | a grip at the end of each header: drag it (mouse or finger), or Tab to it and use Left / Right (Shift for bigger steps), Home for the narrowest; double-click or Enter fits the column to its content. The grip is a `role="separator"` with `aria-valuenow`. |
| `th[data-pin]`, `th[data-pin="end"]` | the column stays while the table scrolls sideways. Pinned cells are solid (the table's surface, the row's selection or state mixed in) with a tonal edge only while something is under them; never a shadow, never glass. The checkbox and details columns travel with the start pins. |
| `data-key="name"` on the table | widths, order, hidden and pinned columns are kept in this browser under that name |
| `th[data-fill]` | the column that takes the spare width when the columns are narrower than the table (default: the `data-primary` one) |
| `data-column-menu` on a data table | a menu on every column header: Sort Ascending, Sort Descending, Group by (with `th[data-groupable]`), Pin, Fit to Content, Move Left, Move Right, Hide. Never drag-only. With a pointer the button shows on hover or focus; on touch it is always there. |
| `.s4-menu[data-table-columns="#table-id"]` | a Columns menu for that table: a check item per column to show or hide it; Alt and Up / Down move the focused column |

### Data (`S4.table`)

|---|---|

| `data-format` | `number`, `integer`, `currency:EUR`, `percent`, `date` (or a `cell` function) |

Script: `setRows(rows)`, `filter(fn)`, `search(text, fields)`, `sort(field, 'ascending'|'descending'|null)`,
`group(field|null)`, `expand(id, open)`, `update(id, patch)`, `remove(ids)` (returns the removed rows, for Undo),
`selectedRows()`, `clear()`, `.rows`, `.view` (indices of the rows shown), `.selected`. Columns: `S4.tableColumns(table)`:
`width(field, px)`, `fit(field)`, `hide(field, on)`, `move(field, index)`, `pin(field, 'start'|'end'|'')`.
Events on the table: `s4-change` with `type` `view` (`count`, `total`), `sort`, `select` (`rows`, `count`), `edit`
(`field`, `value`, `previous`, `undo`), `update`, `resize`, `columns`; `s4-select { row, data }` when a row opens;
`s4-toggle { id, open }` for details; `s4-row-action`. The [filter](#filter) component drives `filter`, `search` and
`sort` and writes them into the address.

**Rows on screen only.** The body holds the rows in view plus a few either side, between two spacer rows whose height
is the rest of the table, so the scrollbar is the real length from the start and never jumps. Each frame reads the
scroll position once, draws, then measures the new rows together (no reading inside a loop). Measured on the reference
page (10,000 rows, Chromium in this sandbox): first draw of the data 25 ms, sorting 10,000 rows 43 ms, about 20 rows in
the page at any time (under 830 elements in the table while scrolling from top to bottom), a smooth scroll at 60 frames a
second with the median frame at 16.7 ms. Every drawn row carries `aria-rowindex`; the table carries `aria-rowcount`, so a
screen reader says "row 4,812 of 5,002".

**Keyboard (data tables):** the table is one Tab stop (the current row). Up and Down move a row, Page Up and Page Down a
screen, Home and End (or Ctrl with them) the first and last; Right and Left move through the row's controls and cells
that edit; Enter opens the row (its `data-page-open` link) or edits a cell; Space picks the row, Shift with Up or Down
extends, Ctrl+A picks every row shown, Escape clears; `+` and `-` open and close details; Shift+F10 opens the row menu.
On a group row, Enter or Right and Left open and close the group.

**Phones:** the stacked layout stays the default for data tables too (rows are measured as they are drawn): headline,
then one line per value, details under the checkbox, the row menu in the top corner, the sort buttons in one row that
scrolls sideways. Use `data-layout="scroll"` on the wrap instead when people compare numbers across a row (a price grid,
a timetable, a register of loans): the real table stays, scrolls sideways, and its pinned first column keeps every row
named.

**States:** inside a `.s4-states`, `setRows` shows `ready` (or `empty` for no rows), and a filter that leaves nothing
shows a `no-results` part when there is one (a Clear Filters button there). `data-table-skeleton="8"` on the loading part
draws skeleton rows shaped like the table's columns.

**Print:** the table takes the sheet's width, nothing is pinned, the checkbox, details and menu columns are left out.
A data table prints the rows that are drawn: print from a report view of the rows that matter.

**When to use what:** a table when people compare values across columns or sort; a [list](#list) when each item is
read on its own. Keep tables to the columns that matter; put the rest on the detail page.

**Do**
- Right-align amounts and counts (`.num`), and give them `data-value` so they sort as numbers.
- Make one column `data-primary` (usually the name) so stacked rows read well on phones.
- Show status with a [status](#status) pill (a label and a tone).
- Label every row checkbox with what it selects ("Select Staples INV-10451").

**Don't**
- Don't make a row clickable and also fill it with buttons; one action per row, or a trailing icon button with
  `tabindex` off the row.
- Don't rely on sideways scrolling on phones; the stacked layout is there so you don't need it.
- Don't sort columns where order means nothing (descriptions).

**Selecting rows (decision 0063, amends 0044 inside tables):** an empty box in a resting row is a quiet dot, half the
size, in the same 3:1 control color; it grows into the full box when its row is hovered or holds the focus, and every
box shows in full while anything is selected. The Select All box in the head always shows in full. Cells keep wrapping
(0058); they never truncate.

**Accessibility:** a real `<table>` with `<caption>`, `scope`d headers and `aria-sort`, so screen readers announce the
column and sort order. Sorting is a native button in the header. Clickable rows are focusable with an inner focus ring and
open on Enter; the link inside stays the accessible way in. Forced-colors mode draws the wrap's border and outlines
checked rows.

**Tokens:** `--s4-size-table-header` (and with the scale additions `--s4-shape-text-field` for cells that edit, `surface-container`, `surface-container-high`, `surface-container-highest`, `outline`, `primary` for the active grip, `--s4-motion-bend`, Reveal for details), `--s4-size-table-row`, `--s4-size-touch-target`, `--md-sys-shape-corner-large`,
`--md-sys-color-surface-container-low`, `--md-sys-color-secondary-container`, `--md-sys-color-on-secondary-container`,
`--md-sys-color-outline-variant`, `--md-sys-typescale-title-small-*`, `-body-medium-*`, `-title-medium-*`,
`-label-large-*`, `--md-sys-state-*`, `--md-sys-motion-spring-spatial` (rows slide into their sorted place),
`--md-sys-motion-spring-fast-spatial` (sort arrow).

<a id="stat"></a>

## Stat

S4 addition. One number people check: revenue, steps, open tickets, balance. A label, a big emphasized number and an
optional change or note. The loudest thing on a dashboard should be the numbers, not the boxes around them.

```html
<section class="s4-pane" aria-label="Key Numbers">
  <div class="s4-stat-row">
    <div class="s4-stat">
      <span class="s4-stat-label">Revenue</span>
      <span class="s4-stat-value">$48.2K</span>
      <span class="s4-stat-meta"><span class="s4-status" data-tone="primary">+8%</span>vs. September</span>
    </div>
    <div class="s4-stat"><span class="s4-stat-label">Open Invoices</span><span class="s4-stat-value">14</span><span class="s4-stat-meta">3 overdue</span></div>
  </div>
</section>
```

| Part / attribute | Values | Default |
|---|---|---|
| `.s4-stat-label` | label-large, on-surface-variant, Title Case | — |
| `.s4-stat-value` | display-small, emphasized weight, tabular figures | — |
| `.s4-stat-meta` | body-small, on-surface-variant; holds a `.s4-status` for the change | — |
| `data-size="small"` | value on headline-small, for dense dashboards | — |
| `data-size="hero"` | value on display-medium: the one number the screen exists for (cash on hand, a calculator's result). One a screen; the layout pass lets it outrank the page title | — |
| `.s4-stat-row` | as many stats per row as fit, at least two on a phone; `--s4-stat-min` sets the column floor | 160 |

**Do**
- Put several stats in one pane with an `.s4-stat-row`, not one pane per number.
- Round to what people need ("$48.2K", "11 mo"); show the exact value in the detail.
- Show the change as a status with a word or a sign ("+12%"), never color alone.

**Don't**
- Don't use a stat for something people don't track over time; use a [description list](#description-list).
- Don't put more than four or five stats in a row.

**Accessibility:** plain text in reading order (label, value, change). A pane holding stats gets an `aria-label`.

**Tokens:** `--md-sys-typescale-display-small-*`, `--md-sys-typescale-emphasized-display-small-weight`,
`--md-sys-typescale-label-large-*`, `--md-sys-typescale-body-small-*`, `--md-sys-color-on-surface(-variant)`.

<a id="meter"></a>

## Meter

S4 addition (decision 0063). How much of something there is, against a whole, a limit or a target: a label, the value
in words, a filled track. Five templates drew one by hand (Tally's runway, Relay's response clock, Pressroom's word
count, Moorings' fleet day, Larkline's storage); this is that element once.

```html
<div class="s4-meter" data-value="7.2" data-max="12">
  <div class="s4-meter-head">
    <span class="s4-meter-label">Runway</span>
    <span class="s4-meter-value"><strong>7.2</strong> of 12 months; safe line at 6</span>
  </div>
  <div class="s4-meter-track">
    <i class="s4-meter-fill"></i>
    <i class="s4-meter-mark" data-at="6" aria-hidden="true"></i>
  </div>
  <div class="s4-meter-scale" aria-hidden="true"><span>Dec</span><span>Nov ’27</span></div>
</div>

<!-- a share of a whole -->
<div class="s4-meter" data-segmented data-max="8" data-size="l">
  <div class="s4-meter-head"><span class="s4-meter-label">On This Phone</span><span class="s4-meter-value"><strong>3.4 GB</strong> of 8 GB</span></div>
  <div class="s4-meter-track">
    <i class="s4-meter-fill" data-value="1.9" data-category="1"></i>
    <i class="s4-meter-fill" data-value="0.8" data-category="2"></i>
  </div>
  <ul class="s4-meter-legend"><li data-category="1">Recordings <b>1.9 GB</b></li><li data-category="2">Guidebooks <b>0.8 GB</b></li><li data-track>Free <b>4.6 GB</b></li></ul>
</div>
```

| Part / attribute | Values | Default |
|---|---|---|
| `.s4-meter` `data-value`, `data-min`, `data-max` | the reading, in the app's own units | 0, 0, 100 |
| `data-state` | `on-track` (success), `near` (warning), `over` (error; the value text turns error too) | the accent |
| `data-segmented` | a share of a whole: fills follow one another with a hairline seam | — |
| `data-steps` | counted units (months, seats, days): the track is cut into that many steps | — |
| `data-size` | `s` 4, default 8, `l` 16, `xl` 32 (fills inset, for ranges on a day) | 8 |
| `data-ink="current"` | on a colored surface: the fill takes the text color, the track a quarter of it | — |
| `.s4-meter-head` | `.s4-meter-label` (label-large, emphasized) and `.s4-meter-value` (body-medium; a `<strong>` inside is the number, title-medium) | — |
| `.s4-meter-fill` `data-value`, `data-from`, `data-category="1…6"`, `data-tone="quiet"` | one fill per series or segment; `data-from` places a range (a booking from 09:00); `quiet` is a second series of the same kind (other people's bookings) | the meter's own value |
| `.s4-meter-mark` `data-at` | a target, a limit or "now": a short line across the track | — |
| `.s4-meter-scale` | ends or ticks under the track, label-small | — |
| `.s4-meter-legend` > `li` | `data-category`, `data-tone="quiet"` or `data-track` (what is left); the amount in `<b>` | — |

`meter.js` turns the values into the fills (`--value`, `--from`, `--at` from 0 to 100 on the track) and gives the meter
`role="meter"` with `aria-valuemin`, `-max`, `-now` and `-valuetext` (the written value), labelled by its label. Change
any `data-value`, `data-max`, `data-from` or `data-at` later and it redraws.

**When to use what**
- A meter is a **reading**: storage used, time left on a promise, words against a target, months of runway.
- A task the app is doing (uploading, syncing) is [progress](#progress). One share shown big is a [ring](#ring).
- Something the person sets is a [slider](#slider). Values compared across many rows or over time are a [chart](#chart).

**Do**
- Say the value in words beside the track ("8 min left of 1 hour", "3.4 GB of 8 GB"); the track only shows it.
- One series takes the accent; segments take category colors named in a legend (decision 0060).
- Use `data-state` for a limit that matters, and say it in the words too ("20 min late").

**Don't**
- Don't animate a meter: it is a reading, it changes in place.
- Don't use more than six segments; group the rest as "Other".
- Don't restyle the class for a brand: the brand comes through the dials (accent, corners, faces).

**Accessibility:** `role="meter"` with the written value as `aria-valuetext`; marks and scales are decoration
(`aria-hidden`) and their meaning is in the value text; state is never color alone. Forced colors draw the track border
and the fills in CanvasText.

**Tokens:** `--md-sys-color-primary`, `--md-sys-color-surface-container-highest`, `--md-sys-color-outline`,
`--s4-color-success|warning`, `--md-sys-color-error`, `--s4-category-1…6`, `--s4-shape-chip`, `--s4-space-hairline`,
`--md-sys-shape-corner-extra-small`, `--md-sys-typescale-label-large|body-medium|title-medium|label-small|body-small-*`.

## Board

S4 addition (decision 0063). Lanes of cards that move from stage to stage: stories, tickets, a sales pipeline, a week of
work. Pressroom and Moorings both rebuilt lane counts, limits and the add-in-place footer by hand; this is that once.

```html
<div class="s4-board" aria-label="Tonight’s Stories">
  <section class="s4-lane" data-limit="3" aria-labelledby="l-editing">
    <header class="s4-lane-head"><h2 class="s4-lane-title" id="l-editing">Editing</h2><span class="s4-lane-count"></span></header>
    <ul class="s4-lane-items" data-reorder data-reorder-group="tonight" aria-label="Editing">
      <li class="my-card">…</li>
    </ul>
    <footer class="s4-lane-foot">
      <button class="s4-button" data-variant="text" data-size="s" type="button" data-lane-add="Working headline">
        <span class="s4-icon" data-icon="add"></span>Add Story</button>
    </footer>
  </section>
  …
</div>
```

| Part / attribute | What | Default |
|---|---|---|
| `.s4-board` | lanes side by side, each at least `--s4-lane-min` wide; on a board narrower than 600 each lane is 85% of it and the board snaps lane to lane | 13rem |
| `.s4-lane` `data-limit` | a lane; past its limit the count turns the error tone and the lane gets `data-over` | — |
| `.s4-lane-head` | `.s4-lane-title` (a heading, title-small) and `.s4-lane-count` (filled in by board.js: "4", or "4 / 3" with a limit) | — |
| `.s4-lane-items` | the cards; add `data-reorder` and a shared `data-reorder-group` ([direct](#direct)) so they drag between lanes | — |
| `.s4-lane-foot` with `[data-lane-add="placeholder"]` | the add-in-place footer: a draft (field, Cancel, Add) opens where the button was; Add fires `s4-lane-add { value, lane, list }` | — |

**Keyboard:** with focus on anything in a card, Alt+Up and Alt+Down move it in its lane, Alt+Left and Alt+Right to the
lane before or after (mirrored right to left). The app hears `s4-reorder`, as for a drag, so Undo works the same way.
Each move is announced ("Rents rise fastest, Ready, position 1 of 3"). Dragging is [direct](#direct): a mouse drags,
a finger holds then drags. Neither is the only way: give a card's page or menu a "Move To" action as well.

**A page with a board** starts with its rail collapsed (the lanes need the width); an app can still say otherwise with
`data-rail` or the rail's own `data-expand`.

**When to use what**
- A board: things that move through stages, where seeing every stage at once matters.
- A [list](#list) grouped by status when people mostly read, not move; a [table](#table) for many fields per item.
- A [month](#month) or [timeline](#timeline) when the stages are dates.

**Do**
- Keep a card short: a title, one or two facts, who has it. Open the rest as a page (decision 0050).
- Name lanes with nouns or stages in Title Case; put a limit only where the team works to one.
- Act at once on a move and offer Undo in a snackbar.

**Don't**
- Don't open a dialog to add a card; it is typed in place. Don't put the cursor in the field for the person (0049).
- Don't make dragging the only way to move a card.

**Accessibility:** lanes are sections named by their heading; each list is named; the count's name is in words
("4 cards, limit 3, over the limit"); moves are announced in a polite live region.

**Tokens:** `--md-sys-color-surface-container-low|highest`, `--md-sys-color-error-container`, `--md-sys-shape-corner-large|medium`,
`--s4-shape-chip`, `--md-sys-typescale-title-small|label-medium-*`, `--s4-space-*`.

## Description List

S4 addition. Labelled values on a detail screen: an order's date, total and status; a contact's email and phone.

```html
<dl class="s4-dl">
  <div class="s4-dl-row"><dt>Vendor</dt><dd>Iron Mountain</dd></div>
  <div class="s4-dl-row"><dt>Amount</dt><dd>$1,240.00</dd></div>
  <div class="s4-dl-row"><dt>Status</dt><dd><span class="s4-status" data-tone="error">Overdue</span></dd></div>
</dl>
<dl class="s4-dl" data-layout="stacked">…</dl>
```

| Part / attribute | Values | Default |
|---|---|---|
| `.s4-dl-row` | one label and its value, at least 48 tall, a divider between rows | — |
| `dt` | body-medium, on-surface-variant, Title Case | — |
| `dd` | body-large, end-aligned, tabular figures; may hold a status, link or icon button | — |
| `data-layout="stacked"` | label above value (long values, narrow panes) | side by side, wraps when tight |

**Do**
- Put it in a [pane](#pane) or the detail pane of a [list-detail layout](#layout).
- Keep labels short ("Due Date", not "The date this bill is due").

**Don't**
- Don't use it for things people compare across many items; that's a [table](#table).
- Don't make rows clickable; use a [list](#list) for things that open.

**Accessibility:** a real `<dl>`; the `div` wrappers are allowed by HTML. Forced colors draw the dividers.

**Tokens:** `--md-sys-color-outline-variant`, `--md-sys-typescale-body-medium-*`, `--md-sys-typescale-body-large-*`,
`--s4-size-touch-target`, `--s4-size-divider`.

<a id="divider"></a>

## Divider

A thin line that groups content (M3). 1px outline-variant.

```html
<hr class="s4-divider">
<hr class="s4-divider" data-inset="start">
<hr class="s4-divider" data-inset="middle">
<hr class="s4-divider" data-orientation="vertical">
```

| Attribute | Values | Default |
|---|---|---|
| `data-inset` | `start` (16 at the start), `middle` (16 at both ends); on a vertical divider, 8 at the top (and bottom) | full width |
| `data-orientation` | `vertical`: a line between items in a flex or grid row; stretches to the row's height (24 minimum) | horizontal |
| `--s4-divider-inset` | the inset length, e.g. `calc(var(--s4-space-4) * 2 + var(--s4-space-10))` (72) to line up with list text after an avatar | 16 |

**When to use what:** prefer space and surface color to separate things. Use a full-width divider between groups, an
inset divider between items of a list, and a vertical one between figures in a row. For lines between every list item,
use the list's `data-dividers` instead.

**Do**
- Use a real `<hr>` when it separates sections of content; it's announced as a separator.

**Don't**
- Don't stack a divider against a surface edge or another divider.
- Don't color dividers; they are always outline-variant.

**Accessibility:** `<hr>` has the `separator` role. A purely decorative vertical divider in a toolbar can take
`aria-hidden="true"`. The line is a real border, so it survives forced-colors mode.

**Tokens:** `--s4-size-divider`, `--md-sys-color-outline-variant`, `--s4-space-2`, `--s4-space-4`, `--s4-space-6`.

## Avatar

A person or thing as a circle: initials, a photo or an icon. Moved out of the list so it works anywhere.

```html
<span class="s4-avatar">MC</span>
<span class="s4-avatar" data-size="l" data-status="online" aria-label="Maya Chen, online">MC</span>
<div class="s4-avatar-group"><span class="s4-avatar">MC</span><span class="s4-avatar" data-more>+4</span></div>
```

| Attribute | Values | Default |
|---|---|---|
| `data-size` | `xs` 24, `s` 32, `m` 40, `l` 56, `xl` 80 | `m` |
| `data-tone` | `secondary`, `tertiary`, `neutral` | primary container |
| `data-status` | `online`, `busy`, `away` | none |
| `data-more` | the "+3" overflow avatar of a group | — |

**When to use what:** Initials when there is no photo; an icon for a thing or a generic user. Use the group for collaborators.

**Do**
- Give a photo an `alt` with the name; give a status avatar an `aria-label` that says the status.

**Don't**
- Don't rely on the status dot alone: say the status in text somewhere near.
- Don't put more than five avatars in a group; add the +N avatar.

**Accessibility:** Initials are text; photos need `alt`. The status dot is decorative, so put the status in `aria-label`.

**Tokens:** surface-container roles, `on-surface`, `on-surface-variant`, shape `full` and `large`, spacing `--s4-space-*`, spring tokens. No outlines (decision 0023).

<a id="accordion"></a>

## Accordion

Sections that open and close. Built on native `<details>`, so it needs no JavaScript.

```html
<div class="s4-accordion">
  <details class="s4-accordion-item" name="faq" open>
    <summary>What is autopay?<span class="s4-icon" data-icon="chevron-down"></span></summary>
    <div class="s4-accordion-body">Pays the bill on its due date.</div>
  </details>
</div>
```

| Attribute | Values | Default |
|---|---|---|
| `name` on every `<details>` | a shared string: only one stays open | independent |
| `open` | starts expanded | closed |

**When to use what:** Use for FAQs, settings groups and long forms split into parts. For switching between views use tabs.

**Do**
- Keep titles short and in Title Case; body text in sentences.
- Put the most important item first and open.

**Don't**
- Don't nest accordions.
- Don't hide content people need to compare side by side.

**Accessibility:** `<summary>` is a native disclosure button: Space and Enter toggle it and screen readers announce expanded or collapsed. The chevron is decorative.

**Tokens:** surface-container roles, `on-surface`, `on-surface-variant`, shape `full` and `large`, spacing `--s4-space-*`, spring tokens. No outlines (decision 0023).

<a id="expand"></a>

## Expand in place

Content that opens right where you asked for it and pushes the rest of the page down. The first rung of the placement
ladder (decision 0047): reach for this before a menu, a panel or a dialog.

```html
<div class="s4-row"><button class="s4-button" type="button" data-expand="reply">Reply</button></div>
<div class="s4-expand" id="reply" data-variant="inset" hidden>
  <form class="s4-expand-body">
    <div class="s4-text-field"><textarea id="r" rows="3"></textarea><label for="r">Reply To Maya Chen</label></div>
    <div class="s4-expand-actions">
      <button class="s4-button" data-variant="text" type="button" data-expand-close="cancel">Cancel</button>
      <button class="s4-button" type="submit">Send</button>
    </div>
  </form>
</div>
```

Inline confirm (the button turns into the question):

```html
<button class="s4-button" data-variant="tonal" type="button" data-confirm="rm">Remove Card</button>
<span class="s4-confirm" id="rm" hidden>
  <span class="s4-confirm-text">Remove this card?</span>
  <button class="s4-button" data-variant="text" data-size="s" type="button" data-confirm-close="">Keep</button>
  <button class="s4-button" data-color="error" data-size="s" type="button" data-confirm-close="remove">Remove</button>
</span>
```

| Attribute | On | Values | Default |
|---|---|---|---|
| `data-expand="id"` | any button | opens or closes that expand; gets `aria-expanded` and `aria-controls` | |
| `data-variant` | `.s4-expand` | `inset` (a filled, rounded container for a composer or small form) | none: plain, part of the page |
| `data-group` | `.s4-expand` | a shared name: opening one closes the others (Reply and Forward) | independent |
| `data-autofocus` | a button inside | that button takes focus when it opens (never a field) | the expand itself |
| `data-expand-close="value"` | a button inside | closes it; `value` arrives in `s4-close` | |
| `data-confirm="id"` / `data-confirm-close="value"` | buttons | swap a button (or its `[data-confirm-row]`) for a `.s4-confirm` and back | |

Script: `S4.expand.open(id, { from })`, `S4.expand.close(id, value)`, `S4.expand.toggle(id)`. Events: `s4-open`,
`s4-close { value }` (value is `""` for Escape). The expand is a direct child of the container it opens in (a pane, a
`.s4-stack`); it cancels the container's gap itself, so nothing jumps.

**When to use what (the placement ladder):**
1. **In place:** the thing itself changes (a switch, an inline confirm, text you edit where it is).
2. **Expand:** a reply, a short form, details or options open under what you touched. This component.
3. **Menu** (anchored glass): a short list of choices or a picker hanging from its button.
4. **Pane:** a detail or inspector beside the content, when the layout has room.
5. **Floating panel:** a longer task that has no place in the page (a new message, filters for the whole view).
6. **Dialog:** only when the app cannot continue without an answer: an action that cannot be undone, or leaving with
   unsaved work. Prefer doing the thing and offering Undo in a snackbar.

**Do**
- Put the expand directly under the control that opens it, inside the same pane.
- Keep it short: a few fields and one row of actions. Longer tasks are a pane or a panel.
- After the action, close it and confirm with a snackbar (with Undo where you can).

**Don't**
- Don't open a dialog for a reply, a comment, a rename, an add form or a filter.
- Don't open an expand far from its button, or more than one at a time in the same place (use `data-group`).
- Don't use the inline confirm for something serious that cannot be undone: that is what a dialog is for.

**Accessibility:** the opener carries `aria-expanded` and `aria-controls`. Opening moves focus to the expand itself,
never into a field (decision 0049: no keyboard pops up until the person taps the field); Tab goes to its first
control. Escape closes and returns focus to the opener. The page is never inert.
The inline confirm moves focus to its first answer and back to the button.

**Motion:** Reveal (the box grows on the calm reveal spring, its content follows); the confirm uses Switch.

**Tokens:** `surface-container-high`, `on-surface`, shape `large`, spacing `--s4-space-*`, `--s4-expand-gap` (public
knob: the gap of the container it sits in, when that is not 16).

<a id="states"></a>

## States

Every list, table and pane has a designed **loading, empty, error and offline** state, so an app never shows a blank
box. One container holds a part per state; the script shows the right one.

```html
<div class="s4-states" data-state="loading">
  <div data-when="loading" data-rows="4"></div>
  <div data-when="offline" class="s4-banner" role="status">…You’re offline…</div>
  <ul data-when="ready offline" class="s4-list">…</ul>
  <div data-when="empty" class="s4-empty">…All Caught Up…</div>
  <div data-when="error" class="s4-empty">…Couldn’t Load… <button class="s4-button" data-variant="tonal" data-retry>Try Again</button></div>
</div>
```

| Attribute | On | What |
|---|---|---|
| `data-state` | `.s4-states` | `loading`, `ready`, `empty`, `error`, `offline` (or any name of your own) |
| `data-when="a b"` | a direct child | the state or states this part belongs to |
| `data-rows="4"` | the loading part, left empty | draws that many skeleton rows |
| `data-retry` | a button | fires `s4-retry` on the container |
| `data-offline="auto"` | `.s4-states` | shows the offline parts while the device is offline |

Script: `S4.states.set(el, 'ready')`, `S4.states.get(el)`, and `S4.states.load(el, promise)`: loading while the
promise runs, then `ready`, `empty` when it resolves to `[]` or `{ empty: true }`, `error` when it rejects.
Event: `s4-state { state, previous }`.

**When to use what**
- **Loading:** skeleton rows shaped like the content (never a spinner on an empty page). Under about 300ms show nothing.
- **Empty:** say what will appear here and offer the action that fills it.
- **Error:** say what failed in plain words and offer Try Again. Never a dialog for an error you can retry.
- **Offline:** keep showing what was loaded, with a banner that says changes are kept and sent later.

**Do** keep the container the same size across states where you can, so the page does not jump.
**Don't** blank the content while refreshing something already shown: keep it and show a small progress bar.

**Accessibility:** `aria-busy` while loading; the container is a polite live region, so the new state is announced.
**Motion:** State (the arriving part fades in). **Tokens:** skeleton, empty state and banner tokens; `--s4-space-*`.

<a id="direct"></a>

## Direct manipulation

Move things with your hand instead of through a menu: **reorder** by dragging, **swipe** a row for its actions,
**select several** and act on all of them. All three work with mouse, finger and keyboard.

```html
<!-- reorder -->
<ul class="s4-list" data-reorder>
  <li><div class="s4-list-item"><button class="s4-drag-handle" type="button" aria-label="Move Budget draft"></button>…</div></li>
</ul>

<!-- swipe -->
<li data-swipe>
  <div class="s4-list-item">…</div>
  <div class="s4-swipe-actions"><button class="s4-icon-button" data-variant="tonal" aria-label="Archive" data-swipe-primary>…</button></div>
</li>

<!-- select several -->
<div class="s4-selection-bar" id="bar" hidden>
  <button class="s4-icon-button" aria-label="Clear Selection" data-selection-clear>…</button>
  <span class="s4-selection-count" data-selection-count></span>
  <button class="s4-icon-button" aria-label="Archive Selected">…</button>
</div>
<ul class="s4-list" data-selectable data-selection-bar="#bar">…</ul>
```

| Attribute | What |
|---|---|
| `data-reorder` (`="horizontal"` for a row of things) | its children can be reordered; fires `s4-reorder { item, from, to, fromList, toList }` |
| `data-reorder-group="name"` | lists that share it pass items between them (board columns) |
| `.s4-drag-handle` | the grip (a button). With one, only the grip drags; without, the whole item drags (a short hold on touch) |
| `data-reorder-fixed` | a child that stays where it is |
| `data-swipe` + `.s4-swipe-actions` | a row whose actions are uncovered by dragging it sideways; `data-swipe-primary` runs on a long swipe |
| `data-selectable` + `data-selection-bar="#id"` | rows can be picked; the bar shows the count and the actions |
| `data-select-toggle` | a part of a row (its picture) that starts selecting when tapped |

Script: `S4.reorder.move(item, toIndex, toList)`, `S4.swipe.open(row)` / `close(row)`, `S4.selection.items(el)`,
`clear(el)`, `all(el)`; event `s4-selection { items, count }`.

How selecting starts: hold a row on a touch screen, Ctrl/⌘-click or Shift-click with a mouse, or tap a
`data-select-toggle`. After that a tap adds or removes a row instead of opening it. Escape ends it. Put the
`.s4-selection-bar` inside the `.s4-top-app-bar` and it takes the bar's place while anything is selected.

**When to use what**
- Reorder: anything whose order is the person's own (priorities, playlists, columns, steps, a board).
- Swipe: the one or two most common actions on a row, on phones. They must also be in the row's menu or on its page.
- Select several: lists where people clean up in bulk (mail, files, tasks).

**Do** give every handle an `aria-label` that names its item; act at once and offer Undo.
**Don't** make dragging the only way to do something; don't swipe to do something that cannot be undone.

**Accessibility:** a handle is a button: Space picks up, Arrow keys move (Left and Right cross between grouped
lists), Space drops, Escape puts it back, and each step is announced. Swipe actions are real buttons reachable with
Tab. Picked rows carry `aria-checked`.
**Motion:** Morph calm for rows making room and settling; nothing animates while your finger is down.
**Tokens:** `secondary-container`, `primary`, `surface-container-highest`, `--s4-size-touch-target`, `--s4-space-*`.

## Filters and Views

One pattern for narrowing a collection (records, orders, specimens, tickets): a **search** that filters as you type,
the **filters in force** as chips (each removable, and Clear All), **Add Filter**, a **filters panel** with every facet
and what each choice would give, a **sort** control and **saved views** (named sets of filters, search and sort) that
can be saved, updated, renamed and deleted with Undo. The state is in the address, so a view can be linked.

```html
<div class="s4-filter" id="records-filter" data-for="#records" data-key="records" data-url aria-label="Filter records">
  <div class="s4-filter-views" aria-label="Saved Views"></div>
  <div class="s4-filter-bar">
    <div class="s4-search" role="search">…<input class="s4-search-input" type="search" aria-label="Search records">…</div>
    <button class="s4-button" data-variant="tonal" type="button" data-filter-add data-menu="add-filter">Add Filter</button>
    <div class="s4-menu" id="add-filter" aria-label="Add a filter"></div>
    <button class="s4-button" data-variant="tonal" type="button" data-filter-panel data-sheet="filters">All Filters<span class="s4-badge" hidden></span></button>
    <button class="s4-button" data-variant="tonal" type="button" data-filter-sort data-menu="sort"><span class="s4-icon" data-icon="sort"></span><span class="s4-filter-sort-label">Sort</span></button>
    <div class="s4-menu" id="sort" aria-label="Sort"></div>
    <button class="s4-icon-button" type="button" data-filter-views data-menu="view-options" aria-label="View Options">…</button>
    <div class="s4-menu" id="view-options" data-align="end" aria-label="View options"></div>
  </div>
  <div class="s4-filter-active" aria-label="Active Filters" hidden></div>
  <p class="s4-filter-count"></p>
</div>
<dialog class="s4-side-sheet" id="filters" data-modeless aria-labelledby="filters-h">
  <div class="s4-sheet-header"><h2 class="s4-sheet-title" id="filters-h">Filters</h2><button class="s4-icon-button" data-close aria-label="Close Filters">…</button></div>
  <div class="s4-sheet-content"><div class="s4-filter-facets"></div></div>
  <div class="s4-sheet-actions"><button class="s4-button" type="button" data-filter-done>Show Records</button></div>
</dialog>
```

```js
const filter = S4.filter(document.getElementById('records-filter'), {
  noun: 'record', nouns: 'records',
  facets: [
    { field: 'family', label: 'Family', type: 'choice', icon: 'tag' },          // checkboxes with counts
    { field: 'collector', label: 'Collector', type: 'tags' },                   // many values: a tag input with suggestions
    { field: 'year', label: 'Collected', type: 'range', min: 1800, max: 2026, grouping: false }   // two number fields
  ],
  views: [{ id: 'all', name: 'All Records' }, { id: 'on-loan', name: 'On Loan', state: { f: { status: ['On Loan'] } } }]
});
```

| Part / attribute | What |
|---|---|
| `data-for="#table"` | the [data table](#table) it narrows (`S4.table`); or pass `{ table }`, or `{ rows, onChange(state) }` for anything else |
| `data-key` | saved views and the chosen view are kept in this browser under that name |
| `data-url` | the state is written to the address query and read back on load: `?q=owl&family=Strigidae|Corvidae&year=1900..1950&sort=year:descending&view=on-loan`. It uses `replaceState` and keeps the hash, so `S4.pages` links (`#view/page/id`) still work |
| `.s4-filter-views` | the views as single-select filter chips; a dot on the chosen one says it was changed since |
| `[data-filter-add]` + its menu | Add Filter: one item per facet; choosing one opens the panel at that facet |
| `[data-filter-panel]` (`data-sheet`) | All Filters, with a badge counting the filters in force |
| `[data-filter-sort]` + its menu | the sortable columns and the direction (follows the table's own header sort) |
| `[data-filter-views]` + its menu | Save as New View, Update, Rename (in place), Delete (with Undo) |
| `.s4-filter-active` | the filters in force as input chips (Delete or Backspace on a chip's remove button works), and Clear All |
| `.s4-filter-count` | “1,204 of 5,000 records”: changes at once, announced politely when typing pauses |
| `.s4-filter-facets` in a `data-modeless` panel | every facet: choices with counts (what you would get with every other filter kept), a tag input for long lists, a range |
| `[data-filter-done]` | the panel's Show button: closes it (on a phone the panel covers the list); there is nothing to apply |

Script: `S4.filter(el, options)` returns the controller: `.state` (`{ q, f, sort }`), `.clear()` (with Undo),
`.useView(id)`, `.views`. Event: `s4-change { state, count, total, view }` on the element.

**When to use what**
- A search alone when people look for one thing by name; the full bar when they narrow by several properties.
- Choice facets for a handful of values (status, type); a tag input for long lists (people, places); a range for numbers
  and years. Five or six facets at most in the bar's Add Filter; the panel can hold more.
- Views for the questions people ask every week (“On Loan”, “Needs Conservation”). Not for one-off searches.
- Chips are right here because views and filters narrow a collection and there can be many (decision 0059); a button
  group is for one value that changes how the same thing is shown, and tabs are for swapping what is on the screen.

**Do**
- Keep the count next to the results; show the no-results state (`.s4-states` with a `no-results` part) with Clear Filters.
- Name views after the question they answer, in Title Case.

**Don't**
- Don't add an Apply button: filters act at once (decision 0054).
- Don't hide the filters in force behind the panel; the chips are how people see why something is missing.
- Don't focus the search when anything opens (decision 0049); the person taps it.

**Accessibility:** the bar is a `role="search"` field and real buttons; the views and the filters in force are labelled
groups; each chip's remove button names the filter (“Remove Family Strigidae”) and focus moves to the next chip when one
goes; facets are sections headed by their name, choices are real checkboxes with their count; the count is a polite
status that waits for typing to pause.
**Motion:** Reveal for renaming a view in place; Follow for the menus; Pop for the panel; State elsewhere.
**Tokens:** chip, search, list and floating panel tokens; label-large for the count and option counts, title-small for
facet titles; `--s4-space-*`.

## Tree View

Nested things you open and close: folders and files, chapters and scenes, regions and sites. In a desktop sidebar, in a
phone's file browser, in a pane.

```html
<ul class="s4-tree" aria-label="Files" aria-multiselectable="true" data-item-menu="file-menu">
  <li class="s4-tree-item" aria-expanded="true">
    <div class="s4-tree-row"><span class="s4-icon" data-icon="folder"></span><span class="s4-tree-label">Quests</span>
      <span class="s4-tree-trailing"><span class="s4-tree-count">412</span></span></div>
    <ul role="group">
      <li class="s4-tree-item"><div class="s4-tree-row"><span class="s4-icon" data-icon="document"></span><span class="s4-tree-label">dialogue.json</span></div></li>
    </ul>
  </li>
  <li class="s4-tree-item" aria-expanded="false" data-lazy><div class="s4-tree-row">…</div></li>
</ul>
```

| Part / attribute | What |
|---|---|
| `.s4-tree` | The tree (`role="tree"`); give it an `aria-label` |
| `.s4-tree-item` + `.s4-tree-row` | An item and its row; a folder has `aria-expanded` and a `ul[role="group"]` |
| `.s4-tree-label`, `.s4-tree-trailing`, `.s4-tree-count`, `.s4-badge` | Name, end slot, a quiet count, an attention badge |
| `aria-selected="true"` | Selected (filled, `secondary-container`) |
| `aria-multiselectable="true"` | Several can be selected |
| `data-lazy` on a folder | Its children load when it first opens (`S4.tree.load`) |
| `data-item-menu="menu-id"` | Every item gets that right-click menu (`menu.contextTarget` is the item) |
| `data-open-on-click` | A single click on a folder row opens it too (a sidebar of groups) |
| `data-no-drag` | No dragging rows |
| `--s4-tree-guides` | The guide line color (`transparent` drops them) |

| Script | |
|---|---|
| `S4.tree.render(tree, nodes)` | Build from data: `{ label, icon, count, badge, id, open, selected, children: [] | lazy: true }` |
| `S4.tree.load(tree, fn)` | `fn(item)` returns a Promise of nodes; a loading row shows meanwhile, an error row offers Retry |
| `.select(item, { add, range })`, `.selected(tree)`, `.open(item, on)`, `.focus(item)`, `.reveal(item)` | Selection, opening, focus |
| `.rename(item)` | Start renaming (F2 does it) |
| `.cut(items)`, `.paste(folder)` | Move without dragging |
| Events on the tree | `s4-change { items, item }`, `s4-select { item }` (chosen: Enter or double-click), `s4-toggle { item, open }`, `s4-rename { item, value, old }`, `s4-move { items, target }` (both cancelable) |

**Keys:** Up and Down move, Right opens or goes to the first child, Left closes or goes to the parent, Home and End,
a letter jumps by name, `*` opens every sibling, Enter chooses (on a Mac it renames, as in the Finder), F2 renames.
Several: Shift with the arrows or a click selects a range, Ctrl or ⌘ with a click adds one, Ctrl or ⌘ with the arrows
moves without selecting and Space adds, mod+A selects all. mod+X then mod+V on a folder moves; Escape cancels.
Shift+F10 or the menu key opens the item's menu.

**Moving:** drag rows onto a folder with a mouse or pen (the folder fills); never drag-only: cut and paste, and the
item's menu, do the same. A finger scrolls the tree and long-presses for the menu.

**Rename** is the one time the tree puts the cursor in a field: you asked to type a name (F2, Enter on a Mac, or a
Rename command), the same reasoning as the palette opened by a key (decision 0049). It never happens on its own.

**Look:** rows are small list rows: touch size by default (48) and 28 in compact density; hover is its own box that
leans in from where the pointer came (decision 0044); corners follow the dial. Each level steps in by
`--s4-size-tree-indent` (20, compact 14) and past the fourth level by half, so deep paths fit a narrow sidebar; a faint
guide line runs down each open folder. Labels wrap, never cut. Opening is Reveal and the chevron turns (Bend). In a
window that is not in front, selected rows turn neutral.

**When to use:** a hierarchy people browse and act on. For one level, use a [list](#list); for two short levels, a
list with subheaders or the rail's groups.

**Do:** put counts at the end, quietly; give folders and items different icons. **Don't:** nest deeper than people can
follow without a breadcrumb; don't make a click on a file both select and open in a desktop app (Enter or a
double-click opens).

**Accessibility:** WAI-ARIA tree: roles, `aria-level`, `aria-expanded`, `aria-selected`, one tab stop with roving focus;
the focused row shows the ring; loading folders are `aria-busy`. Forced colors: the selection is Highlight.

**Tokens:** `--s4-size-tree-row`, `--s4-size-tree-indent`, `--s4-shape-control`, `--md-sys-color-secondary-container`,
`--md-sys-color-outline-variant` (guides), label-large type, `--s4-motion-bend`, Reveal.

## Charts

A small set of chart styles drawn from the tokens, with the reading aids built in.

```html
<figure class="s4-chart" data-type="column" data-labels="Jun,Jul,Aug" data-values="820,640,910" data-format="currency:USD" data-name="Spending">
  <figcaption class="s4-chart-title">Spending By Month</figcaption>
</figure>

<figure class="s4-chart" data-type="line" data-labels="Jun,Jul,Aug"
        data-series='[{"name":"Income","values":[5200,5200,5600]},{"name":"Spending","values":[3820,3640,3910]}]'>…</figure>
```

| Attribute | Values |
|---|---|
| `data-type` | `column` (default), `bar`, `line`, `area`, `donut`, `spark` |
| `data-labels` | comma-separated category names |
| `data-values` / `data-name` | one series and what it is called |
| `data-series` | JSON: `[{ "name": "…", "values": […] }]`, six series at most |
| `data-format` | `number` (default), `currency:USD`, `percent` |
| `data-total-label` | the word under a donut's total |
| `data-no-table` | drops the Table button (only when the numbers are shown elsewhere on the page) |

Script: `S4.chart(el, { labels, series })` draws or redraws. Charts redraw when their box changes size.

**Which chart**
| The data's job | Use |
|---|---|
| Amounts over time, a few periods | `column` |
| A trend over many points | `line`, or `area` for one series |
| Ranking things with long names | `bar` |
| Parts of one whole, five at most | `donut` |
| Which way a stat is going | `spark` beside the number |
| One number | not a chart: a [stat](#stat) |

**What every chart gets:** round axis ticks, hairline gridlines, thin marks with rounded data ends, a legend when
there are two or more series (none for one: the title names it), one value label on what matters, a tooltip on hover,
tap or arrow keys, and a **Table** button with the same numbers as rows.

**Color:** one series wears the accent (`primary`), so the chart follows the app. Several wear `--s4-chart-1 … 6` in
that fixed order: a set checked for color-blind separation on Orion's light and dark surfaces. Text never wears a
series color.

**Do** title the chart with what it shows, in Title Case; give money and percent a `data-format`.
**Don't** use two different y-scales in one chart (make two charts); don't use more than six series (group the rest
as "Other"); don't use a donut for more than five parts; don't use the status colors for series.

**Accessibility:** the SVG is an image with a spoken summary; it takes focus and the arrow keys walk its points,
announcing each; the Table button gives the full data.
**Tokens:** `primary`, `--s4-chart-1…6`, `outline-variant`, `on-surface`, `on-surface-variant`, `inverse-surface`,
label type scale. **Motion:** State (marks dim on hover).

## Ring

S4 addition (decision 0053). One share of a whole, with what it means written in the middle: degree progress, a daily
goal, storage used. The big sibling of circular progress and drawn the same way: a thick round-capped arc, a gap, then
the track. Use progress for "something is working"; use a ring for "this is how far you are".

```html
<div class="s4-ring" data-value="0.36" aria-label="Degree Progress">
  <span class="s4-ring-value">36%</span>
  <span class="s4-ring-label">Complete</span>
</div>
```

| Part / attribute | Values | Default |
|---|---|---|
| `data-value` | 0 to 1; changing it later animates the arc (Ink) | 0 |
| `data-size` | `s` (72, value only), default (112), `l` (160) | default |
| `data-ink="current"` | on a colored surface: the arc takes the text color, the track a quarter of it | — |
| `.s4-ring-value` | the number, emphasized, tabular | — |
| `.s4-ring-label` | one or two words under it | — |
| `--s4-ring-size` | any size | 112 |

`ring.js` draws the SVG and sets `role="progressbar"`, `aria-valuenow` and `aria-valuetext` (the written value).
Always give it an `aria-label`.

**Do**
- Write the value in the middle; a ring with nothing in it is a circular progress.
- One ring per screen region. Several values side by side are stats or a chart.

**Don't**
- Don't put a marker dot, a second arc or an icon on the ring.
- Don't use it for something still loading (that is progress).

## Milestones

S4 addition (decision 0053). A road made of steps, with a marker where you are: courses toward a degree, chapters of a
book, payments on a loan. One pill per step, 4dp apart; done steps are filled, the current one is filled as far as you
are and carries the marker (an upright pill, the M3 Expressive slider handle). A stepper says which page of a task you
are on; milestones say how far along a long road you are.

```html
<div class="s4-row" style="justify-content:space-between"><span class="s4-label-large">Road To Graduation</span><span class="s4-body-small">Goal Jun 30</span></div>
<ol class="s4-milestones" aria-label="8 courses, 3 done">
  <li data-state="done" data-label="Composition"></li>
  <li data-state="current" data-value="0.45" data-label="Accounting"></li>
  <li data-label="Statistics"></li>
</ol>
```

| Part / attribute | Values | Default |
|---|---|---|
| `li[data-state]` | `done`, `current`, none (still ahead) | none |
| `li[data-value]` | on the current step: how far through it, 0 to 1 | 0 |
| `li[data-label]` | the step's name, read out and shown as a tooltip ("Accounting, you are here") | — |
| `data-here`, `data-done` | the words added to the current and finished steps | "you are here", "done" |
| `data-ink="current"` | on a colored surface | — |

**Do**
- Say the same thing in words next to it ("3 of 8 courses done").
- Keep it to about 20 steps on a phone; group beyond that.

**Don't**
- Don't label every step under the road; the row above and the line below carry the words.
- Don't make steps tappable here; the list of the same things is where you act.

## Timeline

S4 addition (decision 0053). When each thing happens along one shared span of time: courses in a term, phases of a
project, bookings in a week. Every row has the same track; its bar sits where the thing starts and ends.

```html
<ol class="s4-timeline" data-now="0.34" aria-label="Course Timeline">
  <li data-start="0" data-end="0.2" data-state="done">
    <span class="s4-timeline-label">Composition</span><span class="s4-timeline-meta">Oct 1 → Oct 19</span>
  </li>
  <li data-start="0.2" data-end="0.46" data-state="current">…</li>
  <li data-start="0.46" data-end="0.7">…</li>
</ol>
```

| Part / attribute | Values | Default |
|---|---|---|
| `li[data-start]`, `li[data-end]` | 0 to 1 of the whole span | 0, 1 |
| `li[data-state]` | `done` (quiet), `current` (accent), none (upcoming) | none |
| `data-now` (on the list) | 0 to 1: draws the "now" marker on every track | — |
| `.s4-timeline-label` | the name (one line, ellipsis) | — |
| `.s4-timeline-meta` | the dates, always written out | — |

Inside a surface that is not a pane, set `--_gap` on the list to that surface's color (the marker's cut-out).

**Do**
- Always write the dates; the bar is the picture, the text is the fact.
- Order rows by start.

**Don't**
- Don't use it for one value (that is progress) or for amounts (that is a bar chart).

<a id="month"></a>

## Month

S4 addition (decision 0053). A month you read, with marks on its days. The date picker is for choosing a date; this is
for seeing a plan: what is due, when you are busy, the day that must not be missed.

```html
<div class="s4-month" data-month="2026-11" data-legend aria-label="Schedule"
     data-marks='{"2026-11-18":"dot","2026-11-26":"band","2026-11-27":"band","2026-11-30":"flag"}'
     data-mark-labels='{"dot":"Course Due","band":"Busy","flag":"Deadline"}'></div>
```

Four marks, all filled (nothing outlined, nothing hatched):

| Mark | Looks like | Means |
|---|---|---|
| today | the accent circle | set by itself (or `data-today`) |
| `dot` | a small accent dot under the number | something happens that day |
| `band` | a tonal band; days in a row join into one capsule | a stretch of time: busy, away, booked |
| `flag` | a filled error-tone circle | the day that must not be missed |

| Attribute | Values | Default |
|---|---|---|
| `data-month` | `YYYY-MM` | this month |
| `data-marks` | JSON, date to mark(s), space separated | — |
| `data-mark-labels` | JSON, mark to words (read out, and the key) | — |
| `data-legend` | draws the key under the grid | — |
| `data-week-start` | `0` Sunday, `1` Monday | 0 |
| `data-min`, `data-max` | `YYYY-MM`: how far you can page | — |

Tapping a day presses it and fires `s4-select` (`{ date, marks }`); show what is on that day right below the month
(placement ladder: in place first). Paging fires `s4-month`. `S4.month.set(el, { month, marks, today })`,
`S4.month.select(el, date)`. Arrow keys move between days.

**Do**
- Keep the same marks meaning the same thing across the app, and show the key.
- Pair it with a list of the same things (a calendar is never the only way to read a plan).

**Don't**
- Don't add a fifth mark; if a day needs more, say it in the line that opens when it is tapped.
- Don't use it to pick a date for a field (that is the date picker).

### Kicker and figure (decision 0063)

Two pieces for editorial pages, usable inside or outside `.s4-prose`:

```html
<p class="s4-kicker">Total Solar Eclipse · 2 August 2027</p>

<figure class="s4-figure">
  <img src="karnak.jpg" alt="The Temple of Karnak at noon">
  <figcaption>Totality over Karnak at 13:07. Photo: Amara Nwosu.</figcaption>
</figure>
```

| Class | Look |
|---|---|
| `.s4-kicker` | The short label above an editorial title, or a post's section. **Do**
- Use real heading levels in order; the look follows the level.
- Use a `data-width="reading"` page so the measure stays comfortable on desktop.

**Don't**
- Don't put app UI (lists of records, forms) inside prose; those are components.

**Accessibility:** links are underlined (not color alone); text meets AA in every mode.

## Code

A block of code people read or copy: a snippet in docs, a config file, a command, a change. It carries its file name
and language, line numbers, marked lines, a **Wrap** toggle and **Copy**. A diff shows added and removed lines with
their sign. Inline code and keys sit in running text. Code is solid content, never glass.

```html
<figure class="s4-code" data-lang="js" data-lines data-mark="6-8">
  <figcaption class="s4-code-head"><span class="s4-code-file">specimens/table.js</span></figcaption>
  <pre><code>const table = S4.table(el);
table.setRows(rows);</code></pre>
</figure>

<figure class="s4-code" data-variant="diff" data-lines>…<pre><code>- old line
+ new line</code></pre></figure>

<p>Fill it with <code class="s4-code-inline">setRows(rows)</code>; search with <span class="s4-keys"><kbd class="s4-kbd">Ctrl</kbd><kbd class="s4-kbd">K</kbd></span>.</p>
```

| Attribute / part | What | Default |
|---|---|---|
| `.s4-code` on a `<figure>` | the block: `surface-container` (one step up inside a card, pane or panel), large corners | — |
| `.s4-code-head` (`<figcaption>`) + `.s4-code-file` | the head: file name in the mono face; the language label and the buttons are added | no head: the buttons sit in the top corner |
| `data-lang` | `js`, `ts`, `json`, `css`, `html`, `xml`, `py`, `sh` (and long names) are colored by the built-in tokenizer; any other name only labels | no colors |
| `data-lines` | line numbers in a gutter that stays while the code scrolls sideways; never copied | none |
| `data-mark="3-4,9"` | marked lines: a step-up fill and an accent bar at the start | none |
| `data-wrap` | long lines wrap; the Wrap button toggles it (`aria-pressed`) | scroll sideways |
| `data-variant="diff"` | lines starting `+` are `<ins>` on the success container, `-` are `<del>` on the error container, `@@` and file lines are quiet; the sign keeps its own column | — |
| `data-plain` | keep the code as written, no colors | — |
| `data-no-actions` | no Wrap or Copy (a one-line example) | buttons |
| `<span class="s4-syntax-…">` inside the code | pre-tokenised code is kept: `keyword`, `string`, `number`, `comment`, `function`, `type`, `property`, `punctuation` | — |
| `.s4-code-inline` | inline code in running text | — |
| `.s4-kbd`, `.s4-keys` | one key (from the desktop component), a combination of keys | — |

Script: `S4.code.render(fig)` after you change the code; `S4.code.text(fig)` gives it as text; `S4.code.tokenize(text, lang)`
gives `[[role, text], …]`. Events: `s4-copy { text, ok }`, `s4-change { wrap }`.

**Colors** are tokens, `--s4-syntax-keyword | string | number | comment | function | type | property`: fixed hues, like the
status colors, so code reads the same with any accent. Each is proven at 4.5:1 on every surface in light, dark and both
high-contrast modes (6:1 there) by `npm run check:tokens`, and on the surfaces of every tinted scheme by
`npm run check:accent`. Comments are italic as well as gray. Plain code and punctuation are `on-surface` and
`on-surface-variant`.

**The tokenizer** is about 3 KB and covers the languages people paste most. It is a set of patterns, not a parser: it
is right for snippets and config, not for a code editor. For any other language, tokenise on the server (Shiki,
Pygments, highlight.js) and map its classes to the `s4-syntax-*` names; the block keeps them.

**When to use what**
- A block for anything people copy or read as code (more than a few words, or several lines).
- `.s4-code-inline` for a name, a value or a short command inside a sentence.
- `.s4-kbd` for keys; never for code.
- A diff for a change someone reviews; not for showing a whole new file.

**Do**
- Name the file in the head when there is one; it is what people search for.
- Mark the two or three lines the text talks about, and say in the text why.
- Keep examples short and real (names and values from the app).

**Don't**
- Don't use a code block for output people only glance at (a log line in a list is plain text).
- Don't add line numbers to a two-line snippet.
- Don't color code by hand outside the tokens; don't put a code block on glass.

**Accessibility:** the `<pre>` is a focusable, named region (from the file name), so the keyboard can scroll long
lines and a screen reader can find it; line numbers and the gutter are generated content and never read or copied;
added and removed lines are `<ins>` and `<del>` with their sign, never color alone; Copy says "Copied" in a polite live
region. Forced colors: the block, inline code and marked lines get a system border.
**Motion:** none (Copy's check is an icon swap). **Tokens:** `--s4-syntax-*`, `surface-container`,
`surface-container-high`, `surface-container-highest`, `primary` (the mark bar), `--s4-color-success-container`,
`error-container`, `--md-ref-typeface-mono`, body-medium size, body-large line height, label-large.

### Behaviour (`site.js`)

- The header gets `data-scrolled` (glass) once content is under it.
- The menu button opens the menu panel with Pop; Escape, a tap outside, a link, or a window growing past 840 closes it.
  Focus moves to the current link when it opens and back to the button on Escape. It is a disclosure, not a modal.
- `[data-period]` groups swap prices; `.s4-compare` groups pick the column; `.s4-toc` marks the section being read
  with `aria-current="location"`.

### When to use what

- **A product or project home page:** `landing.html`. One split hero, proof, how it works, the rest, one accent band.
- **A studio, portfolio or about page:** `site.html` (stacked hero, work as figures, services, contact).
- **Plans:** `pricing.html`. **Writing:** `blog.html` for the index, `article.html` for each post. **Help:** `docs.html`.

- One `h1` per page (`.s4-hero-title`), section titles as `h2`, then `h3` inside.
- Use the accent once a page: the featured plan, or the call-to-action band, or one bento cell.
- Make pictures from real screens (`.s4-frame` with real components inside, `inert`, `role="img"` and a label) or set
  covers in type; give every img and video `width`, `height` and `loading="lazy"` below the first screen.
- Start-align sections; center only a short hero or a closing band.

**Don't**
- Don't center everything, and don't make a page of three identical cards.
- Don't use gradients, shadows, outlines or glass on sections; glass is only for the header and the phone menu.
- Don't put reading in a dialog or a lightbox: a post or a case study is a page (decision 0050).
- Don't leave a hole in a grid: bento spans add up to 12, grids use `data-columns`.

`aria-expanded` and `aria-controls`; the current page is `aria-current="page"`, the section being read

## Forms

Forms that behave. Layout classes plus a script that gets the timing right.

```html
<form class="s4-form">
  <div class="s4-form-row">
    <div class="s4-text-field"><input id="f" required data-msg-required="Enter your first name."><label for="f">First Name</label></div>
    <div class="s4-text-field"><input id="l" required><label for="l">Last Name</label></div>
  </div>
  <div class="s4-text-field"><input id="e" type="email" required data-msg-type="That doesn’t look like an email address."><label for="e">Email</label></div>
  <div class="s4-form-actions"><span class="s4-form-status"></span><button class="s4-button" type="submit">Create Account</button></div>
</form>
```

| Rule | What happens |
|---|---|
| Errors on leaving a field | never while typing; typing in a field with an error clears it the moment it is right |
| Inline success | a field that was wrong and is now right shows a small check by its label |
| Submit with problems | every problem is shown, the first is scrolled into view, nothing is sent; `s4-invalid { fields }` |
| Submit when fine | `s4-submit { values }` (call `preventDefault()` to handle it yourself) |
| `data-autosave` on the form | `s4-save { values, done(ok), wait() }` after a change settles; `.s4-form-status` reads "Saving…" then "Saved" |
| Messages | `data-msg-required`, `-type`, `-pattern`, `-min`, `-max`, `-length`, or `data-msg` on the control |

Script: `S4.form.validate(form)`, `S4.form.values(form)`, `S4.form.saved(form, 'Saved')`.

**When to use what**
- A form you send (sign up, checkout, a new record): a submit button, errors on blur.
- Settings and anything edited in place: `data-autosave`, no Save button, a quiet "Saved".
- Something reversible (remove, archive, move): do it and offer **Undo** in a snackbar. Keep "Are you sure?" for what
  is serious and cannot be undone (the placement ladder, decision 0047).

**Do** write messages that say how to fix it ("Enter the email you signed up with."), in sentence case.
**Don't** disable the submit button until the form is valid (people cannot tell why); don't validate on every key.

**Accessibility:** errors set `aria-invalid` and are tied to the field with `aria-describedby`; the cursor is never
moved into a field for you (decision 0049); the saved mark is a status region.
**Tokens:** `--s4-color-success`, label type scale, `--s4-space-*`. **Motion:** State.

<a id="text-field"></a>

## Text Field

Lets people enter and edit text. A filled box with medium corners (decisions 0009, 0023, 0024): no outline, surface-container-highest fill and the label
above the box, always visible. Icons, prefix / suffix, supporting text, counter, error state, select and auto-growing
textarea. 48dp tall, tabular figures. There is one look: `data-variant` is ignored.

```html
<div class="s4-text-field">
  <span class="s4-text-field-affix" data-prefix>$</span>
  <input id="amount" inputmode="decimal" value="1,240.00">
  <label for="amount">Amount</label>
  <span class="s4-text-field-affix" data-suffix>USD</span>
  <div class="s4-text-field-supporting">Includes tax.</div>
</div>

<div class="s4-text-field">
  <span class="s4-icon" data-icon="search"></span>
  <input id="q" type="search">
  <label for="q">Search Bills</label>
  <button class="s4-icon-button" type="button" aria-label="Clear Search"><span class="s4-icon" data-icon="close"></span></button>
</div>

<div class="s4-text-field" data-error="Enter an amount above $0.00."> … </div>
<div class="s4-text-field"><select id="cat"><option value=""></option><option>Utilities</option></select><label for="cat">Category</label></div>
<div class="s4-text-field" data-counter><textarea id="notes" rows="1" maxlength="120"></textarea><label for="notes">Notes</label></div>
```

| Part / attribute | Meaning |
|---|---|
| `<input id>` / `<select>` / `<textarea>` + `<label for>` | the control and its label (label medium, above the box) |
| `.s4-icon` / `.s4-icon-button` before the control | leading icon (12dp from the edge) |
| `.s4-icon` / `.s4-icon-button` after the control | trailing icon or action |
| `.s4-text-field-affix[data-prefix]` / `[data-suffix]` | "$", "kg": always shown |
| `.s4-text-field-supporting` | helper text, sentence case |
| `data-counter` | "length / maxlength" at the end of the supporting line |
| `data-error="Message"` (or `aria-invalid="true"` on the control) | error color; the message replaces the helper text |
| `disabled` on the control | M3 disabled: 4% container, 38% content |

**Behaviour** (`text-field.js`): adds `placeholder=" "` to text controls; adds a chevron to selects and opens the picker
when the field is clicked; grows textareas; links supporting text with `aria-describedby`; keeps `aria-invalid` and the
error message in sync with `data-error`. A select's glass picker follows the select: change its options (add, remove,
disable) or set `select.value` / `selectedIndex` from script and the button and the list redraw; no `change` event needed.

**Do**
- Title Case labels ("Due Date"), sentence-case helper and error text that says how to fix it.
- Use `inputmode="decimal"` and a `$` prefix for amounts; the field already uses tabular figures.

**Don't**
- Don't use the placeholder as the label.
- Don't put helper text and an error in two places; `data-error` replaces the helper text.

**Accessibility:** native controls with real `<label for>`; supporting text is `aria-describedby`; errors set
`aria-invalid`; focus (issues 62, 64): from the keyboard the focus ring (3dp, focus ring color, outside the box); after
a tap or click a quiet accent hairline inside the box (core.js sets `data-s4-focus="pointer|key"` on `<html>`), never
both; the whole container is a click target;
forced-colors mode draws real borders.

**Tokens:** `--s4-size-text-field`, `--s4-shape-text-field`, `--md-sys-color-surface-container-highest`,
`--md-sys-typescale-body-large/body-small-*`, `--s4-motion-spring-fast-spatial-calm` (label), `--md-sys-state-*`.

<a id="combobox"></a>

## Combobox

A text field that suggests as you type (WAI-ARIA combobox with a listbox popup). The list opens in glass right under
the field, or above it when there is no room (over a phone's keyboard it measures the visible part of the screen). The
part of each option that matches is bold. The cursor never leaves the field: the active option is
`aria-activedescendant`. One value.

```html
<div class="s4-text-field s4-combobox">
  <label for="country">Country</label>
  <input id="country">
  <input type="hidden" name="country">                       <!-- optional: gets the chosen option's value -->
  <template>
    <optgroup label="Europe">
      <option value="pt" data-supporting="Lisbon">Portugal</option>
      <option value="es" data-supporting="Madrid">Spain</option>
    </optgroup>
  </template>
  <div class="s4-text-field-supporting">Where the account is registered.</div>
</div>
```

| Attribute / API | What |
|---|---|
| `<template>` of `<option>` / `<optgroup>` | The options. `value`, `disabled`, `data-supporting` (a second line), `data-icon` (a leading icon). |
| `data-free` | The options are suggestions; any text is the value. Without it only an option may be chosen: other text is invalid ("Choose one of the options in the list.", or `data-msg-option`), shown when you leave the field. |
| `<input type="hidden">` after the text input | Receives the chosen option's `value` (with `data-free`, the text). |
| `S4.combobox.source(field, fn)` | Asynchronous options: `fn(query, signal)` returns a Promise of `[{ value, label, group, supporting, icon }]` (or strings). Shows Searching…, the results, “No matches” or an error with Try Again. |
| `data-min-chars` | Characters before an asynchronous search starts (default 1). |
| `data-loading-text`, `data-empty-text` (`{q}` is the query), `data-error-text` | The notes in the list. |
| `S4.combobox.set(field, value)` | Choose a value from script (no events). |
| Events | `input` and `change` on the input, `s4-change { value, label, item }` on the field, `s4-open` / `s4-close`. |

The trailing button is **Show Options** (a chevron) while the field is empty and **Clear** once it has text: one button,
so focus never falls off the page when it changes. A tap on the field opens a fixed list; an asynchronous one opens
when you type.

**Keyboard:** Down and Up open the list and move through it (wrapping), Alt+Down opens it without moving, Enter
chooses, Escape closes the list (a second Escape clears the field), Tab leaves. With an error showing, Down tries again.

**When to use:** more than about seven options, or options from a server (people, places, products), or a value that may
be new (`data-free`). **Not:** up to about seven fixed options (a select, which opens the same glass list, or radios);
several values (the [tag input](#tag-input)); a command (the [palette](#palette)); filtering a page (the [search](#search) bar).

**Do** name the options as people know them and add a supporting line when two could be confused. Put the list's
`<template>` in the order you want it shown; matches that start with the text come first. **Don't** put actions in the
list, open it on page load or move the cursor into the field from script (decision 0049). Don't add a trailing icon to
the field: that place belongs to the Show Options / Clear button.

**Placement:** an anchored list (Follow), never a dialog. Inside a dialog the list stays inside the dialog's top layer.

**Accessibility:** `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls`,
`aria-activedescendant` on the input; the list is a `listbox` labelled by the field's label, groups are `group`s named by
their heading, each option has `aria-selected`. The number of results, Searching… and errors are announced politely.
Inside `.s4-form` it is validated like any field (on blur, `aria-invalid`, the message in the supporting text).

**Tokens:** `--s4-shape-menu`, `--s4-shape-menu-item` (follows the corner dial), `--s4-focus-ring-*`, glass tokens,
`--md-sys-color-secondary-container`. **Motion:** Follow for the list, Bend for the chevron.

<a id="tag-input"></a>

## Tag Input

Several values in one field (a multi-select). Each chosen value is an input chip inside the Quiet Box and the cursor
sits after them. The box grows a line at a time and keeps its corners; the label and supporting text never move.
Suggestions open in the same glass list as the [combobox](#combobox).

```html
<div class="s4-text-field s4-tag-input" data-name="labels" data-values="Taxes, Household" data-max="5" data-create>
  <label for="labels">Labels</label>
  <input id="labels">
  <template><option>Taxes</option><option>Household</option><option>Urgent</option></template>
  <div class="s4-text-field-supporting">Up to five.</div>
</div>
```

| Attribute / API | What |
|---|---|
| `<template>` of `<option>` | Suggestions (`value`, `data-supporting`). Already chosen ones are left out of the list. |
| `data-create` | People may add their own values: Enter or a comma adds what was typed, and “Add “…”” is offered first in the list. Without it (and with suggestions) only suggestions can be added. A field with no suggestions always creates. |
| `data-values` | The starting values, comma-separated. |
| `data-name` | Each value is a hidden input with this name inside its chip (FormData gives an array). |
| `data-max` | A counter (“2 / 5”) under the field; past it nothing is added and the reason is announced. |
| `data-noun` | What the values are, for announcements (“Removed Taxes.”, “You can add up to 5 labels.”). |
| `required` on the input | At least one value; the message (`data-msg-required`) shows on blur, inside `.s4-form` or not. |
| `S4.tagInput.source(field, fn)` | Asynchronous suggestions: `fn(query)` returns a Promise of `[{ value, label, supporting }]`. |
| `S4.tagInput.values(field)`, `S4.tagInput.set(field, list)` | Read or replace the values from script. |
| Events | `s4-change { values }` on the field, a cancelable `s4-remove { chip, value }` on a chip before it goes, `change` on the input. |

**Typing:** a comma, a semicolon or Enter adds; pasting “Rent, Car; Gifts” (commas, semicolons, tabs or new lines) adds
each; duplicates are ignored (case and accents too). **Removing:** each chip's remove button (also Delete or Backspace on
it), or Backspace in the empty field for the last chip. A removed chip closes up sideways (Reveal); focus moves to the
next chip's remove button.

**When to use:** labels, recipients, skills, filters someone types: several values from a long or open set. **Not:** a
few fixed options (filter chips or checkboxes, where every option is visible); one value (the combobox).

**Do** keep values short (a chip never truncates a word it can show; very long ones end in an ellipsis). Say the limit in
the supporting text. **Don't** add a leading or trailing icon to the field (the chips and the cursor fill the box), or
use it for free text with commas in it.

**Accessibility:** the chips are a list (“Chosen labels”) before the input; each remove button is named “Remove Taxes”
and is in the Tab order. Additions, removals, duplicates and the limit are announced politely. The input is a
`combobox` with a multi-select `listbox` when there are suggestions. The cursor is never put in the field by script
(decision 0049).

**Focus:** the field's own marks: a quiet hairline inside the box after a tap, the focus ring outside it from the
keyboard (repeated in `tag-input.css` for the input that sits one level deeper).

**Tokens:** `--s4-shape-text-field` (the box), `--s4-shape-chip`, `--md-sys-color-secondary-container` (the chips, so they
stand off the field in both color modes and on glass), `--s4-size-chip`. **Motion:** Reveal (a chip leaving), Follow
(the list).

<a id="number-field"></a>

## Number Field

A number with minus and plus in one Quiet Box (WAI-ARIA spinbutton). Same height, label and supporting text as every
field; the value sits in the middle in tabular figures, next to its unit. Tap to step, hold to keep stepping (faster
after a moment), or type.

```html
<div class="s4-text-field s4-number-field">
  <label for="guests">Guests</label>
  <input id="guests" value="2" data-min="1" data-max="12">
  <span class="s4-text-field-affix" data-suffix>people</span>
  <div class="s4-text-field-supporting">Up to twelve.</div>
</div>

<!-- in a list or cart row -->
<span class="s4-text-field s4-number-field" data-inline><input aria-label="Quantity of Oat Milk" value="2" data-min="0" data-max="20"></span>
```

| Attribute (on the input) | What |
|---|---|
| `data-min`, `data-max` (or `min`, `max`) | The limits. The steppers stop at them (and are disabled there); typing past them is an error on blur. |
| `data-step` (default 1) | How far a stepper or an arrow key moves; typed values snap to it on blur. Its decimals set how the value is shown. |
| `data-page-step` | Page Up / Page Down (default ten steps). |
| `data-decimals` | Always show this many decimals (money: 2). |
| `data-no-grouping` | No thousands separator (years, codes). |
| `data-msg-min`, `data-msg-max`, `data-msg-number` | Messages; the defaults say the range (“Enter 1 to 8.”). |
| `data-inline` (on the field) | The small quantity stepper (40 high, buttons 32, no label above: give the input an `aria-label`). |
| Affixes | `.s4-text-field-affix[data-prefix]` / `[data-suffix]` for the unit ($, kg, people). |
| Script | `S4.numberField.value(field)` (a number or null), `S4.numberField.set(field, n)`; `s4-change { value }` on the field, `input` and `change` on the input. |

The input is `type="text"` with `role="spinbutton"` (a browser's number input has its own spinners, eats scroll and
cannot show “1,240”); the script sets `inputmode` (numeric, decimal, or the full keyboard when negatives are allowed,
since a phone's number pad has no minus sign), `aria-valuenow`, `aria-valuemin`, `aria-valuemax` and `aria-valuetext`
(“$4.50”, “2 people”). Values are read and written in the page's language (`lang`): “1.234,5” in Portuguese.

**Keyboard:** Up and Down step, Page Up and Page Down by the page step, Home and End go to the minimum and maximum, Enter
tidies what was typed. The minus and plus buttons are out of the Tab order (the field takes the keys) and never move
the cursor into the field, so tapping them on a phone does not raise the keyboard.

**When to use:** small counts and amounts people nudge (guests, quantity, retries, a tip). **Not:** long numbers people
type but never nudge (an amount of money in a form, a card number: a plain text field with `inputmode`); a value on a
continuous scale (a slider); a rating (the [rating](#rating)).

**Do** put the unit beside the value, not in the label; keep limits real and say them in the supporting text. **Don't**
use the inline stepper outside a row that names what it counts.

**Accessibility:** spinbutton semantics on the input; the buttons are named “Increase Guests” / “Decrease Guests”; when
a button changes the value without the field focused, the new value is announced politely. Errors follow `.s4-form`
(on blur, `aria-invalid`, the message in the supporting text).

**Tokens:** the text field's, `--s4-size-icon-button`, `--s4-size-button-small` (inline buttons).
**Motion:** State only (the buttons' press layer).

<a id="code-field"></a>

## One-Time Code

Four to eight boxes that act as one field, for a verification code, a PIN or a backup code. Underneath is a single real
input, so a phone offers the code from the message it just received (`autocomplete="one-time-code"`), a paste fills
every box at once, and a screen reader hears one field with one label. The boxes only draw its characters.

```html
<div class="s4-text-field s4-code-field" data-length="6" data-group="3">
  <label for="otp">Verification Code</label>
  <input id="otp">
  <div class="s4-text-field-supporting">We sent it to •••• 4021.</div>
</div>
```

| Attribute / API | What |
|---|---|
| `data-length` | Number of boxes, 4 to 8 (default 6). |
| `data-group` | A wider gap after every so many boxes (3 for six, 4 for eight). |
| `data-type="alphanumeric"` | Letters and digits (upper-cased); otherwise digits only. |
| `data-autosubmit` | Submit the form when the last box fills. |
| `data-error="…"` / `data-success` on the field | The result of the app's check: the label and message turn the error color (boxes keep their fill), or the message turns the success color with a check. Typing again clears either. |
| Events | `s4-complete { value }` on the field when the last box fills; `input` on the input. |
| Script | `S4.codeField.clear(field)`. |

The script sets `inputmode` (numeric, or text for letters), `autocomplete="one-time-code"` (keep `autocomplete="off"` for a
PIN), `pattern` and a message for an unfinished code (“Enter all 6 digits.”). Spaces and dashes in a paste are dropped;
anything past the last box is ignored. The caret always sits after the last character.

**Focus:** the box that takes the next character carries the field's marks: a quiet hairline after a tap, the focus
ring from the keyboard. **It never takes focus by itself** (decision 0049), not even on a page that is only this field:
the person taps it, or the phone's suggestion fills it.

**When to use:** a short code sent to the person, a PIN. **Not:** passwords (a text field with the password helpers);
long codes people copy (a plain text field); anything people would want to see while typing in the middle.

**Do** say where the code was sent and how long it lasts; offer “Send a New Code” beside it, not a timer that moves.
**Don't** clear the boxes after a wrong code (people fix one digit), or check while they are still typing.

**Accessibility:** one input with the field's label and supporting text (`aria-describedby`); the boxes are
`aria-hidden`. Errors follow the text field and `.s4-form` (on blur, `aria-invalid`).

**Tokens:** `--s4-shape-text-field` (each box), the field's fill and focus tokens, title-large type, `--s4-color-success`.
**Motion:** State.

<a id="upload"></a>

## File Upload

A drop zone that is also a real button, then one row per file. It works with a tap, a click, the keyboard or a drag;
dragging is an extra, never the only way. **Orion never uploads anything itself:** it checks each file (type, size,
count), shows it and fires events; the app sends it and reports back with a small API.

```html
<div class="s4-upload" data-max-size="10 MB" data-max-files="5">
  <span class="s4-upload-label">Receipts</span>
  <input type="file" name="receipts" accept=".pdf,image/*" multiple>
  <div class="s4-text-field-supporting">They are attached to this expense report.</div>
</div>
<script>
  field.addEventListener('s4-upload', (e) => {               // start sending e.detail.file
    send(e.detail.file, (p) => S4.upload.progress(field, e.detail.id, p))
      .then(() => S4.upload.done(field, e.detail.id), () => S4.upload.fail(field, e.detail.id, 'Couldn’t upload. Try again.'));
  });
  field.addEventListener('s4-retry', (e) => { /* send e.detail.file again */ });
</script>
```

| Attribute | What |
|---|---|
| `accept`, `multiple`, `required`, `disabled`, `name` on the input | As usual. The chosen files are put back into the input, so a plain form post and `required` work. |
| `data-max-size` (“10 MB”) | Bigger files are refused with the reason (“Too large: 14.2 MB. The limit is 10 MB.”). |
| `data-max-files` | More files are refused. |
| `data-msg-type`, `data-msg-size` | Your own wording for a refusal. |
| `data-variant="compact"` | One file in a row the size of a field (for forms), with Remove once chosen. |
| `data-variant="avatar"` | A round photo with a camera badge; `data-initials`, `data-photo` (current photo URL); a `[data-upload-remove]` button inside removes it. Put the label and supporting text in a `.s4-upload-avatar-text` beside it. |
| `data-error="…"` on the field | An error (the zone keeps its fill; the label and message turn the error color). |

The hint under the zone's title is written from `accept`, `data-max-size` and `data-max-files` (“PDF or images, up to
10 MB each, 5 at most”). On a touch screen the zone just says “Choose Files”.

**Events** (on the field): `s4-upload { id, file }` per accepted file; `s4-change { files }`; `s4-retry { id, file }`;
a cancelable `s4-remove { id, file }`; `s4-reject { file, reason }`.
**API:** `S4.upload.progress(field, id, 0..1)` (or `null` for “Uploading…”), `S4.upload.done(field, id, text?)`,
`S4.upload.fail(field, id, message)`, `S4.upload.files(field)`, `S4.upload.add(field, files)`, `S4.upload.clear(field)`.

**Rows:** a thumbnail (the picture itself for images, a file icon otherwise), the name (it wraps, never cut), its size
and state, a progress bar while sending, Try Again after a failure, Remove. Refused files stay as a row with the reason
until removed, so people see what happened. Rows open and close in place (Reveal).

**When to use:** attachments, documents for a form, a profile photo. **Not:** pasting text, picking from files the app
already has (a list or a gallery), or a big media library (a page of its own).

**Do** say the types and the limit before people choose; let the form go on while files send. **Don't** make the zone
the only way in on a phone (it isn't: it is a button), hide refused files, or upload before the person chose.

**Accessibility:** the zone is a `<button>` described by the label and the supporting text; the file input is hidden
(the button opens it). Additions, refusals, finished uploads and failures are announced politely; each row's buttons
are named with the file (“Remove march.pdf”, “Try Again: taxi.pdf”); the progress bar is a `progressbar`.

**Tokens:** `--md-sys-shape-corner-extra-large` (the zone, rounder with the corner dial), `--md-sys-shape-corner-large`
and `-small` (rows and thumbnails, concentric), `--md-sys-color-secondary-container`, `--s4-color-success`,
`--md-sys-color-error`. **Motion:** State (the zone), Reveal (rows), the progress bar's Ink.

<a id="time-field"></a>

## Time Field

Type a time any way you like (“9”, “930”, “9:30 pm”, “21.30”) or pick one from a short list in the glass menu. Times
are shown in the page's language (“9:30 AM” or “09:30”) and stored as `HH:MM`. Pairs with the
[date picker](#date-picker) for a date and time, and with itself for a range. **No clock dial:** typing and a short
list are quicker with a finger, a mouse or a keyboard.

```html
<div class="s4-text-field s4-time-field" data-step="30" data-min="08:00" data-max="18:00">
  <label for="slot">Delivery Slot</label>
  <input id="slot" value="09:30">
  <input type="hidden" name="slot">                          <!-- gets "HH:MM" -->
  <div class="s4-text-field-supporting">Between 8 AM and 6 PM.</div>
</div>

<!-- date and time -->
<div class="s4-date-time">
  <div class="s4-text-field"><label for="d">Meeting Date</label><input id="d" type="date"></div>
  <div class="s4-text-field s4-time-field"><label for="t">Time</label><input id="t"></div>
</div>

<!-- a range: the end names its start -->
<div class="s4-time-range">
  <div class="s4-text-field s4-time-field" id="from-field"><label for="from">From</label><input id="from"></div>
  <div class="s4-text-field s4-time-field" data-range-start="from-field"><label for="until">Until</label><input id="until"></div>
</div>
```

| Attribute | What |
|---|---|
| `value` on the input | A starting time, `HH:MM` (or anything the field can read). |
| `data-step` | Minutes between times in the list (default 30, at least 5). Typed times need not be on a step. |
| `data-min`, `data-max` | `HH:MM`. The list keeps inside them; a typed time outside is an error. |
| `data-hour-cycle="12"` / `"24"` | Force 12 or 24 hours; otherwise the page's language decides. |
| `data-range-start="id"` | On an end field: its list starts after the start time, each choice says how long (“1 h 30 min”), and an end at or before the start is an error. |
| `data-msg-time`, `data-msg-range` | Messages (defaults: “Enter a time like 9:30 AM.”, “Choose a time from 8:00 AM to 6:00 PM.”). |
| Script | `S4.timeField.value(field)` (minutes since midnight or null), `S4.timeField.set(field, 'HH:MM')`, `S4.timeField.parse(text)`; `s4-change { value, minutes }` on the field. |

**Typing:** “9” is 9:00, “930” is 9:30, “9:30 pm”, “9p”, “21.30” and “21h30” all work. Typing narrows the list (“93” shows
9:30 AM and 9:30 PM) and a typed time that is not on the list is offered first. On blur or Enter the text is tidied into
the page's format.

**Keyboard:** Down and Up open the list at the current time and move through it, Enter chooses, Escape closes, Tab
leaves. The clock button opens the list for a pointer and is out of the Tab order.

**When to use:** a time of day: reminders, slots, opening hours, a meeting. **Not:** a duration (a number field with a
unit); a date and time far apart in a list of events (show them as text).

**Accessibility:** a `combobox` with a `listbox` of times (the combobox's list), labelled by the field's label; the cursor
stays in the field (`aria-activedescendant`). Errors follow the text field and `.s4-form`.

**Tokens:** the text field's and the combobox list's. **Motion:** Follow (the list).

<a id="rating"></a>

## Rating

Stars in the accent, always with their number beside them: the picture alone is never the only way to read a rating.
A **display** is read-only and shows half steps; an **input** is a group of real radio buttons.

```html
<span class="s4-rating" data-value="4.5" data-count="128"></span>

<fieldset class="s4-rating" data-input data-name="service" data-value="4" data-labels="Poor,Fair,Good,Very Good,Excellent">
  <legend>Rate the Service</legend>
</fieldset>
```

| Attribute | What |
|---|---|
| `data-value` | Display: any number (stars round to halves, the number beside them is the real value). Input: the starting choice (whole). |
| `data-max` | Number of stars (default 5). |
| `data-count` | Display: the number of reviews, shown as “(128)” and spoken. |
| `data-size="l"` | Display: bigger, for a heading. |
| `data-input` on a `<fieldset>` | The input; give it a `<legend>` (shown like a field's label). |
| `data-name` | The radios' name (form value 1 to max). |
| `data-labels` | Words for each value (“Poor,Fair,Good,Very Good,Excellent”), shown beside the stars and spoken. Otherwise “4 of 5”. |
| `data-required`, `data-msg-required` | A rating must be chosen; inside `.s4-form` the message shows under the stars. |
| `disabled` on the fieldset | Locked (a past rating). |
| Script | `S4.rating.set(el, n)`; the input fires `s4-change { value }` (0 when cleared). |

**Input:** hover previews (mouse only), a tap chooses, a tap on the chosen star clears it (unless required). Arrow keys
move through the stars as in any radio group; the stars are 48 wide touch targets, the first lines up with the legend.

**When to use:** reviews and quick feedback. Display: lists of places, products, vendors (beside the name, small).
**Not:** a score that is not a rating (a number, a [stat](#stat), a [progress ring](#ring)); a choice between named
options (radios or a button group); half-star input (people cannot aim at half a star on a phone).

**Do** show the count with an average; use words for the input when the scale means something specific.
**Don't** color stars yellow or by score: a star is the accent, empty stars are the 3:1 control gray.

**Accessibility:** the display is `role="img"` named “Rated 4.5 out of 5, 128 reviews”; the input is a `fieldset` of
radios named “Very Good, 4 stars”, with the focus ring on the star. Not color alone: the number or the words are always
beside the stars.

**Tokens:** `--md-sys-color-primary` (filled), `--s4-color-control` (empty), `--s4-size-icon-large` (input stars),
`--s4-size-touch-target`, `--s4-shape-control` (the focus ring's corner). **Motion:** State (a star filling).

## Date Picker

A date field opens a glass calendar instead of the browser's own picker (decision 0043). The markup stays native, so
forms, `min`, `max` and pages without scripts keep working.

```html
<div class="s4-text-field"><label for="due">Due Date</label><input id="due" type="date" min="2026-01-01" max="2027-12-31"></div>

<!-- a range: one picker fills both inputs -->
<div class="s4-text-field"><label for="from">Statement Period</label><input id="from" type="date" data-range-end="to"></div>
<input id="to" type="date" hidden>
```

| Attribute (on the input) | What |
|---|---|
| `value`, `min`, `max` | As on any date input (`yyyy-mm-dd`). Days outside the limits can't be chosen, by pointer or keyboard. |
| `data-disabled-dates="2026-11-26,2026-12-25"` | Single days that can't be chosen. |
| `data-range-end="id"` | Selects a range: the first choice is the start, the second the end (swapped if earlier); the end goes into the input with that id. |

The header's month button switches to a month and year chooser; Clear empties the field, Today jumps to today.
Under 600 wide the calendar is a centered floating panel.

**Keyboard:** arrows move by day and week, Home and End to the ends of the week, Page Up and Page Down by month
(with Shift by year), Enter or Space chooses, Escape closes and returns to the field.

**Accessibility:** the field is a button that names the label and the chosen date; the calendar is a dialog with a
roving focus in the grid; today and the selected day are announced.

**Tokens:** `--s4-shape-menu`, `--md-sys-color-primary`, `--md-sys-color-secondary-container`, glass tokens.

## Chip

Compact elements for filters, entered values, quick actions and suggestions. M3 assist, filter, input and suggestion
chips in a chip set.

```html
<div class="s4-chip-set" aria-label="Categories">
  <button class="s4-chip" data-type="filter" type="button" aria-pressed="true">Utilities</button>
  <button class="s4-chip" data-type="filter" type="button">Office</button>
</div>
<div class="s4-chip-set" data-select="single" data-scroll aria-label="Status"> … filter chips … </div>
<div class="s4-chip-set" aria-label="Tags">
  <span class="s4-chip" data-type="input">Travel<button class="s4-chip-remove" type="button" aria-label="Remove Travel"></button></span>
  <span class="s4-chip" data-type="input"><span class="s4-chip-avatar">MR</span>Maya Rossi<button class="s4-chip-remove" type="button" aria-label="Remove Maya Rossi"></button></span>
</div>
<button class="s4-chip" type="button"><span class="s4-icon" data-icon="calendar"></span>Add to Calendar</button>
<button class="s4-chip" data-type="suggestion" type="button">Pay in Full</button>
```

| Attribute | Values | Default |
|---|---|---|
| `data-type` | `assist`, `filter`, `input`, `suggestion` | `assist` |
| `aria-pressed` | filter chip state | `false` |
| `data-elevated` | surface-container-low + level 1 shadow instead of the outline | — |
| `disabled` / `aria-disabled="true"` | disabled | — |
| `.s4-chip-set[data-select="single"]` | exactly one filter chip pressed | multi |
| `.s4-chip-set[data-scroll]` | one horizontally scrolling row | wraps |

32dp, corner `--s4-shape-chip`, label-large, 1dp outline-variant outline, 18dp icons. Selected filter chips are
secondary-container / on-secondary-container with no outline, and a check slides in (fast-spatial width animation),
replacing a leading icon if there is one. Assist icons are primary.

**Behaviour** (`chip.js`): filter chips toggle `aria-pressed` and fire `s4-change { pressed }` on the chip. Input chips:
`.s4-chip-remove` gets a close icon; a click (or Delete / Backspace on it) fires a cancelable `s4-remove { chip }`
(call `preventDefault()` to keep the chip), then the chip collapses and is removed and focus moves to its neighbour.

**Chips, button group or tabs?** If it narrows a collection and there can be many, it is chips. If it changes a value or how the same thing is shown, it is a [button group](#button-group). If it swaps what is on the screen, it is [tabs](#tabs) (decision 0059).

**When to use what:** filter chips to narrow a list; input chips for values someone entered (tags, people);
assist chips for a related action ("Add to Calendar"); suggestion chips for likely values or replies.

**Do:** Title Case labels, 1–3 words; give each remove button an `aria-label` naming the chip.
**Don't:** use chips as primary actions (use buttons) or for navigation (use tabs).

**Accessibility:** filter, assist and suggestion chips are `<button>`s (`aria-pressed` for filters); the remove control is
its own button; 48dp touch targets; forced-colors mode draws borders.

**Tokens:** `--s4-size-chip`, `--s4-shape-chip`, `--md-sys-color-secondary-container`, `outline-variant`,
`surface-container-low`, `--md-sys-elevation-level1/2`, `--md-sys-typescale-label-large-*`,
`--md-sys-motion-spring-fast-spatial`, `--md-sys-state-*`.

Picks exactly one option from a short visible list. M3 radio button on a native input.

```html
<fieldset>
```

## Slider

Picks a value from a range. M3 Expressive slider on a native `<input type="range">`.

```html
<label for="budget">Monthly Budget</label>
<div class="s4-slider" data-label data-prefix="$">
  <input type="range" id="budget" min="0" max="2000" step="10" value="1240">
</div>
<div class="s4-slider" data-stops data-label data-suffix="%">
  <input type="range" aria-label="Tip" min="0" max="25" step="5" value="15">
</div>
```

| Attribute (on `.s4-slider`) | Meaning |
|---|---|
| `data-label` | value label above the handle while dragging or keyboard-focused |
| `data-stops` | a stop dot for every step (discrete slider) |
| `data-prefix`, `data-suffix` | format the label and `aria-valuetext` ("$1,240", "15%") |
| `min`, `max`, `step`, `value`, `disabled` on the input | native |

16dp track: active primary, inactive secondary-container, 6dp gaps either side of a 4dp × 44dp primary handle (2dp
while pressed); outer track corners round, inner corners 2dp; a stop indicator at the end of the track (primary on the
inactive track, secondary-container on the active one). The value label is an inverse-surface pill.

**Behaviour** (`slider.js`): adds the handle, label and stops; keeps `--_value` (0–1) and `--_steps` in sync; fires
`s4-change { value }` on `.s4-slider` for every change (native `input` / `change` still fire). The native thumb is sized
to match the drawing, so the handle stays exactly under the pointer.

### Value as a heading (decision 0063)

```html
<div class="s4-slider" data-value="heading" data-suffix="%">
  <label for="hyd">Water</label>
  <input type="range" id="hyd" min="55" max="90" value="78">
</div>
<!-- with an exact-value field for big numbers -->
<div class="s4-slider" data-value="heading">
  <label for="jobs">Jobs a Month</label>
  <input type="text" inputmode="numeric" aria-label="Jobs a Month, Exact">
  <input type="range" id="jobs" min="100000" max="20000000" step="100000" value="2400000">
</div>
```

`data-value="heading"` puts the label and the value on one row above the track (the label at the start, the value in
title-large at the end), for a tool where the number is what people read: a recipe's hydration, a calculator's input.
An `<output>` you write yourself is kept; without one, slider.js adds it and fills it with the formatted value. An
`<input type="number">` (or a text input with `inputmode="numeric"`, which shows the number grouped, "2,400,000",
while it is not being typed in) in the slider becomes a paired exact-value field (filled, medium corners) that stays in step
with the range both ways: use it when the range is too large to land on an exact value by dragging.

**Do:** pair with a visible label and, for money, a text field for exact entry; use `data-stops` when only a few values
are valid.
**Don't:** use a slider for precise values or very large ranges.

**Accessibility:** the native range input is on top (invisible), so drag, click, arrow keys / Page Up / Home / End and
screen readers are native; focus ring on the handle; 48dp tall target.

**Tokens:** `--md-sys-color-primary`, `secondary-container`, `inverse-surface`, `inverse-on-surface`, `--s4-space-*`,
`--md-sys-typescale-label-large-*`, `--md-sys-motion-spring-fast-spatial`.

## Swatches

S4's seed-color picker, like Android's Wallpaper & style: each swatch previews the palette a seed makes, and picking one
themes the app.

```html
<div class="s4-swatches" data-theme-seed aria-label="Theme Color">
  <button class="s4-swatch" type="button" data-seed="#000000" aria-label="Mono"></button>
  <button class="s4-swatch" type="button" data-seed="#4f46e5" aria-label="Indigo"></button>
  <button class="s4-swatch" type="button" data-seed="#00796b" aria-label="Teal"></button>
</div>
```

| Attribute | Meaning |
|---|---|
| `data-seed` on `.s4-swatch` | the seed color; `#000000` (or empty) is Mono, S4's default monochrome theme (seed `null`) |
| `aria-label` | the color name, Title Case |
| `aria-pressed` | the current one (managed by swatches.js) |
| `data-theme-seed` on `.s4-swatches` | a click calls `S4.theme({ seed, variant })`; the group follows `S4.theme()` through the `s4-theme` event |
| `data-variant` on `.s4-swatches` | the scheme variant a picked seed gets (`vibrant`, `fidelity`, `tonal`, `auto`). Without it the page's own variant is kept: an app that set `fidelity` (a brown or caramel brand) keeps it for every swatch, and `auto` (the default) picks per seed (decision 0060) |
| `data-size="s"` on `.s4-swatches` | 40dp swatches for a picker inside a pane or a card (six fit a phone's row in a pane) |
| `data-show-name` on `.s4-swatches` | writes the pressed swatch's name (its `aria-label`) after the swatches; `data-show-name="id"` writes it into that element instead (an `<output>` in the group's label). Decision 0063 |
| `--s4-swatch-color` | public knob; set from `data-seed` |

**The other theme controls** live in the same script (`theme-controls`), on a connected single-select button group:
`data-theme-mode` (values `system`, `light`, `dark`), `data-theme-contrast` (`0`, `0.5`, `1`) and
`data-brand-dial="surfaces|gray|page|corners|display|text|energy|displayWeight"` (values as `S4.theme` takes them: `tinted` / `neutral`,
`serif` / `inter`, `firm` / `soft` / `round`…). Each calls `S4.theme` when picked and follows `S4.theme()` when the theme
changes elsewhere (restored, reset, Undo), so an app's own Appearance section needs no script (`templates/settings.html`).

48dp circles: a primary half over secondary and tertiary quarters, derived from the seed with CSS relative color syntax
(browsers without it show the plain seed). The selected swatch shrinks inside an on-surface ring with a gap (fast-spatial)
and shows a check badge.

**Behaviour** (`swatches.js`): single choice, `s4-change { seed, swatch }` on the group, one tab stop with arrow keys,
Home and End (roving tabindex).

**Do:** include Mono; name every color; keep 4–10 swatches.
**Don't:** use swatches for arbitrary color input; this picks a theme seed or a category color.

**Accessibility:** native buttons with `aria-pressed` and names; selection shown by ring and check, not color alone;
focus ring; forced-colors mode draws borders and a Highlight outline on the selected swatch.

**Tokens:** `--s4-size-touch-target`, `--md-sys-color-on-surface`, `surface-container-highest`,
`--md-sys-motion-spring-fast-spatial`, `--md-sys-state-*`.

A swatch and its hex code in one Quiet Box. The swatch opens a small glass panel with the named accents (the
[swatches](#swatches)) and a hue slider; the code can be typed. Made for “pick your accent” settings: with
`data-theme-seed` it themes the page as people choose.

```html
<div class="s4-text-field s4-color-field" data-theme-seed>
  <label for="accent">Accent Color</label>
  <input id="accent" name="accent" value="#4f46e5">
  <div class="s4-text-field-supporting">Used for buttons, selection and focus.</div>
</div>

<!-- your own accents -->
<div class="s4-text-field s4-color-field">
  <label for="c">Project Color</label><input id="c" value="#00796b">
  <template>
    <button class="s4-swatch" type="button" data-seed="#00796b" aria-label="Teal"></button>
    <button class="s4-swatch" type="button" data-seed="#c2185b" aria-label="Rose"></button>
  </template>
</div>
```

| Attribute / API | What |
|---|---|
| `value` on the input | A hex code (`#4f46e5`, `4F46E5`, `#46e`). Shown upper-case. |
| `data-theme-seed` | Choosing a color calls `S4.theme({ seed })` (Mono is `seed: null`), and the field follows the theme when it changes elsewhere. |
| `<template>` of `.s4-swatch` | The accents in the panel (named with `aria-label`); otherwise Mono, Indigo, Blue, Teal, Green, Amber, Rose, Purple. |
| `data-msg` on the input | The message for a code that is not a color (default “Enter a color like #4F46E5.”). |
| Script | `S4.colorField.value(field)`, `S4.colorField.set(field, '#hex')`; `s4-change { value }` on the field, `input` and `change` on the input. |

**The panel** is anchored glass that follows the swatch (Follow): focus goes to the chosen accent (arrow keys move
between accents, as in any swatch group), Tab reaches the hue slider, Escape or a tap outside closes it and gives
focus back to the swatch. The hue slider keeps the color's saturation and lightness and turns its hue (a gray starts
from a middle tone).

**When to use:** an app's accent, a label or project color. **Not:** choosing from a few fixed colors only (the swatches
alone); a full color editor with alpha and spaces (out of scope); the theme of the whole system in Orion's showcase
(the brand dials).

**Do** name every accent; keep 4 to 8 of them. **Don't** use the field for status (status colors are fixed tokens) or let
people pick text colors that fail contrast: with `data-theme-seed`, `S4.theme` keeps every role readable.

**Accessibility:** the swatch is a button named with the field and the color (“Choose Accent Color: Indigo”), with
`aria-haspopup="dialog"` and `aria-expanded`; the panel is a labelled dialog; the slider says its degrees. The code is
the text equivalent of the color. Errors follow the text field and `.s4-form`.

**Tokens:** `--s4-shape-control` (the swatch), `--s4-shape-menu` (the panel), glass tokens, `--s4-size-touch-target`.
**Motion:** Follow (the panel), State.

## Password Field

Helpers for a [text field](#text-field) that holds a password: a **Show Password** button, a **strength meter** that
says in words how strong the password is, and a **Caps Lock** notice. The form's own rules (`minlength`, `pattern`,
`required`) decide what is accepted; the meter only helps.

```html
<div class="s4-text-field s4-password" data-strength>
  <label for="pw">New Password</label>
  <input id="pw" type="password" autocomplete="new-password" minlength="12" required>
  <div class="s4-text-field-supporting">At least 12 characters. A few words work well.</div>
</div>
```

| Part | What |
|---|---|
| `.s4-password` on the field | Adds the Show Password button at the end of the box (no other trailing icon there). |
| `data-strength` | Four segments and a sentence under the supporting text: “Strength: Weak, add numbers or symbols”. Read out politely after a pause. |
| Caps Lock | “Caps Lock is on” under the field while it is on and you type there (on keyboards that report it). |
| Script | `S4.password.score(text)` → 0 (too short) to 4 (strong). |

**Show Password** is a toggle: `aria-pressed="true"` while the text shows, and its name (“Show Password”) never changes,
as the pattern asks; the icon changes from an eye to a closed eye. It never moves the cursor (and does not take it away
from the field while you type). The password is hidden again before the form is sent, so the browser offers to save it.

**The score** counts length (8, 12, 16), kinds of characters, and drops common and repeated passwords to Weak. The
segments' colors (error, warning, success) only repeat the words.

**When to use:** sign up, change password, sign in (the toggle only, no meter). **Not:** a PIN or a code (the
[one-time code](#code-field)); a field that is not secret.

**Do** say the rule in the supporting text; use `autocomplete="new-password"` or `"current-password"`. **Don't** block
paste, show the meter on sign in, or make the meter the rule.

**Accessibility:** the toggle is a named button with `aria-pressed` and `aria-controls`; the strength sentence is a
polite live region; the Caps Lock notice is a status. Errors follow the text field and `.s4-form`.

**Tokens:** `--md-sys-color-error`, `--s4-color-warning`, `--s4-color-success`, `--md-sys-shape-corner-full` (segments).
**Motion:** State.

## Inline Edit

A value you change where it is: a name, a title, an amount on a detail page. It reads as plain text and is a real input
underneath, so the person's own tap puts the cursor in it (no script ever does, decision 0049). Pointing at it shows the
field's fill and a pencil; on a touch screen the pencil always shows. Enter or leaving saves, Escape puts it back, and a
snackbar offers **Undo**. No Edit button, no dialog, no Save button (the placement ladder, decision 0047).

```html
<div class="s4-inline-edit"><label for="owner">Owner</label><input id="owner" value="Ana Ribeiro" required></div>

<!-- a heading that can be renamed: it keeps the heading's type -->
<div class="s4-inline-edit s4-headline-small"><input aria-label="Project Name" value="Kitchen Renovation" required></div>
```

| Attribute / API | What |
|---|---|
| `<label>` or `aria-label` | Its name (the label is shown small above, like a field's). |
| `required`, `pattern`, `maxlength` on the input | An empty or rejected value is not saved: the saved one comes back with a short message (`data-msg` for your own words). |
| `data-undo-text` | The snackbar's words (default “Owner changed”). `data-no-undo` for no snackbar. |
| Events | `s4-change { value, previous }` on save and again on Undo. |
| Script | `S4.inlineEdit.set(el, value)` (no events). |

**When to use:** one value on a detail page or a list row that people change now and then. **Not:** a form with several
related values (a [form](#form) with autosave); anything that needs a choice from a list (a select or a
[combobox](#combobox)); long text (a page or an expand with a textarea).

**Do** keep it to short values; give each a label. **Don't** put two inline edits on one line, or ask “Are you sure?”
(Undo is enough).

**Focus:** the text field's marks: a quiet hairline after a tap, the focus ring from the keyboard.
**Accessibility:** a real `<input>` with its label; the message is tied with `aria-describedby` and announced.
**Tokens:** `--s4-shape-text-field`, `--md-sys-color-surface-container-high` (hover), the focus tokens. **Motion:** State.

<a id="badge"></a>

## Badge

Shows that something is new, or how many items need attention (M3). Error and on-error.

```html
<span class="s4-badge"></span>          <!-- small: 6dp dot -->
<span class="s4-badge">3</span>         <!-- large: 16dp, label-small -->
<span class="s4-badge">999+</span>

<!-- on an icon: the host wraps the 24dp icon -->
<button class="s4-icon-button" type="button" aria-label="Notifications, 3 new">
  <span class="s4-badge-host"><span class="s4-icon" data-icon="notifications"></span><span class="s4-badge" aria-hidden="true">3</span></span>
</button>
```

| Part | Values | Default |
|---|---|---|
| `.s4-badge` (empty) | small: 6dp dot | — |
| `.s4-badge` with text | large: 16 high, at least 16 wide, 4 side padding, label-small, tabular figures | — |
| `.s4-badge-host` | wraps an icon; the small dot sits in the icon's top-end corner, a large badge starts 12dp in from the icon's end with its bottom 14dp below the icon's top (M3 / Compose `BadgedBox` offsets) | — |

Outside a host the badge sits inline, e.g. after a label in a list item or tab.

**When to use what:** the **small** dot when the count doesn't matter ("something new"); the **large** badge for a count.
Cap counts at "999+" (write the capped text yourself).

**Do**
- Wrap the icon itself, not a 40dp icon button, so the offsets land on the icon.
- Put the count in the control's accessible name ("Bills, 6 due") and hide the badge itself with `aria-hidden`.

**Don't**
- Don't use a badge for status ("Paid", "Overdue"); use a [status](#status) pill.
- Don't badge every item; reserve it for what needs attention now.

**Accessibility:** the badge doesn't take pointer events, so it never steals a click. A small dot has no text, so the
control's name has to say what's new. Forced-colors mode draws a border.

**Tokens:** `--md-sys-color-error`, `--md-sys-color-on-error`, `--md-sys-typescale-label-small-*`, `--s4-space-1`,
`--s4-space-3`, `--s4-space-4`, `--md-sys-shape-corner-full`.

<a id="status"></a>

## Status

S4 addition. A small pill that names the state of a thing: a bill, a payment, a sync. The label always says the status
in words; the tone and the optional dot only reinforce it, so status never relies on color alone.

```html
<span class="s4-status">Paid</span>
<span class="s4-status" data-tone="tertiary">Due</span>
<span class="s4-status" data-tone="error" data-dot>Overdue</span>
<span class="s4-status"><span class="s4-icon" data-icon="check"></span>Paid</span>
```

| Attribute | Values | Default |
|---|---|---|
| `data-tone` | `primary`, `secondary`, `tertiary`, `error`: the matching container / on-container roles | neutral: surface-container-high / on-surface-variant |
| `data-dot` | a 6dp leading dot in the text color | — |
| leading `.s4-icon` | a 16dp icon instead of the dot | — |

24 high, 8 side padding, small corners (8), label-medium, tabular figures, no wrapping.

**When to use what:** pick tones by meaning and keep them consistent across an app. For bills: Paid is neutral,
Scheduled is primary, In Review is secondary, Due is tertiary, Overdue and Failed are error. Use one error tone per
meaning; don't escalate with more colors.

**Do**
- Use one or two words in Title Case ("Due", "Payment Failed"); add a date when it helps ("Due Nov 2").
- Put the pill next to the thing it describes (in the row, after the amount).

**Don't**
- Don't make a status clickable; to filter by status, use a filter chip.
- Don't use the error tone for anything that isn't a problem.
- Don't use a badge for status; badges count things.

**Accessibility:** the text is the status, so screen readers read it as is, and it works in grayscale and forced colors
(which draws a border). Container / on-container pairs pass AA in every scheme.

**Tokens:** `--md-sys-color-surface-container-high`, `--md-sys-color-on-surface-variant`,
`--md-sys-color-{primary,secondary,tertiary,error}-container`, `--md-sys-color-on-{primary,secondary,tertiary,error}-container`,
`--md-sys-typescale-label-medium-*`, `--md-sys-shape-corner-small`, `--s4-space-1`, `--s4-space-2`, `--s4-space-6`.

<a id="progress"></a>

## Progress

Shows that something is happening (M3 Expressive): linear or circular, determinate or indeterminate. M3E details: a 4dp
gap between the indicator and the track, rounded ends, and a stop dot at the end of a linear track.

```html
<div class="s4-progress" data-value="0.62" aria-label="Q4 Budget Used"></div>              <!-- linear, determinate -->
<div class="s4-progress" aria-label="Syncing With Your Bank"></div>                       <!-- linear, indeterminate -->
<div class="s4-progress" data-type="circular" data-value="0.4" aria-label="Scanning"></div>
<div class="s4-progress" data-type="circular" aria-label="Loading Bills"></div>
```

| Attribute | Values | Default |
|---|---|---|
| `data-type` | `linear`, `circular` | `linear` |
| `data-value` | 0 to 1 (clamped); leave out for indeterminate. Change it at any time; the indicator moves with a spring | indeterminate |
| `aria-label` | what is in progress (required) | — |

progress.js sets `role="progressbar"`, `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow` (removed when
indeterminate) and the internal `--_value`, and draws the circular indicator's SVG.

**Linear:** full width, 4dp high; primary indicator, secondary-container track, 4dp stop dot in primary at the track's end
(it disappears at 100%). **Circular:** 40dp, 4dp stroke with round caps; the track shows only while determinate.

**Public knobs.** The indeterminate loops are long, linear cycles that no spring token describes, so they are
component-level custom properties:

| Property | What | Default |
|---|---|---|
| `--s4-progress-cycle` | linear indeterminate cycle (0042: one drop-like line, front edge leads) | `1500ms` |
| `--s4-progress-circular-cycle` | circular arc breathing cycle (0042) | `1300ms` |
| `--s4-progress-circular-spin` | circular rotation (out of step with the arc) | `1600ms` |

**Reduced motion.** This component carries the one allowed `@media (prefers-reduced-motion: reduce)` query: tokens can't
stop an infinite loop, so the indeterminate animations stop and show a still, partial indicator (40% of the linear bar,
a quarter arc). `:root[data-motion="reduced"]` (S4.motion's app switch) does the same. Determinate changes use the
calm spatial spring, which the tokens already zero under reduced motion.

**When to use what:** **linear** at the top of a surface or under the thing it describes (an upload, a budget); **circular**
in a small space (a button, a card corner, a full-screen load). Use **determinate** whenever you know the fraction.

**Do**
- Label it with what is happening ("Uploading Receipts"), and show the figure next to it when it means something
  ("$6,820.00 of $11,000.00").
- Remove the indicator when the work is done; don't leave a full bar on screen.

**Don't**
- Don't show a progress indicator for actions under about a second.
- Don't stack several indeterminate indicators on one screen.

**Accessibility:** a real `progressbar` with a name and value. Forced-colors mode draws the linear track with a border and
the indicator in CanvasText.

**Tokens:** `--md-sys-color-primary`, `--md-sys-color-secondary-container`, `--s4-space-1` (thickness and gap),
`--s4-space-10` (circular size), `--md-sys-shape-corner-full`, `--s4-motion-spring-spatial-calm` (value changes),
`--md-sys-motion-spring-slow-effects` (indeterminate easing per segment).

<a id="banner"></a>

## Banner

A message that stays on the page until it is handled or dismissed. Not a toast; that is the snackbar.

```html
<div class="s4-banner" role="status" data-tone="error">
  <span class="s4-icon" data-icon="warning"></span>
  <p class="s4-banner-text">One payment failed.</p>
  <div class="s4-banner-actions"><button class="s4-button" data-variant="text" type="button">Update Card</button></div>
  <button class="s4-icon-button" type="button" data-dismiss aria-label="Dismiss"><span class="s4-icon" data-icon="close"></span></button>
</div>
```

| Attribute | Values | Default |
|---|---|---|
| `data-tone` | `primary`, `secondary`, `tertiary`, `error` | neutral |
| `data-dismiss` | on a button inside: fades the banner out and fires `s4-close` | — |

**When to use what:** Use a banner for something that affects the whole page or account and stays true until acted on. Use a snackbar for the result of an action.

**Do**
- Say what happened and what to do, with one text button for the fix.

**Don't**
- Don't stack more than one banner.
- Don't use `role="alert"` unless it is an error that needs attention now.

**Accessibility:** `role="status"` is announced politely; `role="alert"` interrupts. The dismiss button needs an `aria-label`.

**Tokens:** surface-container roles, `on-surface`, `on-surface-variant`, shape `full` and `large`, spacing `--s4-space-*`, spring tokens. No outlines (decision 0023).

<a id="skeleton"></a>

## Skeleton

A quiet placeholder while content loads. Same shape and size as what will replace it. A soft sheen sweeps across the loading region as one wave (decision 0042).

```html
<div aria-busy="true">
  <div class="s4-skeleton" data-shape="text" style="width: 70%"></div>
  <div class="s4-skeleton" style="height: 7rem"></div>
</div>
```

| Attribute | Values | Default |
|---|---|---|
| `data-shape` | `text`, `pill`, `circle` | block with medium corners |

**When to use what:** Use a skeleton when the layout is known and the content takes more than about a second. Use progress when you can show how far along it is.

**Do**
- Set `aria-busy="true"` on the region and remove it when the content arrives.

**Don't**
- Don't show skeletons for less than a second; it flickers.
- Don't animate anything but opacity.

**Accessibility:** The wave stops under `prefers-reduced-motion`. Skeletons carry no text; the busy region tells screen readers loading is happening.

**Tokens:** surface-container roles, `on-surface`, `on-surface-variant`, shape `full` and `large`, spacing `--s4-space-*`, spring tokens. No outlines (decision 0023).

<a id="reward"></a>

## Small rewards

The small moments that make finishing something feel good. Each is an existing motion pattern, so fun never breaks
consistency.

```html
<span class="s4-done-mark"></span>                       <!-- set data-done (or S4.reward.done(el)) and the check draws itself -->
<span class="s4-num" data-count-to="6240" data-count-format="currency:USD"></span>   <!-- counts to its value when it comes into view -->
```

| Thing | How | Pattern |
|---|---|---|
| A check that draws itself | `.s4-done-mark` (`data-size="s|l"`), `data-done` | Ink (the disc), Ink calm (the stroke) |
| A number that counts | `data-count-to`, `data-count-format="number|currency:USD|percent|compact"`, `data-count-decimals`; `S4.reward.count(el, to, { from })` | a count of under a second |
| A row that settles after a drag | reorderable lists ([direct](#direct)) | Morph calm |

**When to use what:** once, at the moment something is finished or a figure changes because of what the person did.
A check for done; a count for a total that moved.

**Do** keep it under a second and let the result be readable the whole time.
**Don't** celebrate routine things (every save, every click), loop a reward, or add confetti: Orion's fun is small.

**Accessibility:** the number's real value is its `aria-label` from the start; the mark is decorative unless you give
it an `aria-label`. Under reduced motion both show their end state at once.
**Tokens:** `--s4-color-success-container`, `--s4-color-on-success-container`, `--s4-space-*`.

<a id="snackbar"></a>

## Snackbar

A short message after an action, often with Undo. **Slides up from the bottom edge**, above a nav bar, docked toolbar or FAB.
Glass (decision 0042): a notification is a raised object. Text and the action are `on-surface` (the action in the
emphasized weight), which the glass guarantee keeps at AA. Rises 14px into place on the `rise` spring.

```js
S4.snackbar({ text: 'Bill archived', action: 'Undo', onAction: restore });
S4.snackbar('Staples marked as paid');
S4.snackbar({ text: 'Couldn’t sync 3 bills. Check your connection.', action: 'Retry', multiline: true, closable: true });
```

| Option | Default |
|---|---|
| `text` | required; sentence case, past tense for confirmations ("Bill archived") |
| `action`, `onAction` | one short action, usually Undo or Retry |
| `closable` | adds a close icon button |
| `multiline` | text on its own line, action below |
| `duration` | 4000ms, or 6000ms with an action; `0` keeps it until dismissed |

Returns `{ element, dismiss() }`. One at a time: a new snackbar replaces the current one. It pauses while hovered or focused,
and is announced politely to screen readers.

**Do:** confirm actions that already happened, offer Undo instead of a confirm dialog. **Don't:** use it for errors that need
a decision (use a dialog) or for messages that must stay (use a banner or inline text).

<a id="tooltip"></a>

## Tooltips

**Plain** tooltips name an icon-only control: `data-tooltip="Copy invoice number"`. They appear after a 500ms hover, on
keyboard focus, or on a long press; Escape hides them; they can be hovered (WCAG 1.4.13). Glass (decision 0042), rising 4px into place fast; they appear 350ms after the pointer arrives.

**Rich** tooltips explain something in a few lines and may hold an action; they sit on glass:

```html
<button class="s4-button" data-variant="text" data-rich-tooltip="autopay-tip">What Is Autopay?</button>
<div class="s4-rich-tooltip" id="autopay-tip" role="dialog" aria-label="About Autopay">
  <span class="s4-rich-tooltip-subhead">Autopay</span>
  <span>Pays the bill from your default card on its due date.</span>
  <div class="s4-rich-tooltip-actions"><button class="s4-button" data-variant="text">Learn More</button></div>
</div>
```

Hover or focus shows a rich tooltip; a click pins it until you click elsewhere.

**Do:** keep plain tooltips to a few words that name the action. The control still needs its own `aria-label`; the tooltip
is linked with `aria-describedby` (added to any existing ids, never replacing them). **Don't:** put essential information
only in a tooltip, or put interactive content in a plain one.

<a id="menu"></a>

## Menu

A short list of choices opened from a button. **Drops** 8px out of the side of its button and fades in, on glass from the first frame (decision 0022), positioned by `orion.js` (flips above when there's no room below).

```html
<button class="s4-button" data-variant="tonal" data-menu="sort-menu">Sort By</button>
<div class="s4-menu" id="sort-menu" aria-label="Sort by">
  <div class="s4-menu-label">Sort By</div>
  <button class="s4-menu-item" role="menuitemradio" aria-checked="true"><span class="s4-icon" data-icon="calendar"></span>Due Date</button>
  <button class="s4-menu-item" role="menuitemradio" aria-checked="false"><span class="s4-icon" data-icon="wallet"></span>Amount</button>
  <hr class="s4-menu-divider">
  <button class="s4-menu-item" data-color="error"><span class="s4-icon" data-icon="delete"></span>Delete</button>
</div>
```

| Part / attribute | Use |
|---|---|
| `[data-menu="id"]` on the opener | Opens the menu; gets `aria-haspopup`, `aria-expanded`, `aria-controls` |
| `.s4-menu[data-align="end"]` | Align the menu's end edge with the opener (for overflow menus at the right) |
| `.s4-menu[data-color="vibrant"]` | Tertiary-container menu |
| `.s4-menu-item` + `.s4-menu-item-text`, `.s4-menu-item-supporting`, `.s4-menu-item-trailing` | Item, with optional second line and a shortcut or value at the end |
| `role="menuitemradio|menuitemcheckbox"` + `aria-checked` | Choice items; checked items use secondary-container |
| `.s4-menu-label`, `.s4-menu-divider` | Group label, separator |
| `data-submenu="menu-id"` on an item | Opens that menu beside it (click, Enter, Space, the arrow toward it, or resting the pointer on it); the arrow back or Escape closes only the submenu, choosing in it closes them all. Add a trailing `<span class="s4-icon s4-menu-item-sub" data-icon="chevron-right"></span>` |
| Built from commands | `S4.commands.menu('id', [...])` writes a whole menu (icons, check and radio items, shortcuts, submenus) from the app's [commands](#commands) |
| Events | `s4-select { value, item }` on the menu when an item is chosen; `s4-open`, `s4-close` |
| JS | `S4.menu.open(menu, anchor)`, `S4.menu.close(menu)`, `S4.position(popup, anchor, { align, gap })` |

**Do:** keep menus short (2–7 items), Title Case items, icons for every item or none. **Don't:** put forms or long text in a
menu (use a dialog or sheet); don't color items except a destructive one.

**Accessibility:** native popover (top layer, light dismiss); arrows, Home/End, type-to-jump, Escape returns focus to the
opener; Tab closes (a submenu and its parents together). Submenu items say `aria-haspopup="menu"` and `aria-expanded`.
48dp item targets (32 in compact density). Keep submenus one level deep.

<a id="dialog"></a>

## Dialog

> **A dialog is the last rung of the placement ladder (decision 0047).** Use it only when the app cannot go on without an answer: something serious that cannot be undone, or leaving with unsaved work. A reply, a comment, an add form, a rename or a filter opens in place with [expand](#expand); a reversible action just happens and offers Undo in a snackbar.

Asks for a decision or a short input. It **pops** in: rises 16px and fades in on the spatial spring, and closes with a
quick drop and fade (decision 0022). On glass, over a 32% scrim.

```html
<button class="s4-button" data-color="error" data-dialog="confirm-delete">Delete Bill</button>
<dialog class="s4-dialog" id="confirm-delete" aria-labelledby="cd-h">
  <span class="s4-icon s4-dialog-icon" data-icon="delete"></span>
  <h2 class="s4-dialog-headline" id="cd-h">Delete this bill?</h2>
  <div class="s4-dialog-content">Staples, $72.40. This can’t be undone.</div>
  <div class="s4-dialog-actions">
    <button class="s4-button" data-variant="text" data-close="cancel">Cancel</button>
    <button class="s4-button" data-variant="text" data-color="error" data-close="delete">Delete</button>
  </div>
</dialog>
```

| Attribute / API | Use |
|---|---|
| `[data-dialog="id"]` | Opens the dialog (focus returns to this element when it closes) |
| `[data-close="value"]` | Closes it; the value comes back in `s4-close { value }` |
| `data-fullscreen="compact"` | Full screen on phones. Needs **both** markups: the normal headline + actions (wide screens) and a `.s4-dialog-bar` (phones) holding a close icon button (`data-close="cancel"`), a `.s4-dialog-headline` and a confirm text button; the other set is hidden at each size |
| `data-persistent` | A click on the scrim doesn't close it (Escape still does) |
| `data-origin="none"` | Fade in place instead of growing from the opener |
| JS | `S4.dialog.open(id, { from })`, `S4.dialog.close(id, value)`; events `s4-open`, `s4-close` |

**Focus:** the dialog itself takes focus when it opens, never a text field (decisions 0043 and 0049; there is no opt-in for fields). `data-autofocus` on a button picks that button. Tab then goes to the first control; focus returns to the opener on close.
by accident. Focus returns to the opener.

**Do:** questions as headlines in sentence case ("Delete this bill?"); actions say what they do ("Delete", not "OK"); confirm
only what can't be undone (use Undo in a snackbar otherwise). **Don't:** stack dialogs; put a dialog on a sheet.

<a id="sheet"></a>

## Floating Panels

A short task without leaving the screen (decision 0043; these replace bottom and side sheets and keep their class
names). A panel is a glass surface that floats inside the window: inset from every edge, all four corners round, and it
pops in like a dialog. Nothing slides up the screen and nothing docks to an edge.

```html
<button class="s4-button" data-sheet="add-expense">Add Expense</button>
<dialog class="s4-bottom-sheet" id="add-expense" aria-labelledby="ae-h">
  <h2 class="s4-sheet-title" id="ae-h">Add Expense</h2>
  <div class="s4-sheet-content">…fields…</div>
  <div class="s4-sheet-actions"><button class="s4-button" data-variant="text" data-close="cancel">Cancel</button><button class="s4-button" data-close="save">Save</button></div>
</dialog>
<dialog class="s4-side-sheet" id="filters">
  <div class="s4-sheet-header"><h2 class="s4-sheet-title">Filters</h2><button class="s4-icon-button" data-close aria-label="Close"><span class="s4-icon" data-icon="close"></span></button></div>
  …
</dialog>
```

| Class / attribute | What |
|---|---|
| `.s4-bottom-sheet` | Floats at the bottom center (on a phone: the full width minus the inset, above the home indicator). |
| `.s4-side-sheet` | From 600 wide: floats at the end side, as tall as the window minus the inset. On a phone: same as the bottom panel. |
| `data-placement="center"` | Centers the panel like a dialog. |
| `data-persistent` | A click outside doesn't close it. |
| `data-modeless` | A **tool panel** (decision 0054): from 600 wide it opens with no scrim and the page behind stays live. Closes with Close, Escape (focus inside), or a second tap on its opener. On a phone it is modal as usual. |

Opening, closing, `[data-close]`, focus and events work exactly like the [dialog](#dialog) (`S4.sheet.open/close`
are the same functions). Opening never focuses a text field (decision 0049); `data-autofocus` on a button picks that button.
`.s4-sheet-handle` in older markup draws nothing, and panels are not dragged.

**Modal or tool panel?** A panel that is a short task you finish or cancel (Add Expense) is modal: the default. A
panel that is a tool for the page behind it (filters, an inspector, formatting) is `data-modeless`: its controls act at
once, there is no Apply button, and you keep working in the page while it is open. Dialogs are always modal.

**Do:** use a bottom panel for a quick add or a set of choices; a side panel for filters or details beside content on
wide screens. Always give it a Cancel or Close. **Don't:** put a panel on a dialog, or a second panel on a panel.

**Accessibility:** a native modal `<dialog>`: focus is trapped, Escape closes, focus returns to the opener. Give it
`aria-labelledby`.

**Tokens:** `--s4-shape-sheet`, `--s4-space-4` (inset), `--s4-scrim-opacity`, glass tokens.

<a id="palette"></a>

## Command palette

Search everything and run any action from one box. Opens with **mod+K** (⌘K or Ctrl K) anywhere, or from a button.
The desktop counterpart of the navigation bar; it works on a phone too.

The palette builds itself: there is no markup to write.

```html
<!-- a button that opens it -->
<button class="s4-icon-button" type="button" data-palette aria-label="Search And Commands"><span class="s4-icon" data-icon="search"></span></button>

<!-- any button or link becomes a command -->
<button class="s4-button" type="button" data-command="Archive Message" data-shortcut="mod+e">Archive</button>
```

```js
S4.palette.register([
  { label: 'New Message', group: 'Mail', icon: 'edit', shortcut: 'mod+n', run: function () { S4.sheet.open('compose'); } },
  { label: 'Export As CSV', group: 'Data', icon: 'export', keywords: 'download spreadsheet', run: exportCsv }
]);
```

| Where commands come from | How |
|---|---|
| The app's own | its [commands](#commands) (`S4.commands.add`), the same list that feeds the menu bar, menus and shortcuts; `palette: false` keeps one out, disabled ones are left out. `S4.palette.register([{ label, group, icon, shortcut, keywords, run }])` adds to the same list |
| Buttons and links on the page | `data-command="Label"` (optional `data-command-group`, `data-command-keywords`); running it clicks the element; its `data-shortcut` is shown |
| The navigation | every destination appears as "Go To …" |
| Appearance | "Switch To Dark Mode" / "Light Mode" (turn off with `S4.palette.theme = false`) |

Script: `S4.palette.open()`, `S4.palette.close()`, `S4.palette.commands()`, `S4.palette.clear()`;
`S4.palette.shortcut = false` frees mod+K. `document` gets `s4-command { command }` when one runs.

**When to use what:** give every desktop app a palette: it is how people who know what they want skip the menus.
Put the app's ten or twenty real actions in it, named the way the buttons are. It does not replace visible
navigation or buttons; everything in it must also be reachable on screen.

**Do**
- Name commands as verbs in Title Case: "Archive Message", "Go To Settings".
- Group them (`group`) and add `keywords` for the words people actually type.
- Show the same shortcut in the palette, the menu and the tooltip.

**Don't**
- Don't put a destructive action that cannot be undone in the palette without its confirm.
- Don't open the palette by itself, and don't use mod+K for anything else.

**Accessibility:** a modal dialog with a combobox and a listbox; Arrow keys move, Enter runs, Escape closes, focus
returns to where it was. Opened with the keyboard, the cursor is in the box; opened by tap or click it is not, so no
keyboard jumps up on a phone (decision 0049), and the first key you press goes into the box.

**Motion:** Pop. **Tokens:** the dialog's glass, list and search tokens; `--s4-space-*`.
