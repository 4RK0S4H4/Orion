Design Review

An end-to-end review of Orion as a language for apps, websites and desktop apps, on phones and computers: what holds up, what does not yet, how it compares with the systems people reach for, and what would let each app look like itself. Eight questions at the end need your answer.

Method: every foundation and framework document was read, the tokens and all 61 component stylesheets were measured, and the showcase and nine templates were looked at in Chromium at 390 and 1280, light and dark. One screen was then restyled with tokens alone (font, corners, accent) to see how far an app can move today. Not covered: a real iPhone or Safari, and screen readers.

The Verdict

Orion is unusually well engineered and more opinionated about behaviour than any system it is compared with below. It is ready for apps. It is not yet ready for websites, and an app cannot yet make it its own beyond color.

Foundations and Tokens9/10Tokens only, proven by checks.
Behaviour9/10Placement ladder, pages, states, undo.
Accessibility8/10Built in; right-to-left and print open.
App Components8/1061; rich inputs and big data missing.
Visual Hierarchy6/10Calm, but flat in neutral mode.
Desktop Apps6/10Window layer exists; no menu bar or shell.
Websites4/10One thin landing template.
Per-App Customization4/10Color only; shape and type are fixed.

What Holds Up

Token Discipline Is RealAcross 61 component stylesheets: 2 hex values, 1 literal font size, every transition on a named pattern. Most public systems do not get close to this.
Proof Instead Of PromisesContrast pairs in four modes, glass legibility over 97 schemes, 210 accent schemes, motion patterns and concentric corners are all failed by a machine. No system compared here ships this.
Behaviour Is Part Of The LanguageWhere things open, how you go into a thing and back, loading and empty states, do-then-undo, never moving the cursor. Material and Apple describe these; Orion builds and checks them.
Size Follows The Pointer, Layout Follows The WidthKeeping density and window class separate is the right model for touch laptops and narrow desktop windows. Few web systems make that split.
Any Accent, Two Color ModesOne seed gives a complete, contrast-safe scheme, neutral or tinted. This is the strongest theming feature and it already works.
Glass With A GuaranteeGlass only on what floats, with a contrast floor and three fallbacks. That is more careful than most glass on the web.

Findings

Ordered by how much each one limits "any app, any website, and unique per app".

Major1. An App Can Only Change Its ColorThe test: one screen restyled by tokens alone. The accent followed everywhere. Corners followed halfway (chips and status pills squared off; buttons, the segmented group and the navigation indicator stayed pills), because 54 places compute the pill from the height and 56 use the full corner directly. Three shape tokens are defined and read by nothing (button, icon button, snackbar). The display face followed; nothing documents a type, spacing or gray-temperature dial.Fix: a small, named set of brand dials, each a checked preset (section "Making It Unique Per App").
Major2. Themes Only Work On The Whole PageEvery token block is attached to the root, and the alias tokens resolve there. A dark sidebar in a light app, a branded band on a website, or two themes side by side cannot be done with tokens. Radix Themes, daisyUI and Bootstrap all allow a theme on any element.Fix: let the mode and brand attributes work on any container.
Major3. Websites Are An AfterthoughtThe landing template is a headline, three cards, an accordion and a call to action. There is no site header with a phone menu, footer, pricing, testimonial, logo row, picture or video hero, feature rows with a screenshot, article index, or documentation layout with a sidebar and contents. Display type is a fixed 57px rather than fluid, and there is no section rhythm scale. On 1280 the three feature cards stop at 936 of 1200 and leave a hole.Fix: a website kit: about ten section components, fluid display type, section spacing tokens, four site templates.
Moderate4. Neutral Mode Reads FlatWith no shadows and no outlines, every layer is separated by a few percent of gray: page, card, chip, field and tonal button sit within three steps. On the dashboard the eye lands on the one black bar and nothing else ranks. Headings are weight 400, so "Overview" (22) and "October" (24) carry the same voice as body text.Fix: stronger type hierarchy by default, and an optional page tone (white cards on a soft gray page). Question 5.
Moderate5. Roboto's Letter Spacing On InterThe type scale keeps Material's tracking (+0.5px at 16, +0.2px at 14), which was tuned for Roboto. Inter is already wider, so body text looks loose, most visibly in the article template. Inter's own guidance is slightly negative at text sizes and tighter as size grows.Fix: retune the tracking column for Inter. Question 4 shows both.
Moderate6. Wide Windows Are Left-AnchoredOn the showcase home at 1280, two 236px cards sit beside 500px of nothing and the search field stops at 720. Card grids do not fill their row, and nothing says what a view does between 1200 and 1600 beyond a cap.Fix: card grids that fill, and a rule per page width for what joins at large and extra-large (a third pane, a wider grid).
Moderate7. Input And Data GapsMissing for real apps: combobox with search, tag input, file drop and upload progress, time and date-time, number stepper, one-time code, rating, tree, carousel, rich popover, code block. Tables lack column resize, pinned columns, virtual rows, filters and saved views. Most are already on Horizon 2.Fix: pull rich inputs forward; they block more app types than anything else on the roadmap.
Moderate8. Desktop Apps Stop At The Title BarThe window layer, shortcuts, context menus and compact density are right. Still missing: a menu bar, a status bar, document tabs, a sidebar tree, a settings window, and one real Electron or Tauri shell to prove the drag regions and window controls.
Moderate9. The Documents Have DriftedThe skill and foundations still say things later decisions reversed: "Nine starter apps" (15), "46 components, eight templates" (61, 15), menus that "drop out of their button" and sheets that "slide from the edge" (0042, 0043), buttons that square "full to small", a bottom sheet's square edge, "42 pairs" (78), and "Orion is Material 3 Expressive" next to "not a clone of Material". The skill builds from these, so drift here becomes drift in apps.Fix: one pass over philosophy, foundations and the skill header, then a check that counts match.
Minor10. Small Things SeenA rise in revenue wears the accent, so with an orange or red accent good news looks like a warning beside the red "Spent" pill (fixed in this round: it uses the success tone). The Elevated button has no shadow to be elevated with and looks like the Text button on a card. Avatar stacks cover each other's initials. Breadcrumb chevrons sit unevenly. The "+4" in the stack and the tonal toggle are faint in dark mode.
Minor11. Reach And Delivery38 physical left and right rules remain against 59 logical ones, and there are no print styles (both on Horizon 1). The bundle is 70 KB of CSS and 69 KB of script compressed, plus 79 KB of icons and a 165 KB font: fine for apps, heavy for a landing page, and there is no way to ship less. No typed API and no package, which only matters if anyone else is to use it.

Compared With Other Systems

What each one is best at, and what Orion should take from it. None of them should be copied whole.

Material 3 ExpressiveOrion's foundation: roles from a seed, type and shape scales, springs. Orion is calmer (neutral base, no halos, no shadows) and goes further on behaviour. Material is ahead on adaptive layout guidance for large screens and on shape as a theme you can change.Take: the large-screen pane rules; shape as a theme.
Apple (Human Interface Guidelines, Liquid Glass)The reference for glass on floating chrome and for desktop apps: menu bar, sidebar, inspector, toolbar, settings window. Orion's glass rules are close to Apple's and better proven for contrast. Apple is far ahead on desktop conventions.Take: the desktop app anatomy, as Orion patterns.
Fluent 2 (Microsoft)Best for dense productivity software: three densities, data grids, command bars, tree views, and a brand ramp that leaves neutrals alone, which is Orion's neutral mode. Visually plainer than Orion.Take: data grid, tree and command bar patterns.
Tailwind With shadcn/uiThe current default for new web apps. It is a kit you copy and own: unlimited freedom, no opinions on behaviour, consistency is your job. Its theme is a handful of variables (base gray, accent, radius, font), which is exactly the short list Orion lacks.Take: the size of the theme contract: five or six dials, not five hundred tokens.
Radix ThemesThe cleanest theming model: accent color, gray family, radius, scaling and panel background, set on any element and nestable. Good-looking as shipped and visibly different per app with five settings.Take: gray family, radius and scaling dials; themes on any container.
daisyUIShows how far named themes go: dozens of looks from one component set by changing colors, three radii (controls, fields, boxes), size, border and depth. Shallow on behaviour and accessibility.Take: separate radii for controls, fields and boxes; named presets.
Ant DesignThe widest component set for business software (forms, tables, trees, uploads, transfer lists) and a token algorithm: seed tokens produce everything else, with compact and dark as algorithms. Heavy and recognisably "enterprise".Take: the breadth list for inputs and data; algorithms as presets.
Mantine And ChakraApplication kits with 100+ parts and hooks, themed through one object including default props per component. They need React; Orion's plain CSS and one script is a real advantage for one-file apps.Take: per-app component defaults (this app's buttons are tonal).
Bootstrap 5Still the widest reach for websites: grid, navbar, footer patterns, carousel, and a theme attribute on any element. Dated look, weak on app behaviour.Take: the website section set Orion does not have.
Carbon, Polaris, Primer, AtlassianProduct systems with the best written guidance: content rules, patterns per task, strict contribution contracts. Each is tied to one brand, so they customize poorly.Take: pattern pages per task (filtering, bulk actions, onboarding).

Where Orion Already Leads

Machine-checked guarantees; behaviour rules that are built, not described; the pointer and width split; glass with a contrast floor; no build step; and a skill that applies it the same way each time. Where it trails: theming beyond color, website sections, rich inputs and data at scale, desktop app anatomy, and delivery.

Making It Unique Per App

The risk in opening a system up is that it stops being a language. The way through is to fix what makes Orion recognisable and open a short list of dials, each with presets that pass the same checks as the default.

Stays Fixed (This Is Orion)Filled, never outlined. No shadows. Glass only on what floats, with the contrast floor. Concentric corners. The ten motion patterns. The placement ladder, pages, states and undo. Title Case labels. Text and controls proven for contrast. Things you click are rounder than things you type into.
Opens Up (The Brand Dials)1. Accent and color mode (exists). 2. Gray temperature: pure, warm, cool. 3. Corners: one softness dial moving controls, fields and boxes together, concentric by rule. 4. Type: a display face, a text face, weight of headings, with tracking retuned per face. 5. Density and scale (exists; add roomy for websites). 6. Motion energy: calm, standard, lively, same patterns. 7. Icon set (exists). 8. Defaults per app: which button variant is the main one, list style, page tone.
Signature (The App's Own)Decision 0053 already covers this: the elements only this app has (a ring, a road, a board) are drawn from Orion's rules in the app's own stylesheet. Add a place for brand moments: logo, illustration and picture slots, a hero, an empty-state picture.
How It Would Be UsedOne call or one attribute block per app, saved with the theme: S4.theme({ seed, surfaces, gray, corners, type, energy }). Each dial is a token set on the root or any container. The checks run over every preset, as the accent check does over 210 schemes today.

Suggested Order

1. Tidy What ExistsBring the documents and the skill header back in line with the decisions; retune letter spacing; fix the small things in finding 10; make card grids fill.
2. Brand DialsRoute every corner through three shape tokens (controls, fields, boxes); add gray temperature, type and energy presets; themes on any container; a check over all presets; a "Make It Yours" page in the skill.
3. Website KitSite header and footer, hero with media, feature rows, pricing, testimonials, logo row, article index, documentation layout; fluid display type; section rhythm; a lighter bundle for pages.
4. Rich Inputs And DataCombobox, tag input, upload, time, number, one-time code; table resize, pinning, virtual rows, filters.
5. Desktop AnatomyMenu bar, status bar, document tabs, tree, settings window, one real shell.
ThroughoutThe roadmap's own test stays the judge: build real apps with the skill, one phone-first and one desktop, and fix what it gets wrong.
