Components / Table

Data tables compare rows across columns: bills, payments, invoices. Every figure uses tabular digits and numbers are right-aligned. On compact screens (the table's space under 600) each row becomes a stacked block with column names, so phones never scroll sideways. Tables are solid content surfaces, never glass.

Sortable, Selectable, Clickable

Sort buttons in the headers cycle ascending, descending and the original order. The checkbox column selects rows (the header box selects all, and shows indeterminate for some). Rows with tabindex="0" open on click or Enter. data-sticky keeps the header in view while the rows scroll.

At Scale: 10,000 Rows

A data table: S4.table(el).setRows(rows) draws only the rows on screen, so ten thousand scroll as smoothly as ten, with a scrollbar that never jumps and every row's place announced (aria-rowcount, aria-rowindex). Pinned first column, column grips (drag, or focus a grip and use the arrow keys; double-click or Enter fits), a menu on every column (sort, group, pin, fit, move, hide), a Columns menu, details in place, inline editing with Undo, a row menu, the selection bar and a totals footer that stays at the bottom. Arrow keys move between rows; Right and Left move through a row's cells; Enter on an editable cell edits it.

Pinned and Resizable, From Markup

Plain markup takes the column features too: data-resizable on the table, data-pin on a header (data-pin="end" for the last). Pinned cells stay solid and get a tonal edge only while something scrolls under them. data-layout="scroll" keeps the real table on a phone instead of stacked rows: right for numbers people compare across a row.
