# Color

**Tokens:** `--md-sys-color-*` (49 M3 roles) · source `tokens/src/color.tokens.json` · live: [tokens page](https://4rk0s4h4.github.io/s4-orion/tokens/#color)

## How color works
Every color in S4 Orion is an **M3 color role** generated from one **seed** by Material Color Utilities. Components only
ever use roles (`primary`, `on-surface`, `surface-container-high`…), never hex values, so any seed produces a complete,
accessible scheme and no component changes.

- **The base is neutral** (decisions 0043, 0045): surfaces, text and outlines are pure grays, tuned by hand ("Crisper":
  a white page in light mode, a deep black in dark mode, clear steps between surfaces). They do not change with the accent.
- **The accent is any color.** `S4.theme({ seed: '#0b57d0' })` or a named one (`S4.theme.accents`: mono, blue, indigo,
  violet, pink, red, orange, amber, green, teal). It colors the primary roles (main button, FAB, switches, sliders,
  progress), selection and the focus ring, nothing else. Monochrome is one accent, and the one the stylesheet ships
  with; it is not the language. `npm run check:accent` proves 216 accent schemes against the neutral base.
- **Gray temperature** (decision 0055): `S4.theme({ gray: 'warm' })` or `'cool'` gives the grays a little color at the
  same lightness (white stays white, black stays black; `npm run check:gray` proves contrast is unchanged). Use warm for
  editorial, food, craft and personal apps; cool for technical and data tools; pure when unsure.
- **Page tone** (decision 0055): `S4.theme({ page: 'soft' })` puts white cards on a soft gray page in light mode. Use it
  for dashboards and card-heavy screens that read flat; leave it off for reading and forms.
- **Status is fixed:** `--s4-color-success|warning|info` and the error roles never change with the accent.
- `S4.theme({ surfaces: 'tinted' })` is stock Material (every role from the seed), kept for apps that want it.
- **Default:** monochrome (black and white). It's stored in `color.tokens.json`, generated by
  `npm run generate:color` from the seed in the file's generator block.
- **An app with a color** (decision 0060): `S4.theme({ seed })` with no variant picks one by the seed (`'auto'`): a muted
  or deep seed (HCT chroma under 60, or tone under 35: plum, terracotta, navy, espresso, a forest green, most brand
  colors) gets **fidelity**, which keeps the seed's own color; a vivid one (the named blue, violet, pink, red, orange, a
  magenta, a chartreuse) gets **vibrant**. `vibrant` raises a muted seed's chroma to about 74 and turns it neon (a coral
  terracotta, a mint green, a hot pink plum), so name it only when the user asks for a bright version. **Tonal** is for
  subtle or photo-sampled colors; tinted mode uses it by default. `S4.theme.variantFor(seed)` says what auto will pick.
- **Glass FABs with a seed** (decision 0060): the default FAB's icon and label take on-primary-container, or white or the
  accent's darkest tone when that keeps more of the glass, and its tint rises above the owner's 75% only as far as the
  label needs for 4.5:1 over any backdrop (a fidelity FAB on a mid-tone seed is nearly solid). `npm run check:glass`
  proves it for every scheme. Never work around a FAB's contrast with `data-color` again.
- **Categories** (decision 0060): `--s4-category-1…6` are the chart palette under names for things that are not charts
  (tags, desks, revision colors, kinds of booking, drawn artwork). Fixed in both modes, never text color, always named
  in words beside the mark. Many categories, or a category that matters more than the others, is a hint to use words.
  "Mine against everyone else's" is the accent against `outline` used as a fill, not a container role (tinted dark
  containers are bright tones).
- **Artwork and illustration** (decision 0060): draw real objects (a sleeve, a product, a plant pot) on the M3 *fixed*
  roles (`primary-fixed`, `secondary-fixed`, `on-secondary-fixed`…): they stay the same in light and dark, so a drawing
  does not change ground with the mode. A tinted scope tints them too; keep artwork in a neutral region.
- **Contrast levels:** standard (0), medium (0.5) and high (1). Raising contrast regenerates every role. Never darken a
  single color by hand. High contrast follows the device's "more contrast" setting automatically.

## Roles to reach for

| Need | Role |
|---|---|
| Page background | `surface` |
| Cards, panes, list groups | `surface-container-low` (or `-lowest` / `-high` to separate nested levels) |
| Nav bar, menus | `surface-container` |
| Dialogs, search | `surface-container-high` |
| Filled text fields | `surface-container-highest` |
| Main text / secondary text | `on-surface` / `on-surface-variant` |
| The one primary action | `primary` + `on-primary` |
| Selected state (nav indicator, chips, tonal buttons) | `secondary-container` + `on-secondary-container` |
| Standout container (FAB) | `primary-container` + `on-primary-container` |
| Errors, destructive confirm | `error` + `on-error`, `error-container` + `on-error-container` |
| Dividers / control outlines | `outline-variant` / `outline` |
| Snackbars | `inverse-surface` + `inverse-on-surface`, action in `inverse-primary` |

## Do / don't
- **Do** put text on the role made for it (`on-*`). **Don't** fade text with `opacity` or alpha; use `on-surface-variant`.
- **Do** show status with a label and a tone. **Don't** rely on color alone.
- **Don't** write hex values in components or app CSS. If a color is missing, it's a role you haven't found yet.

## Guarantees
The token build checks 83 pairs (every `on-*` pair, text on every surface, outlines at 3:1) in light, dark,
high-contrast and dark high-contrast, and fails if any drops below WCAG AA.

## Color on a container
Light or dark mode, the gray temperature, the page tone and the accent can be set on any element, not only `<html>`:
`data-theme="light|dark"`, `data-gray="warm|cool|pure"`, `data-page="soft"`, `data-accent="blue|#0b57d0"` (with
`data-accent-variant` and `data-surfaces="tinted"`), or `S4.theme({ mode, seed, gray, … }, element)`. They nest and the
nearest one wins. A scoped element paints its own surface and text, sets `color-scheme`, and its glass is made from its
own surfaces. Contrast, reduced transparency and reduced motion stay page-wide. `npm run check:scopes` proves that a
scoped light or dark element gets exactly the page-wide values of its mode, so the 83 proven pairs hold inside it.
